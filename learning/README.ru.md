# Учебные треки

Темы сгруппированы по доменам, по одному каталогу на тему. Каждая тема это самодостаточный трек, которым управляет навык `teach`: цель, упорядоченный набор уроков и справочные материалы, которые эти уроки заработали.

## Как начать тему

```bash
cp -r templates/learning-workspace learning/<domain>/<topic-slug>
```

Затем запустите навык `teach` и назовите тему. Он прочитает трек, заполнит цель, расспросив вас, и напишет первый урок.

Домен это группировка, а не трек: он содержит каталоги тем и больше ничего. Добавляйте новый, когда его разделила бы вторая тема.

## Структура

```text
learning/
├── <domain>/              # programming, llm, …
│   └── <topic>/           # one track per topic
├── .nav.yml               # sidebar order/titles for the published site
└── README.md              # this index
```

Каждый трек:

```text
learning/<domain>/<topic>/
├── README.md              # mission, success criteria, lesson index
├── GLOSSARY.md            # canonical terms for this topic
├── RESOURCES.md           # trusted sources, known gaps
├── NOTES.md               # preferences and working notes
├── lessons/               # NNNN-slug.md, one tight win each
├── reference/             # cheat sheets, built for lookup
└── learning-records/      # NNNN-slug.md, what was demonstrably learned
```

Уроки нумеруются с `0001` внутри каждого трека. Треки могут ссылаться друг на друга, но ссылка это указатель, а не включение: она не втягивает материал другой темы в эту цель. Лучше ссылаться на термин глоссария или справочную шпаргалку, чем на урок, потому что они написаны для поиска и подходят любому читателю.

Навык `teach` определяет формат каждого файла здесь. Прочитайте [его спецификацию](https://github.com/TokenCemetery/teach/blob/main/.agents/skills/teach/SKILL.md), прежде чем писать такой файл вручную.
