# 学习：分析型数据仓库

能够在 BigQuery、Snowflake 或 Redshift 上设计一张表、一个模型和一条加载路径，以可预测的成本回答提给它们的分析问题，并能从存储布局出发说明，为什么在行存储上正确的建议到了这里就是错的。

**最新课程：** [20. 修改别人在查询的模型](lessons/0020-changing-a-model-others-query.md)

## 成功的标准

- 从存储布局出发，解释为什么一个查询在行存储上便宜、在列式数据仓库上昂贵，或者反过来，并预测对查询的某个改动会怎样影响它扫描的字节数。
- 说出 BigQuery、Snowflake 和 Redshift 各自在存储与计算之间分离了什么，并为给定的工作负载确定计算规模或隔离计算资源。
- 根据表的查询模式，为它选择分区、聚簇或排序键以及数据分布方式，并展示这个选择省下的扫描量。
- 在给定的粒度上设计维度模型，包括变化的维度如何保留历史。
- 设计一条批量或微批的加载路径，可以重跑而不会重复或丢失行。
- 估算一个查询或一个工作负载在按需计费和容量计费下的成本，并在不改变结果的前提下降低成本。
- 为一个工作负载在数据仓库、Postgres 和湖仓之间做出选择，评审别人的数据仓库 schema 和账单，并在不影响别人的前提下修改他们在查询的模型。

## 约束

- 要求具备可用的 SQL 能力，不要求有数据仓库经验。SQL 语言、查询计划和事务型 schema 设计在 [`programming/sql`](../../programming/sql/) 中讲授，这些课程以它们为前提。
- 全程对比 BigQuery、Snowflake 和 Redshift 这三个平台。每节课先讲机制，再说明各平台如何提供它，这样换了供应商，内容依然适用。
- 平台的默认值、限制和价格会随版本变化。课程引用其中某个值时，会注明它出自哪个文档页面，读者应到该页面核对当前值。

## 范围之外

- SQL 语言、查询计划、schema 设计以及行存储上的隔离：见 [`programming/sql`](../../programming/sql/)，本主题建立在它之上，不再重复讲述。
- 运维 Postgres 实例：见 [`data/postgres`](../../data/postgres/)。第 8 阶段把 Postgres 作为分析负载的候选方案来比较，但不讲如何运维它。
- 作为独立主题的流处理平台。第 6 阶段从数据流加载数据；日志本身如何工作见 [`data/kafka`](../../data/kafka/)。
- 作为独立主题的编排和转换框架（Airflow、dbt）。它们出现在加载或建模课程需要它们的地方，但不讲如何配置。
- BI 工具、语义层和仪表盘设计。
- 作为独立主题的 Spark、Trino 及其他引擎。第 8 阶段把它们查询的湖仓与数据仓库放在一起比较，但不讲如何运行它们。

## 学习路线

共八个阶段，从存储布局到判断力。一个阶段包含若干课程，边界并不严格；一个阶段是否完成，取决于能力，而不是课程数量。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. 行存储与列存储 | 0001 至 0002 | OLTP 与 OLAP 的访问模式、行存储与列存储的对比、行组、列块及其统计信息 | 能预测对于给定的查询哪种布局读取的字节更少，并说明原因 |
| 2. 列式执行 | 0003 至 0004 | 字典编码、游程编码和差分编码，压缩，向量化执行，延迟物化 | 能说明列存储为什么这样压缩和执行，以及 `SELECT *` 在那里的代价 |
| 3. 存储与计算 | 0005 至 0006 | BigQuery、Snowflake 和 Redshift 如何分离存储与计算，slot、虚拟仓库、节点类型、并发和工作负载隔离 | 能在三者中的任何一个上为给定的工作负载确定计算规模并隔离计算资源 |
| 4. 物理设计 | 0007 至 0010 | 分区与分区裁剪、聚簇与排序键、区域映射、数据分布与 join 策略、不再适用的行存储建议 | 能根据表的查询模式选择它的物理布局，并展示它省下的扫描量 |
| 5. 维度建模 | 0011 至 0013 | 事实、维度与粒度，星型模型与宽表、嵌套表的对比，缓慢变化维度 | 能在给定的粒度上设计一个保留问题所需历史的模型 |
| 6. 加载 | 0014 至 0015 | ELT 与 ETL 的对比、批量加载与文件大小、微批与流式摄取、幂等合并 | 能设计一条可以重跑而不会重复或丢失行的加载路径 |
| 7. 成本 | 0016 至 0017 | 各平台的按需计费与容量计费、读懂查询的成本、缓存、物化视图以及限制账单的控制手段 | 能估算一个工作负载的成本，并在不改变结果的前提下降低它 |
| 8. 判断力 | 0018 至 0020 | 数据仓库、Postgres 与湖仓的对比，评审 schema 及其账单，修改别人在查询的模型，依据平台文档裁定争议 | 可以信赖他做出判断，并向别人解释清楚 |

| [0007](lessons/0007-partitioning-and-pruning.md) | 分区与分区裁剪 | 分区表如何让过滤条件跳过整个分区，以及哪些过滤条件会悄悄扫描全部数据 |
| [0008](lessons/0008-clustering-and-sort-keys.md) | 聚簇与排序键 | 在存储内部对数据排序，如何收紧每个块的最小值和最大值，让过滤条件跳过更多的块 |
| [0009](lessons/0009-joins-and-data-distribution.md) | Join 与数据分布 | 分布式数据仓库如何移动行来完成 join，以及数据分布的选择如何决定它是否必须这样做 |
| [0010](lessons/0010-the-row-store-advice-that-stops-applying.md) | 不再适用的行存储建议 | 为行存储建索引和做规范化的哪些习惯在列式数据仓库上是错的，哪些依然成立 |
| [0011](lessons/0011-facts-dimensions-and-the-grain.md) | 事实、维度与粒度 | 如何在选择任何一列之前，先声明事实表中一行代表什么 |
| [0012](lessons/0012-star-schemas-wide-tables-and-nesting.md) | 星型模型、宽表与嵌套 | 什么时候把维度放在各自的表里，什么时候把它们展平成一张宽表，什么时候把它们嵌套起来 |
| [0013](lessons/0013-slowly-changing-dimensions.md) | 缓慢变化维度 | 属性变化时，维度如何保留或丢弃它的历史，以及每种选择对旧报表有什么影响 |
| [0014](lessons/0014-elt-and-batch-loading.md) | ELT 与批量加载 | 为什么数据仓库先加载原始数据再就地转换，以及文件的数量和大小如何决定加载速度 |
| [0015](lessons/0015-micro-batch-streaming-and-idempotent-merges.md) | 微批、流式与幂等合并 | 如何持续地写入数据，并让任何一次加载的重跑都让表的状态和只运行一次时完全相同 |
| [0016](lessons/0016-how-a-warehouse-bills.md) | 数据仓库如何计费 | 每个平台在按需计费和容量计费下分别对什么收费，以及每种计费模式适合什么样的工作负载 |
| [0017](lessons/0017-reading-and-cutting-a-querys-cost.md) | 读懂并降低查询的成本 | 如何在运行查询之前知道它的成本，以及哪些改动能在不改变结果的前提下降低成本 |
| [0018](lessons/0018-warehouse-postgres-or-lakehouse.md) | 数据仓库、Postgres 还是湖仓 | 如何决定一个分析负载应该放在哪里，以及什么时候“用数据仓库”这个惯常答案是错的 |
| [0019](lessons/0019-reviewing-a-warehouse-schema-and-its-bill.md) | 评审数据仓库 schema 及其账单 | 如何评审别人的数据仓库设计，并说出每个选择在字节和金钱上的代价 |
