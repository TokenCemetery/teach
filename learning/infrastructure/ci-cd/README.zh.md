# 学习：CI/CD

通过一条由你负责的流水线，把任何服务从一次已合并的改动带到生产环境中运行：在几分钟内证明每次改动都能构建并通过测试，产出一个带版本的制品，并让同一个制品在各个环境之间逐级晋升，给流水线它所需的访问权限而不依赖长期有效的密钥，用一种能限制糟糕发布所造成损害的策略来部署，并在糟糕的发布溜出去时回滚。学完后，你能评审别人的流水线，指出什么会最先失败、变慢或泄露，修改其他团队依赖的工作流而不破坏他们的合并，并说出什么时候惯常的交付答案是错的。

**最新课程：** [30. 当惯常答案出错时](lessons/0030-when-the-usual-answer-is-wrong.md)

## 成功的标准

- 解释持续集成、持续交付和持续部署各自承诺了什么，以及团队必须践行什么，这些承诺才能成立。
- 把流水线写成代码：触发器与事件、作业、步骤与运行器、action、表达式、上下文与输出。
- 运行构建和测试阶段，让最廉价的问题最先失败，跨矩阵运行，使用缓存，不信任不稳定的测试，并且快到人们愿意等待结果。
- 产出版本可追溯到某次提交的制品，只构建一次，并构建、发布容器镜像，通过摘要引用它。
- 以最小权限给流水线提供密钥和云访问：限定范围的 `GITHUB_TOKEN` 权限，用 OIDC 取代长期有效的密钥，并且不给不可信输入留下触及二者的路径。
- 用环境和审批把关部署，并把同一个制品从预发布环境晋升到生产环境。
- 用滚动、蓝绿和金丝雀策略部署，回滚或前滚，围绕部署安排数据库迁移的顺序，并在推送式部署与 GitOps 之间做出选择。
- 保障供应链安全：固定流水线所运行的内容，并生成和验证来源证明（provenance）与 SBOM。
- 借助可复用工作流、组合 action 和路径过滤器，在多个仓库和单体仓库之间扩展流水线，并调试只在运行器上失败的流水线。
- 评审别人的流水线，修改共享工作流或必需检查而不破坏依赖它的团队，说出什么时候惯常答案是错的，并依据工作流语法参考裁定有争议的行为。

## 约束

- 假定你熟悉 Git、shell，以及用一种语言构建和测试项目。不要求具备 CI/CD 的知识。第 13 课假定你学过[容器系列](../containers/README.md)或具备同等基础，第 19 课和第 22 课假定你掌握 [Kubernetes 系列](../kubernetes/README.md)的基础。
- 讲授流水线要完成的任务，并用 GitHub Actions 来完成它们，就像 `programming/java` 用 Maven 讲授构建生命周期一样。Jenkins 和 GitLab CI 只在它们的模型确实不同的地方出现。
- 每个练习都在免费 GitHub 账号下的一次性公开仓库中运行，在那里 GitHub 托管的运行器不收费。部署练习部署到在作业内创建的 kind 集群，所以不需要云账号。当某节课依赖云服务商（例如 OIDC 信任策略）时，它会展示仅靠 GitHub 就能展示的部分，并把其余部分标为可选。

## 范围之外

- 构建和测试某一种语言的代码。流水线步骤运行的命令归各语言系列负责，例如 [Java：测试与构建](../../programming/java/reference/testing-and-build.md)、[Go：工具链命令](../../programming/golang/reference/toolchain-commands.md)、[Python：项目与打包](../../programming/python/reference/project-and-packaging.md) 和 [C#：测试与构建](../../programming/csharp/reference/testing-and-build.md)。本系列负责在流水线中运行这些步骤。
- 手写 Dockerfile 并手动构建镜像。那属于[容器系列](../containers/README.md)，其中的 [Dockerfile](../containers/reference/dockerfile.md) 速查表正是第 13 课在流水线中构建的内容。
- 交付之后运行工作负载：探针、作为集群功能的滚动发布、打包清单。那属于 [Kubernetes 系列](../kubernetes/README.md)，其中的[打包](../kubernetes/reference/packaging.md)速查表涵盖部署作业所应用的清单。本系列负责把改动交付给它，对 GitOps 的讲解只到足以做出选择为止。
- 编写不会锁表的迁移。那属于 [SQL](../../programming/sql/README.md)，其中的[运维](../../programming/sql/reference/operating.md)速查表收录了迁移安全表。本系列负责在一次部署中安排迁移的顺序。
- 安装和管理 CI 服务器、编写 JavaScript 或 Docker 容器 action，以及移动应用商店的发布。

## 学习路线

共十个阶段，从 CI 和 CD 承诺了什么，到评审别人流水线的判断力。一个阶段包含若干课程，边界并不严格；一个阶段是否完成，取决于能力，而不是课程数量。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. CI 和 CD 的用途 | 0001 至 0002 | 作为承诺的集成、交付和部署，基于主干的开发，作为代码的流水线，Jenkins 和 GitLab 中的对应物 | 能说出流水线保证了什么，并把任何工作流文件当作代码来读 |
| 2. 工作流的构成 | 0003 至 0005 | 事件与过滤器、作业、步骤、运行器、`needs`、action、表达式、上下文与输出 | 能写出在预期时机运行、并在作业之间传递数据的工作流 |
| 3. 快速、可信的反馈 | 0006 至 0010 | 阶段顺序、服务容器、矩阵、缓存、不稳定的测试、关键路径、并发与超时 | 能运行一条人们信任并愿意等待的流水线 |
| 4. 制品与版本 | 0011 至 0013 | 制品与缓存的对比、构建标识、只构建一次、构建并按摘要发布镜像 | 能产出一个可追溯的制品，并把同一个制品交给之后的每个阶段 |
| 5. 密钥与信任 | 0014 至 0016 | 密钥、掩码、`GITHUB_TOKEN` 权限、OIDC 联合身份、脚本注入、`pull_request_target` | 能只给流水线它需要的访问权限，并让不可信输入远离它 |
| 6. 环境与晋升 | 0017 至 0018 | 环境、保护规则、环境密钥、在按环境配置的前提下晋升同一个制品 | 能把关生产部署，并晋升预发布环境测试过的内容 |
| 7. 部署与回滚 | 0019 至 0022 | 重建、滚动、蓝绿和金丝雀，回滚、前滚与功能开关，扩展与收缩式迁移，推送式部署与 GitOps | 能用限制损害的策略部署，并撤销糟糕的发布 |
| 8. 供应链 | 0023 至 0024 | 固定 action 和依赖、Dependabot、SLSA 来源证明、制品证明、SBOM | 能说出流水线运行了什么，并证明一个制品从何而来 |
| 9. 规模化的流水线 | 0025 至 0027 | 可复用工作流、组合 action、单体仓库中的路径过滤器与必需检查、调试日志、运行器差异 | 能在团队之间共享流水线逻辑，并找出一次运行失败的原因 |
| 10. 判断力 | 0028 至 0030 | 评审流水线、修改共享工作流或必需检查、惯常答案何时出错、依据工作流语法参考做出裁定 | 值得信任去对流水线做出决定，并向别人解释清楚 |

## 课程

请按顺序学习。

| # | 课程 | 内容 |
|---|---|---|
| [0001](lessons/0001-what-ci-and-cd-promise.md) | CI 和 CD 承诺了什么 | 持续集成让每次改动都合并到 main 并得到验证，持续交付让 main 始终可发布，持续部署则发布每一个通过检查的改动 |
| [0002](lessons/0002-pipelines-as-code.md) | 流水线即代码 | 仓库中的工作流文件像它所构建的代码一样被版本化、评审和运行，Jenkins 和 GitLab 表达的也是同一个理念 |
| [0003](lessons/0003-triggers-and-events.md) | 触发器与事件 | 在推送、拉取请求、定时任务时或手动启动工作流，按分支和路径过滤，并清楚每个事件针对的是哪次提交 |
| [0004](lessons/0004-jobs-steps-and-runners.md) | 作业、步骤与运行器 | 除非用 needs 排定顺序，作业会在全新的运行器上并行运行，步骤共享同一个工作区，而托管运行器与自托管运行器是在成本与控制权之间取舍 |
| [0005](lessons/0005-actions-expressions-and-outputs.md) | action、表达式与输出 | 用 uses 复用 action，用 if 和基于上下文的表达式做判断，并通过输出在步骤和作业之间传递值 |
| [0006](lessons/0006-build-and-test-stages.md) | 构建与测试阶段 | 排好 lint、构建、单元测试和集成测试阶段的顺序，让最廉价的失败最先出现，并为需要数据库的测试提供服务容器 |
| [0007](lessons/0007-matrix-builds.md) | 矩阵构建 | 用矩阵让一个作业跨多个版本和平台运行，并控制 fail-fast、include 和 exclude 对运行的影响 |
| [0008](lessons/0008-caching.md) | 缓存 | 以锁文件作为缓存键，用 restore keys 回退，并清楚哪些东西绝不能信任缓存来保存 |
| [0009](lessons/0009-flaky-tests.md) | 不稳定的测试 | 在代码没有改动时失败的测试会摧毁人们对整条流水线的信任，所以要找出原因并将其隔离，而不是用重试把它掩盖起来 |
| [0010](lessons/0010-making-a-pipeline-fast.md) | 让流水线变快 | 缩短关键路径，用并发组取消被取代的运行，并设置超时，让卡住的作业无法占住队列 |
| [0011](lessons/0011-artifacts.md) | 制品 | 用制品在作业之间传递构建产物并在运行结束后保留它，以及为什么制品不是缓存 |
| [0012](lessons/0012-versioning-a-build.md) | 为构建定版本 | 给每次构建一个可追溯到其提交的标识，并只构建一次，让被测试的东西就是被发布的东西 |
| [0013](lessons/0013-building-and-publishing-an-image.md) | 构建并发布镜像 | 在工作流中构建、打标签并推送容器镜像，缓存它的层，并把它的摘要交给之后的阶段 |
| [0014](lessons/0014-secrets-and-the-github-token.md) | 密钥与 GITHUB_TOKEN | 按仓库和环境保存密钥，清楚掩码会漏掉什么，并用权限设置削减 GITHUB_TOKEN 的能力 |
| [0015](lessons/0015-oidc-instead-of-long-lived-keys.md) | 用 OIDC 取代长期有效的密钥 | 让云平台信任为单次运行签发的短期令牌，并用 subject 声明限定这份信任的范围 |
| [0016](lessons/0016-untrusted-input.md) | 不可信输入 | 标题、分支名和 fork 中的代码都是攻击者的输入，而检出 fork 代码的 pull_request_target 会把你的密钥交给他们 |
| [0017](lessons/0017-environments-and-approvals.md) | 环境与审批 | 用环境、必需审阅者、部署分支规则和环境密钥为部署把关 |
| [0018](lessons/0018-promotion-between-environments.md) | 在环境之间晋升 | 按摘要把同一个已构建的制品从预发布环境移到生产环境，并按环境提供配置 |
| [0019](lessons/0019-deployment-strategies.md) | 部署策略 | 重建、滚动、蓝绿和金丝雀，各自在容量和风险上付出什么代价，以及金丝雀必须度量什么才有意义 |
| [0020](lessons/0020-rollback-and-roll-forward.md) | 回滚与前滚 | 通过重新部署上一个良好的制品来回滚，在数据已经向前演进时前滚，并用功能开关把部署与发布分开 |
| [0021](lessons/0021-database-migrations-in-a-deploy.md) | 部署中的数据库迁移 | 用扩展与收缩的方式围绕代码安排 schema 变更的顺序，使部署期间运行的每个版本都能与 schema 正常配合 |
| [0022](lessons/0022-push-deploys-and-gitops.md) | 推送式部署与 GitOps | 向集群推送的流水线与在集群内从 Git 拉取的代理的对比，以及二者各自对凭据和漂移有什么影响 |
| [0023](lessons/0023-pinning-what-the-pipeline-runs.md) | 固定流水线运行的内容 | 把第三方 action 固定到完整的提交 SHA，锁定依赖，并用 Dependabot 让这些固定保持最新 |
| [0024](lessons/0024-provenance-and-sboms.md) | 来源证明与 SBOM | 证明制品在哪里、用什么构建，列出它内部包含什么，并在它运行之前验证这两者 |
| [0025](lessons/0025-reusable-workflows-and-composite-actions.md) | 可复用工作流与组合 action | 用被调用的工作流或组合 action 在仓库之间共享流水线逻辑，并根据各自能容纳的内容做出选择 |
| [0026](lessons/0026-monorepos-and-path-filters.md) | 单体仓库与路径过滤器 | 用路径过滤器只运行改动涉及的部分，以及为什么一个被跳过的必需检查会阻塞所有合并 |
| [0027](lessons/0027-debugging-a-pipeline.md) | 调试流水线 | 阅读日志，开启调试日志重新运行，并在本地能通过时找出运行器与你的机器之间的差异 |
| [0028](lessons/0028-reviewing-a-pipeline.md) | 评审流水线 | 评审别人的工作流，指出什么会最先失败、变慢或泄露 |
| [0029](lessons/0029-changing-a-shared-workflow.md) | 修改共享工作流 | 修改其他团队依赖的可复用工作流或必需检查，而不破坏他们的合并 |
| [0030](lessons/0030-when-the-usual-answer-is-wrong.md) | 当惯常答案出错时 | 说出持续部署、金丝雀或某项流水线默认设置何时是错误的选择，并依据工作流语法参考裁定有争议的行为 |

## 使用方式

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
