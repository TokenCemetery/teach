# LLM 智能体术语表

构建智能体时使用的规范术语：循环由哪些部分组成，以及在一个常常用四个词指同一件事的领域里，每个部分该叫什么。

## 术语

**跨运行记忆（Across-run memory）**:
存放在任何单条轨迹之外的事实，并被有意加载回新一次运行的初始上下文，因为全新的运行是从空的对话记录开始的。
_避免使用_: 草稿区（二者是不同的机制，把它们混为一谈是这里最常见的错误），状态（state，过于笼统）

**智能体（Agent）**:
在循环中带着工具运行语言模型的系统，由模型决定调用哪个工具、何时调用以及何时停止，而不是沿着开发者预先固定的路径执行。
_避免使用_: 助手（assistant）、机器人（bot）、copilot（这些是产品用语，无法说明控制流是固定的还是由模型决定的）

**智能体循环（Agent loop）**:
运行中的智能体不断重复的周期：把对话记录发给模型，执行返回的工具调用，把结果追加到对话记录，如此重复，直到某个停止条件触发。
_避免使用_: 链（chain）、流水线（pipeline）（二者指的都是固定的序列，而这恰恰是智能体循环不具备的特征）

**审批关卡（Approval gate）**:
运行框架层面的检查点，在执行属于高风险类别的调用之前暂停循环，直到有人批准或拒绝。
_避免使用_: 人在回路中（human-in-the-loop，过于宽泛，审批关卡指的是这一种具体机制）

**自主性谱系（Autonomy spectrum）**:
从单个提示词，到开发者固定的工作流，再到由模型主导的智能体，按控制流中有多少是由模型在运行时选择、而不是由开发者事先选定来排序的范围。
_避免使用_: “有多智能体化”（how agentic，把自主性当成一个模糊的单一量，而它其实是一个有可检验答案的控制流问题）

**客户端工具（Client tool）**:
实现运行在运行框架自身代码里的工具，所以模型请求它时，由运行框架直接执行。
_避免使用_: 本地工具（local tool）、自定义工具（custom tool）

**压缩（Compaction）**:
用模型仍可据以行动的精简摘要，替换掉一段旧的对话记录，以损失一部分信息为代价，换取更小的常驻上下文。
_避免使用_: 摘要（summarization，过于笼统，压缩特指针对智能体自身的对话记录，而不是任意文本）

**混淆代理人（Confused deputy）**:
一个拥有合法权限的组件，被不可信内容欺骗，替攻击者滥用了这份权限，而它本身并没有被攻破。
_避免使用_: “模型被黑了”（nothing was compromised，什么都没有被攻破，工具只是做了它被设计为允许的事）

**上下文污染（Context poisoning）**:
一条没有依据或错误的说法进入对话记录，随后被之后的每一轮悄悄当作既定事实对待。
_避免使用_: 幻觉（hallucination，过于宽泛，上下文污染特指一条已经进入并留存在对话记录中的说法，而不是任何一次单独的错误输出）

**上下文腐化（Context rot）**:
随着低相关性内容在上下文中不断累积，模型的注意力和准确率随之下降，即使没有任何所需信息被截断。
_避免使用_: “上下文满了”（把硬性的 token 上限与一个软性的准确率问题混为一谈，而后者远在达到上限之前就已开始）

**单个完成任务的成本（Cost per completed task）**:
一个任务真正成功所需要的每一次尝试、每一次重试和每个工作者的 token 成本，而不只是最后那次成功调用的成本。
_避免使用_: 单次 API 调用成本（cost per API call，会低估一个需要多次尝试才成功的任务）

**扇出（Fan-out）**:
编排者同时派出多个工作者，去处理同一问题的不同变体，用 token 成本换取并行的实际耗时。
_避免使用_: 并行（parallelism，过于笼统，扇出是产生并行的那种具体的多智能体形态）

**落点定位（Grounding）**:
把模型的意图转换为实际的屏幕坐标或屏幕上的目标，这一步本身就可能出错，即使模型最初的决定是正确的。
_避免使用_: 点击准确率（click accuracy，过于狭窄，落点定位涵盖任何从观察到动作的映射，而不只是点击）

**交接（Handoff）**:
一个智能体完成自己负责的那部分任务，把干净且有边界的上下文，而不是它的完整轨迹，交给第二个专门的智能体去完成下一阶段。
_避免使用_: 扇出（交接是顺序的，扇出是并行的，见本课中的对比）

**运行框架（Harness）**:
模型周围的那层代码，负责保存对话记录、执行工具调用、强制执行限制，并决定循环何时结束。模型做选择，运行框架去行动。
_避免使用_: 运行时（runtime）、框架（framework，框架只是运行框架的一种可能实现，而不是这个概念本身）

**最小权限（Least privilege）**:
把每个工具的访问范围限定在它真正需要的程度，而不是“以防万一”地授予宽泛的访问权。
_避免使用_: 沙箱（sandboxing，沙箱负责强制执行边界，最小权限则是决定这条边界该划多窄的设计原则）

**致命三要素（Lethal trifecta）**:
可访问私有数据、会接触不可信内容、能够向外部通信，这三者结合在一起，就会让智能体变得可被利用。去掉其中任何一个，攻击就无法成立。
_避免使用_: “安全风险”（security risk，过于含糊，无法据此行动，致命三要素给出的是需要检查的三个具体条件）

**编排者（Orchestrator）**:
多智能体系统中负责拆解任务、把子任务分派给工作者并综合它们的报告的那个智能体，它自己不做子任务的工作。
_避免使用_: 经理（manager）、协调者（coordinator）（这些泛称无法把这个角色与工作者区分开）

**提示词注入（Prompt injection）**:
智能体读到的、带有意在劫持其行为的指令的内容，利用的是模型在结构上无法区分数据和指令这一点。
_避免使用_: 越狱（jailbreak，越狱直接针对模型自身的拒绝训练，注入则把指令藏在智能体被要求处理的内容之中）

**ReAct**:
在每个动作之间穿插一小步推理的模式，使每一步的推理都能针对前一步的实际结果做出反应。
_避免使用_: 思维链（chain-of-thought，指的只是推理文本本身，ReAct 特指把推理与工具动作及其观察到的结果交错进行）

**反思（Reflection）**:
一个明确的阶段，智能体用自然语言评估一次失败的尝试，并把这份评估带入下一次尝试，这不同于在相同上下文里简单地重试。
_避免使用_: 自我纠正（self-correction，用来泛指模型内部做的任何事，反思指的是外部的、被存储并带入下一次的版本）

**按需检索（Retrieval on demand）**:
上下文中只常驻一份摘要或引用，只有模型真正需要时，才通过一次工具调用把完整细节取回来。
_避免使用_: RAG（RAG 从外部语料库检索，而这里检索的是智能体自己已经产生、或可以直接访问的细节）

**沙箱（Sandbox）**:
运行框架在工具代码能触及的范围（文件系统、网络、资源）周围强制设立的执行边界，无论模型请求的是什么。
_避免使用_: 权限（permission，权限是你授予的东西，沙箱则是即使面对格式错误或带有恶意的调用，也能强制执行这项授权的机制）

**草稿区（Scratchpad）**:
智能体在单次运行中写下并读回的笔记。它其实只是对话记录的一部分，运行结束后就消失了。
_避免使用_: 记忆（memory，草稿区无法在写入它的那次运行之后留存）

**服务端工具（Server tool）**:
由服务商在自己的基础设施上，代运行框架执行的工具，例如托管的网页搜索或沙箱中的代码执行。运行框架从不运行它的实现，只从服务商的响应中读取结果。
_避免使用_: 托管工具（hosted tool）、内置工具（built-in tool）

**子智能体（Sub-agent）**:
一次独立的智能体运行，拥有自己的对话记录和运行框架，被拉起来完成一项有边界的工作，它对父智能体上下文的唯一影响，就是它回报的那份摘要。
_避免使用_: 在编排者与工作者系统之外使用“工作者”（worker 指的是由编排者交付有边界任务的子智能体，机制相同，术语指明的是角色）

**token 放大（Token amplification）**:
一个任务作为智能体循环运行时，比作为单个提示词多花多少 token，来源是对话记录的重复增长、多智能体的重复劳动，以及重试的层层叠加。
_避免使用_: “智能体很贵”（agents are expensive，过于含糊，放大指的是具体的倍数，以及其中每一部分来自哪里）

**工具（Tool）**:
以名称、描述和参数 schema 的形式提供给模型的能力，模型可以请求它，运行框架代为执行。
_避免使用_: 函数调用（function call，指的是模型发出的那条消息，而不是这项能力）、插件（plugin）、skill

**追踪（Trace）**:
智能体一次运行的结构化、带时间戳的记录，由多个 span 组成，采用与厂商无关的约定，因此一个工具的追踪可以在另一个工具里读取。
_避免使用_: 日志（log，非结构化日志正是追踪所取代的东西，追踪有明确定义的 schema，可以被工具查询）

**轨迹（Trajectory）**:
智能体一次运行的完整有序记录：每一次模型轮次、工具调用、工具结果和停止决定。诊断失败时读的是它，而不只是最终答案。
_避免使用_: 对话记录（transcript，模型实际看到的消息列表，不包含运行框架自己的决定）、历史（history）、日志（log）

**工作者（Worker）**:
由编排者交付有边界子任务的子智能体，运行自己的循环和对话记录，与其他工作者相互隔离。
_避免使用_: 用“子智能体”指编排角色（子智能体指的是机制，工作者指的是这个机制中的这个具体角色）

**工作流（Workflow）**:
开发者预先固定了模型调用和工具调用顺序的系统。它可以包含分支和循环，但路径不由模型选择。
_避免使用_: 智能体（二者的区别正是第 1 阶段的要点）、链（chain）
