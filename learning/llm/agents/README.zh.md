# 学习：LLM 智能体

学会亲手构建一个智能体循环，判断某个任务到底需不需要智能体，而不是用固定的工作流，并且能从轨迹出发诊断一个出问题的智能体，而不是在它的提示词里再多加一条指令。

**最新课程：** [0037. 评审别人的智能体设计](lessons/0037-reviewing-someone-elses-agent-design.md)

## 成功的标准

- 为一个给定的任务写出智能体循环，说清上下文里每条消息在做什么，以及什么会让循环结束。
- 针对一个任务，在单个提示词、固定工作流和智能体之间做出选择，并拿被放弃的那个方案的成本来为这个选择辩护。
- 设计智能体的工具面：名称、描述、返回形态，以及决定它无人看管时可以做什么的权限边界。
- 从轨迹出发诊断出问题的智能体，指出原因（循环、被污染的上下文、定义有误的工具、错误的停止条件），而不是随意地重新写提示词。
- 解释为什么读取不可信内容的智能体不能只靠提示词里的指令来保证安全，并设计出真正守得住的边界。
- 估算智能体循环的 token 成本和延迟，并说出放大效应来自循环的哪个部分。

## 约束

- 不限定服务商。循环、工具 schema 和控制流都用类 Python 的伪代码给出，所以这些内容不会随工具调用 API 的频繁变动而过时，而大多数智能体的文章都栽在这上面。
- 传输格式是个例外，因为工具调用消息在传输中的样子是事实，而不是算法。课程会展示一对真实抓取的请求和响应，第二个服务商只作为与它的差异出现。
- 不预设也不讲授任何框架。框架能带来什么（持久状态、图式控制流、恢复执行）在接近结尾处作为一个决策讲一次，而不是作为教程。
- 练习以检查为主，而不是以构建为主：阅读真实的追踪、真实的工具 schema、真实的 MCP 服务器清单，并为一个已经在运行的智能体标出权限边界。
- 假定你知道语言模型是什么，并能轻松阅读类 Python 的代码。不要求有构建智能体的经验。

## 范围之外

- 作为一门学科的评测：见 [`llm/evals`](../../llm/evals/)（第 0013 课讲轨迹、任务成功与步骤准确率的对比，以及 `pass^k`）。这里只把它当作构建智能体的人需要的那一项能力来讲，并链接过去，而不重复其内容。
- 检索流水线的内部机制：见 [`llm/rag`](../../llm/rag/)。检索在这里是智能体调用的一个工具，而不是分块、嵌入和重排序。
- 服务与推理的内部机制：延迟、批处理和约束解码见 [`llm/inference`](../../llm/inference/)。
- 训练模型使用工具：见 [`llm/finetuning`](../../llm/finetuning/)。
- 作为分布式系统问题的重试、幂等和部分失败：见 [`architecture/distributed-systems`](../../architecture/distributed-systems/)。这里只讲工具调用与普通远程调用不同的那些方面。
- 作为一门主题的提示词工程（指令、示例、推理、结构化输出、模板，以及衡量提示词改动）：见 [`llm/prompting`](../../llm/prompting/)。本系列保留工具描述、带工具的注入，以及并发下的缓存，提示词工程的通用内容则链接到那里。

## 学习路线

共十六个阶段，从零基础到资深的判断力。这不是课程清单：一个阶段包含若干课程，边界并不严格。

| 阶段 | 课程 | 内容 | 完成的标志 |
| --- | --- | --- | --- |
| 1. 智能体是什么 | 0001 至 0002 | 循环、智能体与工作流与链的对比、自主性谱系 | 能对一个系统分类，并说出“智能体”这个词用在它身上是否恰当 |
| 2. 工具调用的机制 | 0003 至 0005 | 工具调用的传输格式、参数 schema、谁执行什么、并行调用、作为结果返回的错误 | 能读懂一次原始的工具调用交互，并说出每条消息起了什么作用 |
| 3. 从零写出循环 | 0006 至 0007 | 编写循环、停止条件、作为智能体全部状态的对话记录 | 能写出智能体循环，并为它在哪里停下辩护 |
| 4. 作为提示词工程的工具设计 | 0008 至 0009 | 作为提示词界面的名称和描述、返回形态、结果的 token 成本、工具集膨胀 | 能设计工具面，并说出每条描述为什么这样措辞 |
| 5. 上下文管理 | 0010 至 0012 | 作为核心预算的窗口：截断、压缩、按需检索、作为上下文隔离的子智能体 | 能为长时间运行的任务规划什么内容在何时离开上下文 |
| 6. 记忆与状态 | 0013 至 0014 | 单次运行内的草稿区与跨运行记忆、作为记忆的文件、检索为什么不是记忆 | 能选择某个事实该存放在哪里，并说出运行结束时会发生什么 |
| 7. 规划与反思 | 0015 至 0017 | ReAct、先规划后执行、自我批评、任务拆解、推理模型改变了什么 | 能为任务选定规划模式，并说出它在 token 和延迟上的代价 |
| 8. 多智能体 | 0018 至 0019 | 编排者与工作者、交接、扇出、协调成本、何时一个工具更好的智能体胜出 | 能判断第二个智能体是否带来了第一个智能体无法通过补充能力获得的东西 |
| 9. 协议与互操作 | 0020 至 0021 | MCP 的工具、资源、提示词与传输方式，服务商的函数调用格式，大规模工具发现 | 能读懂 MCP 服务器的清单，并说出它暴露了什么、没有标准化什么 |
| 10. 执行环境 | 0022 至 0023 | 沙箱、作为工具的代码执行、文件系统访问、人在回路中的审批关卡 | 能为一组给定的工具划定沙箱边界 |
| 11. 计算机使用与浏览器智能体 | 0024 至 0026 | 作为观察的截图、把动作落到坐标上、可靠性问题 | 能说出驱动屏幕的智能体与调用工具的智能体为什么失败方式不同 |
| 12. 失败模式与可观测性 | 0027 至 0029 | 循环、上下文污染、级联的工具错误、幻觉参数、追踪与轨迹回放 | 给定一条轨迹，能指出出错的那一步，而不是重新写提示词 |
| 13. 评估智能体 | 0030 至 0030 | 结果与轨迹的对比、重复试验的可靠性、智能体基准测试实际衡量的是什么 | 能说出针对某个智能体该衡量什么，并把其余部分交给 `llm/evals` |
| 14. 安全 | 0031 至 0032 | 作为智能体决定性问题的提示词注入、致命三要素、最小权限、混淆代理人、MCP 供应链 | 能设计出在智能体读到恶意内容时仍然守得住的权限边界 |
| 15. 生产、成本，以及框架能带来什么 | 0033 至 0035 | token 放大、提示词缓存、并发、持久性与可恢复性、单个完成任务的成本 | 能估算循环的成本，并说出某次部署真正需要框架的哪项保证 |
| 16. 判断力 | 0036 至 0037 | 何时不该构建智能体、评审别人的智能体设计并说出每个选择的代价、以一手资料裁定有争议的说法 | 可以信赖他做出判断，并向别人解释清楚 |

## 使用方式

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
