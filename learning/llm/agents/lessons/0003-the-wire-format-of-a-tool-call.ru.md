# Урок 3. Формат вызова инструмента на проводе

**Связь с целью курса:** Напишите цикл агента для поставленной задачи и назовите, что делает каждое сообщение в его контексте и что завершает цикл.
**Первоисточник:** [Документация: "Tool use with Claude", Claude Platform Docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)
**Предварительные требования:** [Урок 2](0002-agent-workflow-or-prompt.md), [Инструмент](../GLOSSARY.md)

## Разминка

1. ▢ Чем отличается вызов моделью обвязкой от исполнения обвязкой инструмента?

<details markdown="1"><summary>Проверка</summary>

Обвязка вызывает модель, отправляя ей по сети запрос (транскрипт плюс инструменты) к API провайдера; модель работает внутри инфраструктуры провайдера и возвращает структурированный вывод. Инструмент вызывается, когда модель просит о нём, выдавая структурированный блок вызова инструмента; обвязка исполняет его, как правило вызывая функцию в той же кодовой базе или в той же сети.

</details>

2. ▢ В каком случае модель может прислать обычный текст вместо вызова инструмента?

<details markdown="1"><summary>Проверка</summary>

Когда модель закончила задачу, над которой работала, и готова вернуть пользователю окончательный ответ, или когда она решает (в пределах заданных вами ограничений), что на этом ходу вызывать инструмент ей не нужно.

</details>

## Что нужно знать

### Вызов инструмента на проводе

Когда вы отправляете провайдеру модели запрос с просьбой пользоваться инструментами, запрос содержит три вещи: имя модели, список доступных инструментов (с их именами, описаниями и схемами параметров) и транскрипт разговора на данный момент.

Определение инструмента выглядит так: имя, описание для человека и JSON Schema, которая ограничивает параметры, какие может прислать модель. Вот запрос Anthropic с единственным инструментом:

```json
{
  "model": "claude-sonnet-5",
  "max_tokens": 1024,
  "tools": [
    {
      "name": "get_weather",
      "description": "Get the current weather for a given city",
      "input_schema": {
        "type": "object",
        "properties": {
          "city": {"type": "string", "description": "The city name"}
        },
        "required": ["city"]
      }
    }
  ],
  "messages": [
    {"role": "user", "content": "What's the weather in Lisbon?"}
  ]
}
```

Когда модель решает вызвать инструмент, она его не исполняет. Вместо этого она возвращает структурированный блок, описывающий, какой инструмент вызвать и какие аргументы передать. Провайдер прекращает выдачу и сообщает об этом полем `stop_reason`. Вот полный ответ Anthropic:

```json
{
  "id": "msg_01ABC",
  "type": "message",
  "role": "assistant",
  "content": [
    {"type": "text", "text": "I'll check that for you."},
    {
      "type": "tool_use",
      "id": "toolu_01XYZ",
      "name": "get_weather",
      "input": {"city": "Lisbon"}
    }
  ],
  "stop_reason": "tool_use"
}
```

Обратите внимание: поле `input` это уже разобранный JSON, а не строка. Каждый вызов инструмента получает уникальный идентификатор (здесь `toolu_01XYZ`), чтобы обвязка могла сообщить модели, какой результат отвечает на какой вызов. Ассистент может также включить обычный текст до или после блока вызова инструмента.

### От провода к исполнению

Ваша обвязка видит этот ответ и знает, что должна исполнить `get_weather` с аргументом `{"city": "Lisbon"}`. Как это сделать, зависит от инструмента:

- Если это **клиентский инструмент** (функция в вашем собственном коде), вы вызываете его напрямую: `weather_result = get_weather(city="Lisbon")`.
- Если это **серверный инструмент** (то, что провайдер запускает за вас, например размещённый веб-поиск), провайдер уже исполнил его до возврата ответа. Вы достаёте результат из ответа.

### Отправка результата обратно

Когда у обвязки есть результат (из исполнения функции или из чтения ответа провайдера), она отправляет его обратно модели в новом сообщении, помеченном идентификатором вызова инструмента. Формат Anthropic вкладывает его в сообщение с ролью `user`:

```json
{
  "role": "user",
  "content": [
    {
      "type": "tool_result",
      "tool_use_id": "toolu_01XYZ",
      "content": "18C, partly cloudy"
    }
  ]
}
```

Это сообщение попадает в транскрипт как новый ход. Теперь у модели есть и вызов инструмента, который она сделала, и результат, и она решает, что делать дальше: вызвать другой инструмент, вызвать тот же с другими аргументами или вернуть окончательный ответ.

### Формат OpenAI на проводе (отличие)

API OpenAI использует те же понятия, но другие имена полей и формы. Вместо того чтобы пересказывать весь обмен, вот что отличается:

Параметры инструмента вкладываются в `function.parameters` вместо голого `input_schema`. Аргументы вызова инструмента от модели приходят как закодированная в JSON строка в `function.arguments`, а не как заранее разобранный объект, поэтому обвязка должна её разобрать. Сигнал остановки это `finish_reason: "tool_calls"` вместо `stop_reason: "tool_use"`. Результат возвращается отдельным сообщением `role: "tool"` с `tool_call_id`, а не оборачивается в сообщение `user`. Вот сокращённый пример для той же задачи с погодой:

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": null,
      "tool_calls": [{
        "id": "call_abc123",
        "type": "function",
        "function": {"name": "get_weather", "arguments": "{\"city\": \"Lisbon\"}"}
      }]
    },
    "finish_reason": "tool_calls"
  }]
}
```

За ним следует результат в виде сообщения `role: "tool"`:

```json
{"role": "tool", "tool_call_id": "call_abc123", "content": "18C, partly cloudy"}
```

Схема та же: определение инструмента, вызов инструмента с идентификатором, результат, помеченный тем же идентификатором. Имена и формы различаются, но любую обвязку, которая справляется с одним, можно приспособить к другому, сопоставив эти поля.

## Практика

1. ▢ Почему в показанном выше ответе Anthropic поле `input` содержит разобранный JSON-объект, а не JSON-строку?

<details markdown="1"><summary>Проверка</summary>

API Anthropic разбирает аргументы вызова инструмента на стороне провайдера перед возвратом, сокращая работу обвязки. Ваш код получает готовые значения, а не строку для разбора. OpenAI присылает аргументы строкой, поэтому в обвязке нужно вызвать `json.parse()` или аналог, прежде чем ими пользоваться.

</details>

2. ▢ Когда вы отправляете результат инструмента обратно модели, зачем он включает поле `tool_use_id`?

<details markdown="1"><summary>Проверка</summary>

Модель могла запросить несколько инструментов за один ход. Идентификатор позволяет модели сопоставить каждый результат с соответствующим сделанным ею вызовом, чтобы знать, какой ответ пришёл на какой запрос.

</details>

3. ▢ В протоколе Anthropic результат инструмента едет внутри сообщения с ролью `user`. В протоколе OpenAI он едет как сообщение `role: "tool"`. Почему эта разница не важна для логики цикла агента?

    - a) Потому что обвязке не нужно их различать при построении транскрипта
    - b) Потому что модель обрабатывает их одинаково независимо от роли
    - c) Потому что один протокол явно неверен и его следует избегать
    - d) Потому что результаты инструментов не входят в официальный транскрипт

<details markdown="1"><summary>Проверка</summary>

**b)** Модель обрабатывает их одинаково независимо от метки роли или структуры сообщения. Логика такая: вот результат вызова инструмента, который вы сделали; что вы хотите делать теперь? Деталь протокола (внутри сообщения пользователя или как сообщение инструмента) эту логику не меняет. (a) близко, но мимо сути: роль не важна самому циклу.

</details>

4. ▢ Обвязка получает такой ответ OpenAI: `"arguments": "{\"city\": \"Paris\"}"`. Как обвязка должна обработать это, прежде чем передать инструменту?

<details markdown="1"><summary>Проверка</summary>

Разобрать как JSON: `json.loads("{\"city\": \"Paris\"}") yields {"city": "Paris"}`. OpenAI возвращает строку, и обвязка должна десериализовать её в словарь (или объект), прежде чем распаковывать аргументы в вызов функции.

</details>

## Практика в реальной работе

- [ ] Откройте код или документацию реального фреймворка для агентов (LangChain, Vercel AI или собственный Python SDK Claude) и найдите, где он отправляет модели определение инструмента. Определите имя, описание и схему параметров. Отметьте, откуда в коде берётся каждое из них.
- [ ] Проследите один полный цикл вызова инструмента в той же кодовой базе: найдите, где она разбирает ответ модели с вызовом инструмента, исполняет инструмент и отправляет результат обратно. Отметьте, как идентификатор используется для их сопоставления.
- [ ] Завтра: напишите минимальную обвязку (не больше 20 строк, псевдокод подойдёт), которая отправляет провайдеру модели один инструмент, разбирает ответ с вызовом инструмента и отправляет результат обратно. Фреймворк не используйте.
