# Урок 6. Пишем цикл

**Связь с целью курса:** Написание цикла агента это ключевое умение для самостоятельного построения агента, и оно прямо служит цели курса: «напишите цикл агента для поставленной задачи и назовите, что делает каждое сообщение в его контексте и что завершает цикл».
**Первоисточник:** [Статья: "Building Effective Agents", Anthropic Engineering](https://www.anthropic.com/engineering/building-effective-agents)
**Предварительные требования:** [Урок 5](0005-parallel-calls-and-errors-as-results.md), [Цикл агента](../GLOSSARY.md)

## Разминка

1. ▢ Из урока 5: что добавляется в транскрипт, когда вызов инструмента даёт сбой?

<details markdown="1"><summary>Проверка</summary>

Результат инструмента с ошибкой, помеченный идентификатором неудавшегося вызова и отмеченный как ошибка, добавляется точно так же, как был бы добавлен успешный результат. Цикл не падает; модель видит сбой как обычный ход.

</details>

2. ▢ Из урока 5: почему модели безопасно просить два инструмента параллельно, а не один за другим?

<details markdown="1"><summary>Проверка</summary>

Потому что каждый вызов инструмента получает свой уникальный идентификатор, а обвязка возвращает каждый результат, помеченный этим же идентификатором. Модель всегда может сопоставить результат с породившим его вызовом независимо от порядка исполнения.

</details>

## Что нужно знать

### Цикл агента как код

В основе цикл агента прост. Вот он в виде псевдокода:

```text
function run_agent(model, tools, transcript, max_turns):
    for turn_count in range(max_turns):
        response = call_model(model, transcript)
        transcript.append(response)

        if response.has_no_tool_calls():
            return response.text

        for tool_call in response.tool_calls:
            result = execute_tool(tools, tool_call)
            transcript.append(result)

    return "Max turns reached"
```

Это обвязка. Модель выбирает, какой инструмент запросить и когда перестать запрашивать. Обвязка обеспечивает лимиты и механику.

Обратите внимание на структуру: **вызвать модель, добавить ответ, проверить, закончили ли мы, иначе исполнить инструменты и добавить их результаты, затем вернуться к началу**. На каждом ходу транскрипт растёт. Ничто не хранится в памяти вне транскрипта.

### Почему транскрипт должен расти на каждом ходу

Начинающие иногда строят цикл вот такого вида:

```text
function run_agent_wrong(model, tools, transcript, max_turns):
    for turn_count in range(max_turns):
        response = call_model(model, transcript)

        if response.has_no_tool_calls():
            return response.text

        for tool_call in response.tool_calls:
            result = execute_tool(tools, tool_call)
            transcript.append(result)  # Only append results, not the model's request
```

Это ошибка. Если вы не добавляете в транскрипт ответ модели с вызовом инструмента до исполнения инструмента, на следующем ходу модель не будет «помнить», что просила инструмент. Когда обвязка снова вызовет модель, в транскрипте не будет сказано «модель попросила поиск» или «модель попросила калькулятор». Модель может снова попросить тот же инструмент, не понимая происходящего. В литературе это называют забыванием запроса. Транскрипт становится несвязным.

Исправление в том, чтобы добавлять ответ **сразу** после вызова модели, прежде чем делать что-либо ещё:

```text
function run_agent_correct(model, tools, transcript, max_turns):
    for turn_count in range(max_turns):
        response = call_model(model, transcript)
        transcript.append(response)  # Append right away

        if response.has_no_tool_calls():
            return response.text

        for tool_call in response.tool_calls:
            result = execute_tool(tools, tool_call)
            transcript.append(result)
```

Теперь, когда цикл повторяется и снова вызывает модель, транскрипт включает «модель сказала, что вызовет поиск», и модель может рассуждать о результате.

### Условия остановки: выбирайте осознанно

Циклу агента нужно останавливаться. Есть несколько мест, где это можно выбрать:

**Максимум ходов**: внешний цикл считает ходы и выходит, если счёт превышает лимит. Это защитное ограждение. Без него сломавшаяся модель или зациклившийся инструмент могли бы работать вечно.

**Нет вызовов инструментов**: ответ модели не содержит вызовов инструментов. Это остановка «по счастливому пути»: модель решила ответить. Проверяйте это после добавления ответа модели.

**Явный инструмент остановки**: можно предложить инструмент `stop` или `finish`, который модель вызывает, чтобы выйти явно. Обвязка проверяет это и возвращает результат. Это полезно, если задача открытая и модели нужно явное действие «я закончила». Если вы предлагаете такой инструмент, опишите его чётко, чтобы модель понимала, когда им пользоваться.

**Ограничитель числа ошибок**: если вызов инструмента даёт сбой, обвязка добавляет ошибку как результат. Если слишком много вызовов инструментов подряд дают сбой, обвязка останавливается и возвращает траекторию с ошибкой, а не продолжает вечно. Это предотвращает циклы повторов.

Они не исключают друг друга. Боевая обвязка может проверять их все:

```text
function run_agent_with_guards(model, tools, transcript, max_turns, max_errors):
    error_count = 0

    for turn_count in range(max_turns):
        response = call_model(model, transcript)
        transcript.append(response)

        if response.has_no_tool_calls():
            return response.text

        if response.has_explicit_stop_tool_call():
            return response.text

        for tool_call in response.tool_calls:
            result = execute_tool(tools, tool_call)

            if result.is_error():
                error_count += 1
                if error_count > max_errors:
                    return "Too many errors"
            else:
                error_count = 0

            transcript.append(result)

    return "Max turns reached"
```

Суть в том, что эти решения должны быть видны в вашем коде, а не скрыты и не случайны. Вы выбираете, когда остановиться, и выбираете, сколько шансов на восстановление получает агент.

## Практика

1. ▢ В показанном выше цикле на псевдокоде почему `transcript.append(response)` должно происходить до проверки `if response.has_no_tool_calls()`?

<details markdown="1"><summary>Проверка</summary>

Транскрипт должен включать ответ модели, чтобы последующие ходы (или наблюдатель, читающий траекторию) видели, что сказала и решила модель. Если проверять остановку до добавления, вы вернёте текст модели, но транскрипт вообще не покажет, что модель отвечала. Кроме того, пропала бы другая информация из ответа (например, какие инструменты модель рассматривала, но решила не вызывать).

</details>

2. ▢ Модель вызывает инструмент, обвязка успешно его исполняет и возвращает результат. Результат добавляется в транскрипт. На следующей итерации цикла обвязка снова вызывает модель. Что модель видит в транскрипте такого, чего не видела на предыдущем ходу?

<details markdown="1"><summary>Подсказка</summary>

Подумайте, что было добавлено на предыдущей итерации цикла, сразу после первого вызова модели.

</details>

<details markdown="1"><summary>Проверка</summary>

Модель видит собственный ответ с вызовом инструмента, добавленный до того, как цикл исполнил инструмент. На втором ходу транскрипт включает и этот ответ, и результат инструмента. Если бы ответ не добавлялся первым, модель видела бы только результат, как будто инструмент вызвало что-то иное, чем модель.

</details>

3. ▢ Вы строите обвязку с ограничителем числа ошибок: если три вызова инструментов подряд дают сбой, остановить цикл. Когда нужно сбрасывать счётчик ошибок в ноль?

    - a) Когда достигнут максимум ходов
    - b) Когда вызов инструмента успешен и возвращает результат без ошибки
    - c) Когда цикл начинается
    - d) Когда ответ модели не содержит вызовов инструментов

<details markdown="1"><summary>Проверка</summary>

**b)** Когда вызов инструмента успешен. Ограничитель нужен, чтобы ловить закономерность повторяющихся сбоев. Если один инструмент дал сбой, а следующий успешен, цикл повторов прерван и можно допустить больше сбоев. Если сбрасывать только в начале (c), остановиться вы не смогли бы никогда; если сбрасывать при достижении максимума ходов или при отсутствии вызовов инструментов (a, d), ограничитель не работает. Сброс при успехе это и есть шаблон: один успех обнуляет счётчик.

</details>

4. ▢ Ваша модель должна выполнить поиск, прочитать документ, а затем сделать сводку. На третьем ходу она снова просит тот же инструмент поиска. В первый раз поиск был успешен. Какая ошибка в вашей обвязке наиболее вероятна, исходя из того, что вы знаете о работе транскриптов?

<details markdown="1"><summary>Проверка</summary>

Обвязка не добавляет в транскрипт ответ модели с вызовом инструмента после вызова модели. Модель никогда не видит собственного запроса инструмента поиска с первого хода. Когда её вызывают на третьем ходу, транскрипт показывает результат поиска, но не запрос, поэтому модель не знает, откуда взялся результат, и снова просит поиск. Исправление в том, чтобы добавлять ответ сразу после вызова модели, до исполнения инструмента.

</details>
