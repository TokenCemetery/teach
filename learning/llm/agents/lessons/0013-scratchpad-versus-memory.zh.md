# 第 13 课：草稿区与记忆

**使命关联:** 从轨迹出发诊断出问题的智能体，而不是在它的提示词里再多加一条指令，做法是弄清哪些信息会跨运行留存，哪些会在运行结束时消失。
**主要来源:** [文章：“Effective Context Engineering for AI Agents”，Anthropic Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
**前置知识:** [第 12 课](0012-sub-agents-as-context-isolation.md)、[轨迹](../GLOSSARY.md)

## 热身

1. ▢ 轨迹记录的是什么？

<details markdown="1"><summary>检查</summary>

智能体一次运行的完整有序记录：发给模型的每条消息、模型发出的每个工具调用，以及运行框架追加回来的每个结果。

</details>

2. ▢ 拉起子智能体去处理一项有边界的工作时，子智能体能看到父智能体完整的对话记录吗？

<details markdown="1"><summary>检查</summary>

不能。子智能体得到的是自己全新的对话记录，历史为空。它可能收到父智能体作为初始提示词传给它的摘要或特定上下文，但不会继承父智能体的完整轨迹。

</details>

## 要点

**草稿区**其实只是对话记录的一部分，或者说是智能体在单次运行中写下并读回的笔记。在一项长任务中，智能体可能用草稿区来记录累计的总数、多步计划或中间发现，这样模型就不必每一轮都重新推导它们。草稿区是短暂的：当运行框架停止循环、运行结束后，草稿区只存在于轨迹里，别处没有。如果你一小时后启动一次新的智能体运行来继续这项工作，草稿区就没有了。

常见的混淆就出在这里。一个智能体在一次运行中保留了草稿区，“记住”了某件事。同一个智能体重新启动后，就不会记得它。模型也许会对草稿区的工具或文件沿用同一个名称，但内容已经没有了，因为那次运行已经不存在了。

**跨运行记忆**则有根本的不同。新的运行从空的对话记录开始，所以模型需要从上一次运行中知道的任何事情，都必须存放在任何单条轨迹之外的某个地方，并在下一次运行开始时被有意地加载回来。运行框架在循环开始之前，从持久存储（文件、数据库或检索系统）中读取，并把相关的事实放进初始提示词或上下文，让模型可以据此行动。

举一个具体的例子：一个智能体在评审一个大型 pull request 的代码。在一小时的运行中，它保留着一份草稿区，列出所有已经检查过的文件，这样当模型考虑一个新文件时，可以瞥一眼草稿区，避免重复分析已经做过的工作。草稿区是对话记录的一部分。运行结束时，评审完成，草稿区作为轨迹的一部分被归档。

再设想另一个场景：一个编程助手在数周内，跨许多次独立的会话，帮助同一位用户写代码。用户对某种代码风格、命名约定和库有强烈的偏好。如果助手在每次会话时都重新启动，它一开始并不知道这些偏好。助手需要跨运行记忆：运行框架在每次会话开始时读取的一份文件或笔记，上面写着“用户偏好 X，使用 Y，避免 Z”。这个事实不在任何单条轨迹里；它被持久地存储，并在运行开始时加载进来。

来自[文章：“Effective Context Engineering for AI Agents”，Anthropic Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)的关键洞察是：这是两种独立的机制。草稿区是智能体在运行期间操作的一个工具或产物。跨运行记忆则是位于智能体循环之外的数据层，由运行框架管理。

## 练习

1. ▢ 一个智能体在求解一道多步骤的数学题。运行期间，它把自己的演算笔记写进一个草稿区文件。结束时，它把最终答案追加到一个结果文件里。几天之后，你用另一道题再次启动同一个智能体。哪个还会在？

    - a) 草稿区笔记。
    - b) 结果文件。
    - c) 两者都在，因为它们都是文件。
    - d) 都不在，因为每次运行都会清空文件。

<details markdown="1"><summary>检查</summary>

**b)** 结果文件还会在，因为它是运行之外的持久存储。草稿区笔记虽然写进了文件，却只与旧的那次运行相关，并不会自动加载进新的对话记录。如果智能体在新的运行里需要那些旧笔记，运行框架就必须有意地读取它们，并把它们放进初始提示词。

</details>

2. ▢ 你在设计一个必须记住已处理过的文件名的智能体。你会使用草稿区还是跨运行记忆？

<details markdown="1"><summary>提示</summary>

想一想，这些信息是在单次运行中使用，还是在多次独立的运行之间使用。

</details>

<details markdown="1"><summary>检查</summary>

如果所有文件都在一次长时间的运行里处理完，草稿区就够了。智能体每次都检查草稿区，避免重复处理。如果工作被拆分到多次智能体运行中，比如每天重新启动，或者每个用户请求一次运行，那么你就需要跨运行记忆，让新的运行能看到之前做过什么。

</details>

3. ▢ 用全新的运行框架重新启动的智能体，看不到上一次运行里写进草稿区的笔记，根本原因是什么？

<details markdown="1"><summary>检查</summary>

因为草稿区是对话记录的一部分，而新的运行从空的对话记录开始。旧的轨迹被归档了，却没有加载进新的运行。要让草稿区的内容在新的运行里可见，运行框架就必须从存储中读取它，并把它插入初始提示词，这样一来，它就从草稿区变成了有意设计的跨运行记忆。

</details>

4. ▢ 你在构建一个帮助用户管理个人任务清单的智能体。智能体添加任务、完成任务，并按标签过滤。任务清单应该是仅限于一次运行的草稿区，还是在多次运行之间持久保存的跨运行记忆？为什么？

<details markdown="1"><summary>检查</summary>

跨运行记忆。任务清单需要在一次会话之后继续保留。如果用户明天启动智能体并说“给我看看我的任务”，智能体必须仍然能看到今天的清单。草稿区会在运行结束时消失，用户的数据就丢了。

</details>

## 实战练习

- [ ] 花两分钟梳理你自己的智能体代码。找出运行框架在哪里创建全新的对话记录，是空的还是只带初始提示词。写下你看到的内容。
- [ ] 查找你的智能体目前保存的任何“记忆”或“状态”。它是由运行框架在循环开始之前加载的，还是只在运行期间被引用？如果只在运行期间，它就是草稿区。如果是在启动时加载的，它就是跨运行记忆。
- [ ] 明天：找一个或写一个草稿区的用法，即智能体写下一条笔记，再读回来，然后运行结束。另外再找一个或设想一个跨运行的用法，即智能体需要上周运行中的某个事实来回答今天的问题。
