# 第 17 课：自我批评与推理模型带来的变化

**使命关联:** 要诊断出问题的智能体，你需要认清：什么时候该加入反思阶段（一个单独的循环，评估过去的失败并把教训带到后面），什么时候模型自身的内部推理已使这个循环变得多余。
**主要来源:** [论文：“Reflexion: Language Agents with Verbal Reinforcement Learning”，Shinn 等，2023](https://arxiv.org/abs/2303.11366)
**前置知识:** [第 16 课](0016-plan-then-execute-and-decomposition.md)

## 热身

1. ▢ 在先规划后执行的智能体中，如果某一步失败了，而运行框架不支持重新规划，会发生什么？

<details markdown="1"><summary>检查</summary>

运行框架没有办法调整。它要么盲目地沿着原计划继续（多半会再次失败），要么停止。智能体既无法从失败中学习，也无法转向另一种做法，因为计划是预先锁定的，没有任何机制可以更新它。

</details>

2. ▢ 显式的重新规划，相比从头重新运行智能体，有什么优势？

<details markdown="1"><summary>检查</summary>

重新规划让模型能在上下文中看到确切的失败并对它进行推理。如果只是重新运行智能体，它可能又产生同样的计划。有了重新规划，运行框架会把失败追加到对话记录里，并要求模型制定新的计划，这样模型就能看到哪里出了问题并做出调整。

</details>

## 要点

### Reflexion：加入反思循环

Reflexion 论文在智能体循环里引入了一个显式的反思阶段。一次尝试失败之后（智能体的答案错了、任务没有完成、测试失败），运行框架不会立刻重试。它会先针对哪里出了问题，生成一段自然语言的反思。这段反思被存储起来（通常放在文件或记忆缓冲区里），并包含在下一次尝试的上下文里。

这个循环是这样的：

1. 让智能体运行一个任务。
2. 检查任务是否成功（测试通过，或由人评估答案是否正确）。
3. 如果失败，生成一段反思：“我尝试了 X，但 X 失败了，因为 Y。”
4. 把反思存进持久记忆。
5. 再次运行智能体，这一次在上下文里包含已存储的反思。
6. 回到第 2 步。

这与简单的重试不同。简单的重试，是在相同的上下文下再次运行智能体。Reflexion 则是在上下文里带着反思再次运行智能体，所以第二次尝试可以从第一次尝试的失败中学习。

### 为什么反思不是免费的

Reflexion 要花额外的模型调用。如果第一次尝试失败了，你现在需要一次调用来生成反思，再需要另一次调用来运行第二次尝试。对于失败率低的任务，这笔开销不值得付出。对于需要多次尝试的任务，累积的成本很高。

反思还会消耗上下文预算。每一段反思都占用上下文窗口里的 token。如果你在多次尝试中积累了许多反思，最终就不得不修剪或总结它们。这是前面几课讲过的上下文管理问题的另一个版本。

只有当反思本身有真实的信息作为依据时，它才有意义：失败的测试、错误信息、人的评估。如果任务没有清晰的失败信号，反思就没有具体的东西可以回应，很可能只是在为之前的错误答案找理由。

### 具备延长内部推理的模型

近年来，一些前沿模型获得了在给出答案之前进行延长的内部推理的能力。这种推理在对话记录里不可见（它发生在模型的单个轮次之内，在输出返回之前），却让模型能够自我纠正、复核自己的工作，并在明显的错误出现在输出里之前就把它们抓住。

这改变了显式反思循环存在的理由，但并没有消除它。反思循环过去提供的一部分价值（抓住明显错误的中间步骤），现在发生在模型自己的推理之内，所以在上面再加一个反思循环，带来的边际收益比过去要小。

不过，显式反思仍然有一项内部推理不具备的优势：它能纳入只有在工具调用之后才存在的信息。如果某个工具调用返回“Permission denied”，或测试失败了，模型的内部推理在它最初的推理阶段不可能看到这个失败信号，因为那时工具还没有运行。显式的反思循环则可以观察到工具的实际结果，并把它纳入下一次尝试。

所以问题不是“反思还是内部推理”，而是“尽管有内部推理，外部反思额外的成本什么时候才物有所值？”

### 显式自我批评什么时候值回成本

在下面这些情况下使用外部反思：

- 任务有清晰的、可检查的失败信号（测试套件通过或失败、API 返回错误、人把答案评为错或对）。
- 在失败的启发下进行的第二次或第三次尝试，很可能在第一次失败的地方成功。
- 任务值得重试：价值足够高，使得额外的模型调用是合理的。

在下面这些情况下不要加入反思：

- 任务没有清晰的失败信号（例如“写一份摘要”，却没有测试或评分标准来检查正确性）。
- 失败不是模型的错（例如所需的 API 宕机了，那不是模型能修复的）。
- 第一次尝试已经极有可能成功，失败很少见。

### 设计反思的信号

反思的质量取决于它收到的信号。如果你告诉运行框架“这个任务失败了，因为用户这么说”，反思可能会生成“我尝试写一份摘要，但用户不喜欢”。这对下一次尝试来说太含糊了，无从着手。更好的失败信号会是“摘要缺少客户明确提出的需求”，或者“摘要超过了 100 字的限制”。

构建会反思的智能体时，要仔细设计失败检查。成功是什么样子？什么具体的证据能证明失败？反思要回应的，正是这些证据。

## 练习

1. ▢ 一个智能体写代码来解决一道 LeetCode 题目。测试套件运行代码，报告“所有测试通过”，或者打印出某个具体失败的测试用例。失败之后，运行框架生成一段反思，并在上下文里带着这段反思再次运行智能体。为什么这很适合 Reflexion？

<details markdown="1"><summary>检查</summary>

这里有清晰的失败信号：测试套件。反思可以写成“测试用例 [输入] 期望 [输出]，但我产生了 [错误的输出]。”这既具体又可操作。模型在下一次尝试中读到它，就可以针对失败的用例专门调试。代码生成本质上也是迭代的；预期会有多次尝试，而且值得付出这笔成本。

</details>

2. ▢ 一个智能体被要求为电商网站撰写产品文案。智能体写出文案并提交。没有测试套件，没有评分标准，也没有自动检查。一位人工营销经理读了之后说：“这不对，重来。”Reflexion 在这里有帮助吗？

<details markdown="1"><summary>提示</summary>

反思循环有什么反馈可以依据？它是否具体到足以让下一次尝试据此行动？

</details>

<details markdown="1"><summary>检查</summary>

Reflexion 帮助不大。“这不对”这个反馈太含糊了。反思会变成类似“营销经理不喜欢我的文案”。智能体的下一次尝试没有任何具体的改动可做。更好的办法是从经理那里得到具体的反馈（例如“写得更短一点，并加上价格对比”），并把它放进下一个提示词里，而不是依赖反思循环。

</details>

3. ▢ 具备延长内部推理的模型，现在可以在自己的推理阶段进行自我纠正。在这种情况下，下面哪一项仍然是显式外部反思循环的优势？

    - a) 外部反思总是比内部推理更快。
    - b) 外部反思能纳入只有在模型第一次尝试之后才存在的信息（比如工具错误或测试失败）。
    - c) 外部反思在上下文 token 上比内部推理更便宜。
    - d) 外部反思适用于所有模型，即使是没有内部推理能力的模型。

<details markdown="1"><summary>检查</summary>

**b)** 内部推理发生在任何工具运行之前，所以它无法观察到工具的实际结果或测试失败。显式的反思循环可以纳入这些信息，所以即使对具备内部推理的模型，它也有价值。a) 是错的，内部推理往往比多跑一个循环更快。c) 是错的，外部反思会消耗上下文 token（反思文本和下一次尝试都要占用空间）。d) 是对的，但不是关键洞察；问题问的是在有内部推理的情况下，反思还增加了什么。

</details>

4. ▢ 你在构建一个处理求职申请的智能体。运行框架有清晰的信号：由招聘经理批准或拒绝。你想用 Reflexion，在多次尝试中改进智能体的决策。每段反思应该捕捉什么，才对下一次尝试有用？

<details markdown="1"><summary>检查</summary>

反思应该捕捉被拒绝或被批准的具体原因（如果能拿到的话）。例如，“申请被拒绝，因为：缺少所需的认证。下一次尝试，在批准之前先检查是否具备所需的认证。”或者“申请被批准，因为：所需技能经验丰富，求职信的沟通也很好。”反思应该针对具体的申请，而不是泛泛的建议。这样才能给下一次尝试一些具体可行动的东西。如果招聘经理只给出是或否，没有说明原因，反思的可操作性就会差一些。

</details>

## 实战练习

- [ ] 找一个涉及迭代、并且有清晰通过或不通过信号的任务（例如解题、通过测试、满足评分标准）。实现一个会反思的智能体循环：尝试、检查失败、生成反思、带着上下文里的反思重试。运行五次，数一数智能体在有反思与没有反思时分别需要多少次尝试。记录差异。
- [ ] 在你的工作中找一个没有清晰失败信号的任务（例如写作、设计、创意工作）。描述你会如何加上一个信号（例如“对照评分标准”“请同行评审”“检查特定的标准”）。加上失败信号，会让会反思的智能体变得有用，还是这个任务更适合由人来把关？
- [ ] 明天：阅读一条 Reflexion 的轨迹（来自论文、博客文章，或你自己构建的东西）。找出其中的反思文本。如果模型具备内部推理，这段反思还会有用吗？为什么？
