# 第 19 课：协调成本

**使命关联:** 要在单个装备良好的智能体与多智能体系统之间做出选择，你需要知道编排者与工作者系统在 token、推理和碎片化上下文上要付出什么代价，以及如何判断第二个智能体是否带来了第一个智能体无法直接获得的东西。
**主要来源:** [文章：“Don't Build Multi-Agents”，Cognition](https://cognition.ai/blog/dont-build-multi-agents)
**前置知识:** [第 18 课](0018-orchestrator-and-worker.md)

## 热身

1. ▢ 回忆第 18 课：在编排者与工作者系统里，一个工作者能在另一个工作者运行期间，看到它完整的推理轨迹吗？

<details markdown="1"><summary>检查</summary>

不能。每个工作者都运行着自己的智能体循环，有自己隔离的对话记录。只有当编排者明确传递时，工作者才能看到彼此的发现，而且只是最终报告，而不是完整的推理。这种隔离既是一个优点（让上下文保持干净），也是一项代价（工作者无法共享任务进行中的洞察）。

</details>

2. ▢ 回忆第 18 课：扇出和交接有什么区别？

<details markdown="1"><summary>检查</summary>

扇出是并行地派出多个工作者去处理同一个问题的不同变体，同时探索不同的角度，以获得更广的覆盖和并行性。交接是顺序的：一个智能体完成它的任务，把干净的上下文传给专门负责下一阶段的第二个智能体。两者都是多智能体模式；扇出用的是时间，交接用的是专业化。

</details>

## 要点

### token 成本：多个智能体，成本高出许多倍

每一次智能体运行都有成本。编排者与工作者系统要把这笔成本付许多遍。

假设单个智能体用 10,000 个 token 解决一个问题：比如 20 轮，每轮 500 个 token。现在假设同一个问题被拆成三个独立的子任务，每个由一个工作者用 8,000 个 token 解决（略少一点，因为每个工作者的焦点更窄）。编排者本身用 2,000 个 token 来拆解任务并综合结果。

总成本：8,000 + 8,000 + 8,000 + 2,000 = 26,000 个 token。多智能体系统的成本是单个智能体的 2.6 倍，尽管每个工作者在自己那一部分上，比单个智能体单独处理时效率略高。工作者并行探索，所以实际耗时更快，但 token 成本被成倍放大了。

如果工作者运行得没有效率，或者编排者需要协调不止一次（例如，编排者意识到工作者漏掉了一个依赖，于是派出新的工作者，或者要求工作者按新的指令再运行一遍），这笔账会更糟。Cognition 的文章把这一点指为核心问题：并行带来的提速，值得为它付出几倍的 token 成本吗？

### 碎片化的上下文：工作者看不到彼此

单个智能体运行一项长任务时，会积累上下文：它知道自己试过什么、什么有效、什么无效，以及为什么。多智能体系统会把这份上下文碎片化。工作者 A 和 B 可能研究重叠的领域（例如都在试图理解某个约束），但工作者 A 看不到工作者 B 对这个约束的推理；它只看到最终的报告。

具体来说：工作者 A 在任务进行中意识到某个约束有一个微妙的含义。工作者 A 对它进行了推理，建立了直觉，然后汇报。编排者读了报告，把它传给工作者 B。工作者 B 现在知道了结论，却不知道得出结论的推理。工作者 B 无法在任务中途完善或质疑这段推理，因为它看不到工作者 A 的思考。工作者 B 要么接受报告并使用它（失去了完善的机会），要么忽略它并重新推导出同样的洞察（浪费 token）。

对于最佳答案要从多条推理线索之间的来回打磨中产生的任务，碎片化的上下文是一项实实在在的限制。轮次足够多的单个智能体，可以把它所有的推理放在一个地方，并在见解逐步发展时把它们整合起来。

### 相互冲突的结论：独立探索会导致分歧

当两个工作者独立地探索同一片领域时，它们可能得出不同的结论。这不一定是错的；它们也许确实发现了不同的（而且都有效的）解读。但这也可能意味着其中一个工作者犯了错，或者漏掉了另一个抓住的东西。

编排者看到两份报告，必须调和它们。如果冲突是语义上或事实上的，编排者就有麻烦了：它只有工作者的摘要，没有它们完整的推理，所以很难追溯分歧来自哪里。编排者可能会运行一个新的智能体（一个“裁判”或“综合者”子智能体）来调和，这会增加更多成本。

单个智能体的替代方案避免了这一点：单个智能体按顺序处理同一片领域，会把每个新发现整合进它正在形成的心智模型里，所以能在矛盾出现时发现它们，并在自己的推理循环里解决。

### 决策原则：什么时候多智能体更便宜？

Cognition 这篇主要来源认为，无论是在 token 上还是在推理质量上，大多数多智能体系统都不比一个工具更好的单个智能体更便宜。问题不是“并行是不是更快？”（是的），而是“并行是否买到了一些单个智能体花更少成本就无法拥有的东西？”

应用这个决策原则：

**多智能体合理的情况：**

- 子任务确实是独立的（没有共享的上下文，任务进行中不依赖彼此的结果）。
- 每个子任务都比原任务更简单（每个工作者解决的是确实更窄的问题，所以工作者效率提升的总和超过了重复劳动的成本）。
- 你需要并行带来的提速（节省的时间值得付出 token 倍数；你有一个用单个智能体多跑几轮也赶不上的实际时限）。
- 每个工作者的工具足够专门，以至于共用一套工具会因为无关的选项而拖慢每个工作者。

**拥有更多资源的单个智能体通常更胜一筹的情况：**

- 子任务共享上下文，或相互完善（单个智能体让它所有的推理保持连通；多智能体系统则必须重新推导或重新沟通）。
- 你在上下文预算上还有余地（给单个智能体更大的上下文窗口、更好的检索、更多的工具、更多的轮次）。
- 子任务相互依赖，或者需要多条思路之间的来回打磨。
- 相对于问题本身，协调开销（编排者的时间、沟通、调和相互冲突的结论）很高。

直白地说：一个工具更好、上下文更长、轮次更多的单个智能体，解决同一个问题，往往比上下文碎片化的多个智能体更便宜，推理质量也更好。并行带来的提速是真实的，但并不是免费的。

## 练习

1. ▢ 你在构建一个问答系统。方案 A：一个带有搜索、代码执行和文档工具的智能体。方案 B：一个编排者，并行派出三个工作者，每个带一个专门的工具（搜索工作者、代码工作者、文档工作者）。两者的目标都是回答复杂的用户问题。在什么情况下，方案 B 的 token 成本会比方案 A 更便宜？

<details markdown="1"><summary>检查</summary>

这是个陷阱。在大多数情况下，方案 B 在 token 上成本更高：你要为三次完整的智能体运行付费，外加编排者的开销，就像本课 26,000 对 10,000 token 的例子。只有在一种很窄的情况下，方案 B 才会更便宜：三个子任务真正相互独立，而且每个都比整个问题简单得多，以至于三个工作者加上编排者用的 token 总数比单个智能体还少（例如三个工作者各用 2,500 token，加上一个用 2,000 token 的编排者，共 9,500，对比单个智能体的 10,000）。这只会在单个智能体在合并后的问题上浪费很多轮次时发生。其他情况下，方案 A 更便宜。取舍在于实际耗时（方案 B 因为并行而更快）与 token（方案 A 更便宜）之间。你选择方案 B 是为了速度，而不是成本。

</details>

2. ▢ 在第 18 课的编排者与工作者系统（并行研究工作者）里，假设两个工作者最终研究了同一份资料，对它说了什么却得出不同的结论。编排者手里有两份报告。编排者缺少什么、而单个智能体本来会拥有？

<details markdown="1"><summary>提示</summary>

想想在对那份资料进行推理的那一刻，每个工作者的对话记录里有什么，与单个智能体的对话记录里有什么。

</details>

<details markdown="1"><summary>检查</summary>

编排者看到了两个结论，却没有得出每个结论的推理。单个智能体读了同一份资料，会把它关于这份资料的全部推理放在一份对话记录里：它如何解读文本、注意到了什么细微之处、考虑并否决了什么。单个智能体的推理是完全可追溯的。编排者只能问“你为什么得出那个结论？”，而工作者得重新解释，或者编排者得再派一个新的智能体去追查分歧。这就是碎片化的上下文。

</details>

3. ▢ 你在决定一个任务是用扇出（编排者与工作者）还是单个智能体。任务是：给定一个数据集和一个问题，清洗数据、探索数据、构建模型并报告发现。在扇出下，这些阶段（清洗、探索、建模、报告）会并行运行，还是顺序运行？

    - a) 并行，因为扇出会同时派出所有工作者。
    - b) 顺序，因为探索依赖于清洗，建模依赖于探索。
    - c) 并行，但可以拆分工作，让每个工作者独立完成所有阶段。
    - d) 取决于工作者能否访问同一个数据集。

<details markdown="1"><summary>检查</summary>

**b)** 这个任务不适合扇出，因为各阶段是顺序的：你无法很好地探索脏数据，不了解数据就无法建模，依此类推。每个阶段都依赖前一个阶段。扇出在有独立子任务的任务上最出彩（并行研究角度 A、角度 B、角度 C）。对于顺序的工作，交接（第 18 课）比扇出更合适，或者一个轮次足够多的单个智能体更简单。(a) 是错的：并行不会变魔术，依赖关系依然存在。(c) 是可能的，但违背了专业化的初衷；每个工作者都需要全部的工具和知识。(d) 是干扰项；数据访问在这里不是限制因素。

</details>

4. ▢ Cognition 的文章认为，一个检索更好或工具更强的单个智能体，在 token 上往往比编排者与工作者系统更便宜地解决问题。这一说法的核心理由是什么？

<details markdown="1"><summary>检查</summary>

单个智能体把它所有的推理放在一份对话记录里，所以它能在一个推理循环里整合发现、发现矛盾并完善结论。编排者与工作者系统要付出许多个智能体循环的 token 成本，还会把上下文割裂开，使工作者重新推导或重新沟通洞察。单个智能体因保持上下文统一、推理连通而带来的效率提升，往往超过多智能体系统并行带来的提速，尤其是当问题带有依赖关系，或受益于整合的推理时。给一个智能体更多的工具或更好的检索（两者都比运行多个智能体便宜），往往更胜一筹。

</details>

5. ▢ 你在构建一个调试失败程序的系统。你考虑扇出：派出三个工作者，各自并行尝试不同的调试策略，然后让编排者挑出最好的洞察。这个设计有哪项代价，是第 19 课讲到、而它没有算进去的？

<details markdown="1"><summary>检查</summary>

token 成本乘以三（每个工作者都是一次完整的智能体运行）、碎片化的上下文（没有哪个工作者能看到其他工作者的探索，所以它们可能把同一条死胡同重新走三遍，而不是互相学习），以及编排者必须调和关于 bug 是什么的、可能相互冲突的结论。一个按顺序尝试全部三种策略的单个智能体，会在推进的过程中逐步建立起关于这个 bug 的统一模型。三个工作者做不到这一点，除非编排者运行一个调和步骤（又一个智能体，更多成本）。扇出买到的是速度（三个工作者用最慢那个工作者的时间完成，而不是三者之和），但对于调试这种见解层层相叠的任务，代价很高。

</details>

## 实战练习

- [ ] 找一个你以前解决过的问题（调试、分析、规划、研究，什么都行）。在脑子里把它分别当作轮次很多的单个智能体和三个扇出的工作者来过一遍。并行会在哪里为你赢得实际耗时？碎片化的上下文会在哪里让你付出代价，并迫使你重新推导或做调和工作？
- [ ] 至少阅读一遍 Cognition 的文章“Don't Build Multi-Agents”。找到作者论证单个智能体加更好的工具胜过编排者与工作者的那一节。写下他们给出的一个具体例子，以及是什么让单个智能体更便宜。
- [ ] 明天：勾画一个你可能构建成智能体系统的任务。针对这个任务估算：单个智能体会用多少 token？扇出系统会花多少（假设三个工作者，每个的 token 成本比单个智能体对应那一份任务略少）？这个提速值得你付出这个 token 倍数吗？
