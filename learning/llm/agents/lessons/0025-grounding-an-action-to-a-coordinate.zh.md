# 第 25 课：把动作落到坐标上

**使命关联:** 要诊断出问题的、使用计算机的智能体，就需要把落点定位错误（坐标没点中）与工具误用或逻辑错误区分开来，这样才能修复真正的问题。
**主要来源:** [文档：“Computer use tool”，Claude Platform Docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)
**前置知识:** [第 24 课](0024-screenshots-as-observations.md)

## 热身

1. ▢ 在调用工具的智能体里，当模型想更新某个用户时，它向运行框架发送什么？运行框架又如何知道要更新的是哪个具体的用户？

<details markdown="1"><summary>检查</summary>

模型发送一个工具调用，带有类似 `user_id: "u_123"` 的参数，这是一个稳定、唯一的标识符。运行框架读取这个标识符，并按 ID 更新用户，没有任何歧义。

</details>

2. ▢ 在使用计算机的智能体里，当模型想点击它在截图上看到的某个按钮时，它向运行框架发送什么？运行框架又如何知道要点击哪个按钮？

<details markdown="1"><summary>检查</summary>

模型发送一个在某个像素坐标处点击的动作，比如 `click(x=450, y=200)`。运行框架读取这个坐标，并在屏幕上那个确切的位置点击。

</details>

## 要点

### 落点定位问题

落点定位是把模型的意图转换为实际屏幕坐标的那一步。当调用工具的智能体想更新一条记录时，它通过稳定的 ID、名称，或运行框架可以直接据以行动的唯一标识符来指明这条记录。这里没有歧义：运行框架要么找到这条记录，要么找不到。

当使用计算机的智能体想点击一个按钮时，它必须在当前的截图中，凭视觉找到那个按钮，估计它的像素坐标，并发出一个类似 `(x, y)` 的坐标元组。这在四个方面更难。

**第一，没有稳定的参照。** 如果窗口改变大小、页面滚动，或内容发生位移，一张截图里位于像素 450, 200 的按钮，就成了另一个按钮（或者根本没有按钮）。ID 在布局变化时依然存在；坐标则不会。调用工具的智能体会按名称去要一个按钮；使用计算机的智能体则按位置去要一个按钮，这很脆弱。

**第二，模型无法求助。** 在调用工具的智能体里，如果运行框架不理解某个参数，它会返回清晰的错误：“user_id u_999 not found”或“invalid format for date_field”。模型读到错误，并修正它的参数。在使用计算机的智能体里，点击错了坐标，只会点中错误的东西（或空白处）。模型得不到错误信息。它要到下一张截图才发现点击落在了错误的地方，即便如此，它还得通过视觉检查，推断出这次点击没有点中。

**第三，反馈循环很慢。** 调用工具的智能体犯错之后，会得到一条有类型的错误信息。使用计算机的智能体犯错之后，得再截一张完整的屏，发给模型，等模型解读新的图像并推理哪里出了问题，然后再试一次。每一次落点定位错误，都要花一次完整的模型往返才能发现并修复。

**第四，细微的环境变化会破坏本来可行的序列。** 按 ID 指明用户的工具调用，即使用户的姓名、邮箱或部门变了，依然有效。在坐标处的点击，只要按钮挪动哪怕几个像素就会失效。13 英寸的笔记本屏幕、27 英寸的显示器、浏览器缩放、字体渲染和 CSS 断点，都可能把同一个按钮移到不同的坐标。一条在某台机器上运行得完美的轨迹，换到另一台机器上可能悄无声息地失败。

### 是什么让落点定位变得脆弱

设想一个智能体在正常缩放的桌面浏览器上，成功点击了位于 (300, 150) 的搜索框。同一个网页在手机上查看，或者把浏览器缩放设为 125%，可能会把搜索框渲染在 (225, 112) 或 (375, 188)。这个坐标就不再正确了。点击可能落在空处，或者完全落在另一个元素上。

智能体的逻辑是合理的。模型做了一个合理的决定。动作类型（点击）也是对的。但坐标错了，因为环境变了。要求名为 `search` 的工具的、调用工具的智能体，就没有这个问题，因为工具名称是稳定的。

这就是为什么落点定位错误是由屏幕驱动的智能体所特有的一类失败。它们不会出现在调用工具的智能体里，因为调用工具的智能体是按名称而不是按位置来引用事物的。

### 部分缓解：感知结构的工具

一些浏览器或计算机使用工具试图通过提供折中的办法来降低落点定位的脆弱性：除了截图，工具还会返回页面元素的结构化信息：每个按钮、链接和表单字段的名称、角色、位置和边界框。

这样模型就可以说“点击标有‘Submit’的按钮”，或“点击邮箱那一行里的文本框”，由运行框架在点击时把这个具名的引用转换为坐标，而不是让模型从像素中估计坐标。这恢复了一些稳定性：如果按钮移动了，运行框架会自动计算新的坐标，而不需要模型重新估计。

这是一种取舍。你获得了可靠性，却失去了纯截图式动作所实现的一部分“适用于任何图形界面”的通用性。感知结构的工具对网页很管用，因为 HTML 元素有语义角色和稳定的 ID，但对桌面图形界面应用、游戏，或这个工具并未针对的冷门应用，可能就不管用了。纯截图式的动作没有这个限制，但更脆弱。

### 如何在轨迹中发现落点定位错误

阅读使用计算机的智能体的轨迹时，留意这些模式：

- 模型的意图说得通（它决定搜索某样东西、填写某个字段等等），但动作没有产生预期的结果。
- 连续的多次点击落在错误的地方。
- 同一个动作在一张截图上有效，在下一张上却失败。
- 坐标远离任何可见的元素。

这些是落点定位错误的标志。模型对该做什么的推理是正确的，只是坐标与屏幕不符。这有别于逻辑错误（模型决定做错误的事）或工具故障（工具崩溃了）。

## 练习

1. ▢ 一个智能体在坐标 (500, 250) 处点击来提交表单。点击之前的截图显示，提交按钮大致位于 (500, 250) 的中心。动作成功，表单提交了。下一轮，智能体试图在同样的坐标 (500, 250) 处，再次点击同一个提交按钮，但表单已经消失，屏幕上显示着一条加载信息。第二次点击落在空处。这是落点定位错误吗？

<details markdown="1"><summary>检查</summary>

不是。第一次点击的落点定位是正确的。第二次点击没点中，是因为屏幕变了，而不是因为模型估错了坐标。落点定位错误发生在坐标与模型此刻所看的截图上预期的目标不符时。页面内容变化之后，这个坐标就过时了，但这不是智能体决策中的落点定位错误；这是正确的行为：智能体尝试点击的，是一个已经不在那里的东西。

</details>

2. ▢ 一个智能体读取一张登录页面的截图，页面上有两个字段：顶部是用户名，下面是密码。智能体决定输入密码，估计密码字段大约在 (350, 180)，并发出动作 `type(x=350, y=180)`。运行框架在 (350, 180) 处点击，而那其实是用户名字段，于是密码被输入到了用户名字段里。智能体随后看到一张新的截图，显示用户名字段里现在填的是密码。这是落点定位错误、逻辑错误，还是两者皆是？

<details markdown="1"><summary>提示</summary>

分开问两个问题：(1) 模型对该做什么的决定合理吗？(2) 模型把坐标估对了吗？

</details>

<details markdown="1"><summary>检查</summary>

这是落点定位错误，而不是逻辑错误。模型的决定是正确的：它决定输入密码。但模型估错了密码字段的坐标。坐标 (350, 180) 是错的；密码字段实际上在屏幕更靠下的位置，也许在 (350, 240)。模型本来想点中正确的目标，却把动作的落点定位错了。

</details>

3. ▢ 一个使用计算机的智能体依次与两个不同的 Web 应用交互。在第一个应用里，它通过点击位于 (400, 300) 的字段，成功填写了表单。在第二个应用里，它试图点击屏幕上位置看起来相似的文本输入框，同样是 (400, 300)，但在第二个应用里，那个坐标是空白处，点击没有落在任何地方。第二次点击是落点定位错误吗？

    - a) 是，因为在第二个应用的截图上，这个坐标与预期的目标不符
    - b) 不是，因为模型对两个应用使用了相同的推理
    - c) 不是，因为这个坐标第一次是有效的，所以第二个应用一定有 UI 的 bug
    - d) 不是，因为落点定位错误只有在模型故意去点错东西时才会发生

<details markdown="1"><summary>检查</summary>

**a)** 这次点击的落点定位是错的：在第二个应用的当前截图上，这个坐标与预期的目标不符。同一个坐标在另一个应用上有效，这一点无关紧要；落点定位关心的是意图与模型此刻面前屏幕上的坐标之间是否吻合。**b)** 是错的，因为一次点击是否落点正确，不取决于模型的推理，只取决于坐标是否落在预期的目标上。**c)** 是错的，因为一个坐标曾经有效一次，并不能说明它在另一个屏幕上是否正确；是模型假定了它不该假定的稳定性。**d)** 是错的，因为落点定位错误是失误，而不是有意的选择。

</details>

4. ▢ 你在阅读一条智能体未能完成任务的轨迹。在第七轮，智能体点击了 (1200, 50)，也就是屏幕的右上角。那里看不到任何东西，点击没有任何效果。模型随后说它没有找到想找的按钮。下一轮，智能体点击了 (150, 50)，也就是左上角，找到了这个按钮。对第七轮出了什么问题，提出一个假设。

<details markdown="1"><summary>检查</summary>

智能体很可能判断错了按钮的位置，把点击的落点定位得太靠右了。按钮实际上在屏幕的左侧，但模型估计它在右侧。这是典型的落点定位错误：模型的意图（找到并点击按钮）是对的，坐标却是错的。智能体在下一轮自己纠正了，可能是重新读了截图，或重新考虑了它的估计。

</details>

## 实战练习

- [ ] 在正常缩放下，给一个网页截一张屏。挑一个按钮，写下你估计的它的像素坐标。现在把浏览器放大 25%，再截一张新的屏。用浏览器的开发者工具（检查元素并查看它的边界框），查出同一个按钮在放大后的截图上的坐标。写下新的坐标。你在第一张截图上的估计与实际坐标相差多远？缩放是怎样改变位置的？

- [ ] 观看或阅读一条使用计算机的智能体的轨迹（来自博客、工具文档或示例）。对连续的三个动作，把智能体想做什么（来自上下文或提示词），与它发出的坐标及随后的截图相对照。落点定位与意图吻合吗？如果不吻合，是什么改变了坐标？

- [ ] 明天：设计一个简单的 Web 表单（在脑子里或用代码都行），你认为使用计算机的智能体很难把它的落点定位正确。表单的哪些特性使落点定位变得脆弱？然后设计同一个表单的第二个版本，让它更容易定位，并解释你改了什么。
