# 第 21 课：数据量与教师成本

**使命关联:** 本使命要求你选择数据量，并把教师自身的成本计入预算，这需要一个能在信封背面算出来的公式，以及对你付了哪些成本、没付哪些成本的清晰认识。
**主要来源:** [论文：“Distillation Scaling Laws”，Busbridge 等，2025](https://arxiv.org/abs/2502.08606)，第 5 节和公式 9
**前置知识:** [第 20 课](0020-choosing-student-size.md)、[教师模型](../GLOSSARY.md)、[序列级蒸馏](../GLOSSARY.md)、[合成数据](../GLOSSARY.md)

## 热身

1. ▢ 第 20 课列出了蒸馏比监督学习更有效率的两个条件。把它们都陈述出来。

<details markdown="1"><summary>检查</summary>

学生的总算力或 token 数，不得超过一个取决于学生规模的阈值，并且必须已经存在一个教师，或者教师在单次蒸馏之外还有用途。两条中有任何一条不满足，论文的结果就偏向直接训练学生。

</details>

2. ▢ 第 8 课在教师解码出的输出上训练学生，第 9 课把它与匹配分布做了比较。二者之中，哪个需要教师的 logit，哪个只需要它的文本？

<details markdown="1"><summary>检查</summary>

[token 级](../GLOSSARY.md)（logit）蒸馏需要教师在每个位置上的分布。[序列级蒸馏](../GLOSSARY.md)只需要教师解码出的文本，这就是为什么它能通过只返回文本的 API 工作。两者把教师的成本放在不同的地方，本课就给这些成本标价。

</details>

3. ▢ 第 12 课说，数量弥补不了糟糕的样本。如果你把一份生成的数据集翻倍而不过滤它，你预期其中糟糕样本所占的比例会怎样？

<details markdown="1"><summary>检查</summary>

大致不变。把一个缺陷率固定的集合翻倍，缺陷和好样本一起翻倍。只有在第 12 课的过滤把质量定下来之后，更多的数据才有帮助，这就是本课计算的是通过过滤后留下的 token 的原因。

</details>

## 要点

### 两种成本，两个公式

稠密 Transformer 的训练成本，通常近似为每个参数每个 token 6 FLOPs：前向传播约 2，反向传播约 4。单独一次前向传播约为每个参数每个 token 2。这些都是近似。它们忽略了随上下文长度增长的注意力项，并且把所有参数同等看待。

论文自己也这么说。它把监督成本写成约 6ND，把 2N 的前向近似当作通常的简写，然后又拒绝在它自己的结果里使用它，理由有二：使用非嵌入参数会带来偏差，而且对上下文很长的小模型，注意力的贡献很显著（第 5 节，公式 9 下方）。它转而推导出一个修正后的每 token 成本。在数量级层面做规划时，这个简写就够了。对于你要为之辩护的数字，要把它说成一个近似，并说明你略去了什么。

它的蒸馏成本（公式 9）是学生的训练，加上教师的前向传播，其中每一项只在适用于你时才计费。用简写表示：

```text
student training   ≈ 6 × N_student × D
teacher inference  ≈ 2 × N_teacher × D     (forward only, over the same D tokens)
```

这里 N 是参数量，D 是学生训练所用的 token 数。教师这一项用同样的 D，因为 logit 蒸馏要让教师在学生看到的每个 token 上运行。把一个除以另一个，得到一个值得记住的比值：

```text
teacher cost / student cost  ≈  N_teacher / (3 × N_student)
```

一个规模是学生三倍的教师，运行成本大约等于训练学生的成本。任何更大的教师，成本都超过你所构建的学生。

### 算例：用教师给 token 打分

一个 1B 的学生在 100B 个 token 上训练，logit 来自给这同样的 token 打分的教师。

| 量 | 计算 | FLOPs |
|---|---|---|
| 学生训练 | 6 × 1e9 × 1e11 | 6.0e20 |
| 7B 教师打分 | 2 × 7e9 × 1e11 | 1.4e21 |
| 70B 教师打分 | 2 × 70e9 × 1e11 | 1.4e22 |

7B 教师的成本约为学生自己训练的 2.3 倍，70B 教师约为 23 倍。同一个学生在同样 token 上的监督基线，成本只有那 6.0e20。70B 的运行，是同一个学生以大约 24 倍的算力训练，所以要让它值得，学生的损失必须比相同算力下的监督学生低得多，而第 20 课的阈值说明了这种情况有多常见。

### 把教师的成本分摊到多个学生

如果教师对数据集打一次分，并存储它的 logit，几个学生就可以从同一次打分训练。用四个 1B 的学生，在这 100B 个 token 上，配 7B 的教师：一个学生的成本是 1.4e21 + 6.0e20 = 2.0e21，四个是 1.4e21 + 4 × 6.0e20 = 3.8e21，每个是 9.5e20。这就是论文的第三种设置，教师的成本分摊到它所服务的各个学生上（它的表 2）。它略去了存储 logit 的成本，那是第 7 课引入的账单，而论文把它另外处理。

### 算例：用生成的文本代替 logit

对序列级蒸馏，教师的计费是生成，不是打分。按前向传播的近似，生成 G 个 token 的成本约为 2 × N_teacher × G FLOPs，然后学生在这 G 个 token 上，每个轮次都训练一遍。这是对论文核算方式的延伸，不是出自论文，因为论文研究的是 logit。

一个 70B 的教师生成 1B 个 token：2 × 70e9 × 1e9 = 1.4e20。一个 3B 的学生在它们上训练两个轮次：6 × 3e9 × 1e9 × 2 = 3.6e19。教师的生成约为学生训练的 3.9 倍，而且生成出来的数据集可以重复使用，所以第二个学生不需要再向教师付费。

关于把 FLOPs 当作成本来读，有一点提醒。一次生成一个 token，会让 GPU 远远达不到满负荷利用，所以生成的实际耗时和花费，远高于 FLOPs 所暗示的。这是关于解码的一般常识，不是这里某个来源的结果，所以在报出预算之前，先在你的硬件上度量每秒生成多少 token。

### 论文怎么说钱花在哪里

当教师预训练也是账单的一部分时，论文的表 3 概括了最佳分配随规模如何变化：

| 学生规模 | 算力 | 最优分配 |
|---|---|---|
| 小（最大约 3B） | 小（最大约 1e21 FLOPs） | 主要是教师预训练 |
| 小（最大约 3B） | 大（约 1e25 FLOPs 及以上） | 在学生训练与教师推理之间平均分配，教师预训练要少得多 |
| 大（约 10B 及以上） | 小 | 主要是标准的学生训练 |
| 大（约 10B 及以上） | 大 | 在学生训练、教师推理和教师预训练之间平均分配 |

请把这些读作论文的定律在教师预训练计费的场景下的最优值。它们不是针对你已有的开源教师的配方，那种情形里预训练这一项为零。

### 多少数据才够

论文给出的诚实答案是，更多的 token 既不是免费的，也不是无限的。教师固定时，随着 token 预算增大，蒸馏相对监督学习的优势会缩小，最终监督学习追平甚至超过它（第 5.1 节）。所以“够了”就是多出来的一个 token 更适合花在学生自己信号上的那个点，而这个点随学生规模升高。

Minitron 是一个有用的对照。在 Muralidharan 等人的表 2 里，Minitron 8B 在 94B 个 token 上训练，而 Nemotron-3 8B 是 3.8T，约少了 40 倍。这个比较有两点需要注意。Minitron 的学生，从剪枝之后教师的权重开始，而论文里的学生是从零开始的。而且 40 倍这个数字，比较的是剪枝加蒸馏的模型与从零训练的模型，而不是与同一个学生的监督运行相比。所以它显示的是，好的初始化可能只需要多么少的数据。它没有显示从零开始的学生需要多少数据。

他们在模型家族层面的节省，同样是一种核算上的选择。他们报告，15B、8B 和 4B 这一家族的算力降低了 1.8 倍（第 4.1 节），算法是 (4.4e17 + 2.5e17 / 40 + 1.2e17 / 40) 对 4.4e17 + 2.5e17 + 1.2e17，单位是每个训练步骤的 FLOPs。按它的写法，这个和计入的是每个模型自己的训练步数。描述这个计算的句子里，没有为较小模型重新训练期间运行 15B 教师增加一项。那正是本课说要计入的那一项。

## 练习

1. ▢ 计算：一个 1B 的学生在 50B 个 token 上训练，用 8B 教师的存储 logit 打分一遍。给出学生的训练 FLOPs、教师的打分 FLOPs，以及后者与前者之比。

<details markdown="1"><summary>提示</summary>

学生用 6 × N × D，教师用 2 × N × D，两者用同样的 D。这个比值也等于 N_teacher 除以三倍的 N_student。

</details>

<details markdown="1"><summary>检查</summary>

学生：6 × 1e9 × 5e10 = 3.0e20。教师：2 × 8e9 × 5e10 = 8.0e20。比值：约 2.7，与 8 / (3 × 1) = 2.67 相符。两者都是由 6N 和 2N 近似得到的数量级数字。它们略去了注意力，以及存储或搬运 logit 的成本。

</details>

2. ▢ 一个 70B 的教师生成 1B 个 token 的答案，一个 3B 的学生在它们上训练两个轮次。二者之中哪个花的 FLOPs 更多？多多少倍？

<details markdown="1"><summary>提示</summary>

生成是每个 token 一次前向传播，成本为 2 × N_teacher。训练是每个 token 每个轮次 6 × N_student。

</details>

<details markdown="1"><summary>检查</summary>

生成：2 × 70e9 × 1e9 = 1.4e20。训练：6 × 3e9 × 1e9 × 2 = 3.6e19。教师的生成约为学生训练的 3.9 倍。增加轮次只会抬高学生这一边，所以第三个轮次会让两者几乎相等。生成的文本还可以给另一个学生重复使用，不需要额外的教师成本。

</details>

3. ▢ 四个 1B 的学生，共用一次 7B 教师对 100B 个 token 的打分。每个学生平均多少 FLOPs？为什么它低于单个学生的情形？

<details markdown="1"><summary>检查</summary>

总计：1.4e21 + 4 × 6.0e20 = 3.8e21，所以每个学生 9.5e20，而单独一个学生是 2.0e21。教师的那一遍只付一次，由四个学生分摊。这忽略了保存 logit 的存储和带宽成本，对每个 token 上的完整词表分布来说，这可能很大。

</details>

4. ▢ 关于 Minitron 的 94B token 这个数字，下面哪项陈述是正确的？

    - a) 它说明，从 15B 教师蒸馏时，从零开始的学生大约需要 94B 个 token。
    - b) 它说明，剪枝后的学生用比从零训练少得多的 token 就能恢复。
    - c) 它说明，蒸馏所需的数据，比对该学生的监督训练少约四十倍。
    - d) 它说明，15B 教师的推理成本相对学生的训练可以忽略不计。

<details markdown="1"><summary>检查</summary>

b)。这个 8B 学生是从 15B 模型剪枝得到的，所以它从教师的权重开始。a) 和 c) 把剪枝得到的初始化，当成了从零开始的蒸馏。40 倍这个数字，比较的是 Nemotron-3 8B，那是另一个从零训练的模型。d) 并没有被显示：按它的写法，家族成本的计算不包含教师前向传播这一项，所以它对那项成本两边都没说。

</details>

5. ▢ 第 4 阶段穿插题：你计划用一个 API 托管的教师生成 20B 个 token 的指令数据，并蒸馏一个 3B 的学生。说出在你下定决心之前，FLOPs 公式没有告诉你的两件事，一件关乎成本，一件来自第 13 课。

<details markdown="1"><summary>检查</summary>

关于成本：生成远不受 FLOPs 约束，所以真正的数字是 API 价格，或者你硬件上的实际耗时，而且是过滤后的产出，不是原始的 20B，决定了你要训练多少 token。来自第 13 课的：服务商的条款是否允许用它的输出训练模型，这是任何算力估算都回答不了的。

</details>
