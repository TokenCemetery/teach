# 评测术语表

用于证明模型的改动是否有效，并论证某个数字确实反映了这种改动的规范术语。

## 术语

**标注指南（Annotation guideline）**:
发给每位人工评分员、在他们开始之前就要读的书面文件，其中定义每个评分类别，附有具体的边界示例以及这些示例是如何裁定的。评分员之间一致性低，往往说明缺少标注指南或指南含糊不清，而不是评分员本身不可靠。
_避免使用_: 评分细则（rating rubric，其他地方交替使用这个词；本工作区统一使用“标注指南”）

**引用正确性（Citation correctness）**:
为某个论断所引用的那段具体文字，是否真的支持这个论断。这是比忠实性更严格的逐条引用检查。一个论断可以是忠实的（在检索到的内容中某处有依据），却仍被归到错误的引用上，或者根本没有归到任何引用上。
_避免使用_: 忠实性（faithfulness，相关但独立的检查：忠实性问的是论断是否有检索到的上下文支持，引用正确性问的是它具体引用的来源是否真的支持它）

**科恩 kappa（Cohen's kappa）**:
在扣除仅凭偶然就会出现的一致性之后，衡量两位评分员一致程度的统计量：`κ = (p_o − p_e) / (1 − p_e)`。kappa 为 0 表示不比偶然好，kappa 也可能为负。已知当某个评分类别比其他类别少见得多时，它会低估一致性。
_避免使用_: 百分比一致率（percent agreement，未经校正的原始数字；kappa 专指经过偶然校正的版本，两者讲出的可能是不同的故事）

**数据污染（Data contamination）**:
评测数据或它的近似改写，进入了模型的训练数据（通常是预训练，因为基准被抓取进了网页爬取数据），或者模型被反复针对同一个评测集调优，直到它不再度量底层的能力。
_避免使用_: 泄漏（leakage）、作弊（cheating）

**漂移（Drift）**:
特征与结果之间的现实关系随时间变化，使得基于较早数据构建的模型或评测，逐渐不再符合当前的现实。它专指留出数据与较新（“次日”）数据之间出现大幅差距时所表明的情形；同一输入上离线结果与线上结果之间的差距是另一种问题，是工程错误，不是漂移。
_避免使用_: 训练与服务偏差（training-serving skew，更宽泛的术语，涵盖任何训练与服务之间的差异；漂移专指基于时间的、模型之下的现实世界发生了变化的情形）

**忠实性（接地性）（Faithfulness (groundedness)）**:
生成的答案中的每个论断，是否真的有它所应依据的检索上下文支持，而不是凭空编造、与之矛盾，或者夹带了没有依据的细节。这是论断层面的检查：一个大体忠实的答案，仍可能藏着一个没有依据的论断。
_避免使用_: 引用正确性（citation correctness，更严格、独立的检查：问的是某个论断引用的那一段具体文字，是否就是真正支持它的那一段，与论断本身有没有依据无关）

**护栏指标（Guardrail metric）**:
实验或生产系统并不试图优化、而专门跟踪的指标，用来发现在另一个指标（OEC）被改善的同时，某项改动悄悄损害了它。只报告 OEC 的提升，而不同时检查护栏指标，可能掩盖真实的退步。
_避免使用_: OEC（护栏指标明确不是优化的对象；把二者混为一谈，就失去了分别跟踪它们的意义）

**留出数据（Held-out data）**:
被评判的模型在训练或微调期间从未见过的评测样本，或这些样本的近似改写。只有分数背后的数据是留出的，分数才有参考价值。
_避免使用_: 测试集（test set，容易与训练流程中的数据划分混淆）、未见数据（unseen data）

**OEC（总体评估标准，Overall Evaluation Criterion）**:
实验真正想要推动的那个具体指标，或由少数几个指标加权组成的组合。一个好的 OEC 候选既要可移动（足够灵敏，在可行的实验中能产生变化），又要与真正重要的结果有因果联系，而不只是相关。
_避免使用_: 任何容易推动、却与真实结果没有因果联系的指标（Kohavi 自己的例子：“浏览的照片数”很容易推动，但对收入几乎没有因果影响）

**过度拒答（Over-refusal）**:
模型拒绝了一个实际上安全的提示词，通常是因为它在措辞上像一个不安全的提示词，或者涉及听起来敏感的话题但并无危害。这是与越狱真正不同的失败模式，而只含不安全提示词的红队评测无法检测到它。
_避免使用_: 误拒（false refusal，一些来源中交替使用；本工作区统一使用“过度拒答”）

**红队测试（Red-teaming）**:
有意构造旨在让模型产出不安全输出的输入，无论是由人工测试员还是自动生成攻击的方法完成，然后针对给定的模型及其防御，度量这些输入成功的频率（越狱）。
_避免使用_: 只报告攻击成功率并称之为“安全评测”；它对过度拒答一无所知，而过度拒答是另一种失败模式，需要自己的测试集

**饱和（Saturation）**:
基准达到了天花板，模型在上面得分近乎满分，在实际使用中却仍会在同类任务上失败，因为这个基准不再度量底层的能力，而是开始度量对基准本身的熟悉程度。
_避免使用_: 数据污染（data contamination，相关但不同的成因；饱和也可能源于长期针对某个基准的大量正当调优，而不只是基准的题目泄漏进了训练数据）

**选择性披露（Selective disclosure）**:
用基准或竞技场测试多个未发布的私有模型变体，只公开报告得分最高的那一个。这会把排行榜变成优化目标（古德哈特定律），而不是中立的度量，并使排行榜报告的分数与实际发布的模型版本之间出现差距。
_避免使用_: 数据污染（data contamination，另一种操纵手段；选择性披露是一种报告做法，不是评测数据泄漏进了训练）

**尾部延迟（Tail latency）**:
最慢的那部分请求（通常报告为 p95 或 p99），与平均值相对。平均延迟不变，可能掩盖了明显变差的尾部；而在大规模下，一个请求如果扇出到许多后端调用，就要等它们全部完成才能结束，于是真正决定实际响应时间的是尾部。
_避免使用_: 平均延迟（average latency，一个聚合值，在真正主导用户体验的尾部明显变差时，它仍可能保持不变）

**任务成功率（Task success）**:
把智能体轨迹的实际最终状态与标注的目标状态作比较，只要某个动作序列达到了正确的结果就算数，而不是只认某一条预先定好的参考序列。比步骤准确率更忠实，因为步骤准确率只能给它拿到的那一条轨迹记分。
_避免使用_: 步骤准确率（step accuracy，更窄也更脆弱的度量：把每个动作与参考轨迹逐一匹配，会错误地惩罚另一条同样有效、通向同一正确结果的路径）

**训练与服务偏差（Training-serving skew）**:
模型的离线（训练或留出）表现与线上生产表现之间的任何差异。Google 自己的指导意见把它拆成成因不同的几种比较；同一输入上，离线分数与线上结果之间的差异，特指工程错误，而不是漂移或建模问题。
_避免使用_: 漂移（drift，更窄的、基于时间的情形：训练之后现实世界发生了变化；并非每一种离线与线上的差异都是漂移）

**轨迹（Trajectory）**:
智能体处理一项任务时产生的完整序列，包括工具调用、中间决策和各个轮次，与逐条响应的评测所评分的那个单一输出相对。逐条响应的指标在这里无从着手，这就是智能体评测需要自己的指标的原因。
_避免使用_: 响应（response，过于狭窄；轨迹是整个多步骤、常常多轮次的过程，而不是其中的任何单个输出）
