# 学习：评测

能够搭建一套评测，抓住凭感觉检查会漏掉的退步，并用它对模型的改动（微调、提示词改动、RAG 改动）做出上线与否的判断，而且这个判断能用数字而不是感觉来辩护。

**最新课程：** [19. 评审评测报告](lessons/0019-reviewing-an-eval-report.md)

## 成功的标准

- 针对给定的模型改动，设计一个留出的评测集，它能抵御数据污染，并能抓住随手翻看会漏掉的退步。
- 用这套评测对改动是否上线做出判断并为之辩护，指出所依据的数字，以及这个数字为什么可信。
- 针对给定的情形，比较 LLM-as-judge 与针对具体任务的指标，并根据各自的优劣来选择，而不是默认选其一。
- 评审别人的评测报告或评测运行框架，具体指出是什么让它的数字不可信（没有留出的评测集、没有校准的裁判、没有方差估计的单次运行、用排行榜名次代替针对具体任务的判断），而不是只说它感觉单薄。

## 约束

- 不限定领域：同样适用于评测微调、提示词改动和 RAG 改动，因为这三者适用的是同一套评测纪律。
- 不要求固定的技术栈，也不假定有先前的经验。

## 范围之外

- 在一个微调系列之内讲授的评判变体、留出数据的设计、指标和回归测试集：见 [`llm/finetuning`](../../llm/finetuning/)（第 0020 至 0024 课），它们专属于微调。本工作区把评测本身作为主题，只链接回去，不再重述。
- 对模型做量化，并评判量化付出了什么代价：见 [`llm/quantization`](../../llm/quantization/)。那个系列用评测来度量量化损失，而本系列讲的是评测如何构建。
- 编写并给被测的提示词做版本管理：见 [`llm/prompting`](../../llm/prompting/)。那个系列用评测来度量提示词的改动，而本系列讲的是评测如何构建。
- 蒸馏出较小的模型，并对照其教师模型度量它损失了什么：见 [`llm/distillation`](../../llm/distillation/)。那个系列用评测来比较学生模型与教师模型，而本系列讲的是评测如何构建。

## 学习路线

共十三个阶段，从一套可信的评测，到一个经过辩护的上线与否判断，这个判断要把人工、安全、智能体、RAG、生产环境、成本以及公开排行榜的诱惑都考虑在内，最后以判断力收尾：评审别人的评测，并作为共享的基础设施诚实地维护一套评测。一个阶段包含若干课程，边界并不严格；一个阶段是否完成，取决于能力，而不是课程数量。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. 留出数据与数据污染 | 0001 至 0002 | 训练集与测试集划分的纪律、污染的检测及其来源 | 能设计出抵御数据污染的留出集 |
| 2. 针对具体任务的指标 | 0003 至 0004 | 精确匹配、F1、BLEU/ROUGE、代码执行指标、按任务选择 | 能为给定的任务选出指标并论证 |
| 3. LLM-as-judge | 0005 至 0006 | 裁判提示词的设计、校准、位置偏差与冗长偏差、与人类的一致性 | 能搭建裁判提示词，并说出它的失败模式 |
| 4. 搭建评测运行框架 | 0007 至 0008 | 评测框架、可复现的运行、把设计变成数字 | 有一套能产出可信数字的、可运行的评测运行框架 |
| 5. 上线与否的判断 | 0009 至 0010 | 统计显著性与噪声、退步阈值、传达决定 | 能用数字为上线或不上线的判断辩护，并说明这个数字为什么可信 |
| 6. 作为一种方法的人工评测 | 0011 | 标注指南、抽样复核、科恩 kappa，以及一个人工标签的代价 | 能精确度量评分员之间的一致性，并诊断数值偏低的原因 |
| 7. 安全与红队评测 | 0012 | 红队测试、越狱与攻击成功率、过度拒答与 XSTest | 能同时报告拒答率和过度拒答指标，并解释为什么单靠任何一个都不算安全评测 |
| 8. 评测智能体与工具使用 | 0013 | 轨迹、任务成功率与步骤准确率、`pass^k` 可靠性 | 能解释为什么任务成功率胜过步骤匹配，以及为什么单次试验的成功率并不等于重复试验的可靠性 |
| 9. 针对 RAG 的评测 | 0014 | 忠实性/接地性、引用正确性、区分检索失败与生成失败 | 能分别独立地度量忠实性和引用正确性，并诊断 RAG 流水线究竟是哪一侧失败了 |
| 10. 在线评测 | 0015 至 0016 | A/B 测试、OEC 与护栏指标、生产遥测、漂移、训练与服务偏差 | 能选出带护栏指标的、经得起辩护的 OEC，并把离线与线上的差距正确地归因于方差、漂移或工程错误 |
| 11. 作为评测维度的成本与延迟 | 0017 | 尾部延迟与平均延迟、每请求/每 token 的成本、把二者纳入上线与否的判断 | 能为一个同时权衡质量、尾部延迟和成本、而不是只看质量的上线与否判断辩护 |
| 12. 公开基准 | 0018 | 静态基准的污染/饱和、竞技场式的选择性披露、排行榜规模上的风格偏差 | 能解释为什么排行榜名次通不过 OEC 的检验，也不能代替针对具体任务的上线与否判断 |
| 13. 判断力 | 0019 | 评审评测报告、依据一手资料裁定有争议的说法、维护他人所依赖的评测套件 | 值得信任去评审别人的评测，并为它的数字辩护或指出是什么让它不可信，也能把评测套件作为共享的基础设施维护，而不破坏别人的关卡 |

请按顺序学习。

| [0005](lessons/0005-judge-prompt-design-and-calibration.md) | 裁判提示词的设计与校准 | 如何写出评分一致的裁判提示词，以及在信任一个裁判之前，它得到校准意味着什么 |
| [0006](lessons/0006-judge-bias-and-human-agreement.md) | 裁判偏差与人类一致性 | LLM-as-judge 中的位置偏差和冗长偏差，以及如何度量裁判与人类评分员的一致程度 |
| [0007](lessons/0007-eval-frameworks-and-harness.md) | 评测框架与搭建评测运行框架 | 每个评测运行框架都有的四个阶段，以及在自建评测即代码和复用标准化基准运行框架之间做选择 |
| [0008](lessons/0008-reproducible-runs.md) | 可复现的运行 | 为什么同一套评测在不同次运行中会得出不同的数字，以及一个可信的结果除了分数还必须记录什么 |
| [0009](lessons/0009-statistical-significance-vs-noise.md) | 统计显著性与噪声 | 为什么分数的差异必须对照偶然就可能产生它的噪声来衡量，以及为什么成对比较胜过把两个分数当作相互独立的 |
| [0010](lessons/0010-defending-the-go-no-go-call.md) | 为上线与否的决定辩护 | 如何诚实地设定退步阈值，以及一份完整的上线与否辩护必须引用的全部内容 |
| [0011](lessons/0011-human-evaluation-as-a-method.md) | 作为一种方法的人工评测 | 第 6 课拿裁判与人类评分员作比较，却从没教过人工评分究竟是怎样产生的，而它所依赖的原始一致率，要先经过对偶然的校正才有意义 |
| [0012](lessons/0012-safety-and-red-teaming-evaluation.md) | 安全与红队评测 | 只度量模型拒绝真正不安全提示词的频率的安全评测，度量的只是权衡的一半，因为能提高这个数字的同一种调优，同样很容易提高模型拒绝那些本来就不危险的提示词的频率 |
| [0013](lessons/0013-evaluating-agents-and-tool-use.md) | 评测智能体与工具使用 | 智能体的任务有许多条通向同一个正确结果的有效路径，所以拿一条参考动作序列给它评分，是在轨迹的尺度上重复了精确匹配的错误，而即便只看单次试验的成功率，也掩盖了同一个智能体在第二次尝试同一任务时有多常失败 |
| [0014](lessons/0014-rag-specific-evaluation.md) | 针对 RAG 的评测 | llm/rag 划清了检索失败与生成失败的界线，却没有定义生成一侧的检查，而这个检查需要两个独立的数字，而不是一个，因为忠实的论断和引用正确的论断，可能彼此独立地失败 |
| [0015](lessons/0015-ab-tests-and-guardrail-metrics.md) | A/B 测试与护栏指标 | 到目前为止的每个阶段都是离线的，但要上线给真实用户，需要它自己的决策指标，而只看这个指标，恰恰与前面各阶段已经警告过的、不要孤立地信任的单一安全数字一样危险 |
| [0016](lessons/0016-production-telemetry-and-drift.md) | 生产遥测与漂移 | 离线数字与线上数字不一致，并不是一个问题，而是三个不同的问题，把工程缺陷当成漂移，或把漂移当成工程缺陷，会让修复工作完全交给了错误的团队 |
| [0017](lessons/0017-cost-and-latency-as-eval-dimensions.md) | 作为评测维度的成本与延迟 | 脱离服务成本来度量的质量提升，只是上线与否判断的一半，而平均延迟这个数字，恰恰掩盖了决定用户是否真的觉得系统很快的那条尾部 |
| [0018](lessons/0018-public-benchmarks.md) | 公开基准 | 排行榜上的位置是一个可以被移动的指标，由不是你的人为不是你的用户优化，并由一套自带已有文献记载的操纵手段的流程打分，这使它恰恰成了第 15 课警告过的、不该信任为上线与否信号的那类指标 |
| [0019](lessons/0019-reviewing-an-eval-report.md) | 评审评测报告 | 具体指出是什么让评测报告的数字不可信（数据污染、没有校准的裁判、没有方差估计的单次运行、用排行榜名次代替针对具体任务的判断），而不是只说它感觉单薄 |

## 使用方式

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
