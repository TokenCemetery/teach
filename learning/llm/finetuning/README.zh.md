# 学习：适配器微调（LoRA、QLoRA、DoRA）

成为这样的人：拿到一个基础模型和一项任务，能判断适配器微调到底是不是正确的答案，能把它跑起来，能用一个会抓住退步的评测来证明它有效，并把它发布出去；而当提示词或检索能把事情做得更好时，也能有说服力地主张改用它们。

**从这里开始：** [0001. 基础模型到底是什么](lessons/0001-what-a-base-model-is.md)
**最新课程：** [0027. 何时不该微调](lessons/0027-when-not-to-fine-tune.md)

## 成功的标准

- 针对给定的模型，推导出全量微调与 LoRA 的内存开销，并说清每一个字节。
- 为一项新任务选择秩、alpha、目标模块和学习率，并且每一项都依据任务来论证，而不是依据某篇博客的默认值。
- 在同一项任务上训练 LoRA、QLoRA 和 DoRA 适配器，并解释测得的差异，而不是宣传的差异。
- 搭建一个能在发布前抓住退步的评测，而不是看着损失曲线干等。
- 通过一套推理栈部署适配器，并度量它在质量和延迟上付出了什么代价。
- 诊断失败的运行并指出原因：过拟合、灾难性遗忘、聊天模板错误、分词器不匹配、目标模块错误。
- 读一篇新的 PEFT 论文，并判断它声称的优势在你自己的任务上是否站得住脚。

## 约束

- 不假定有机器学习的背景。矩阵乘法是唯一被默认为已知的数学；在它之上的一切，都在需要的地方讲授。
- 在 1B 到 3B 级别的基础模型上做适配器训练，大约放得进 16 GB 的加速器内存或统一内存，这使整条路线都在普通单设备硬件的可及范围之内。
- 后端的支持并不均衡，但也并不排他。CUDA 仍然是最完整、优化得最好的路径，发表的数字在上面最可靠地复现；其他后端也能工作，只是内核覆盖程度不一，每一步更慢。每个概念都原样适用；不同的只是速度和内核是否可用。
- 练习的延迟很长：一次训练运行要花几分钟到几小时，所以课程要成批安排，而不是塞进一个晚上，中间穿插阅读。
- 工具的变化比任何一本书都快。库的 API 要从所安装版本的文档里读，绝不凭记忆回想。
- 路线里没有任何一步需要付费的基础设施，不过租用更大的加速器会让某些比较更快。

## 范围之外

- 大规模的全量微调、预训练，以及从零训练一个模型：见 [`llm/pretraining`](../../llm/pretraining/)。
- RLHF、DPO 和偏好优化：见 [`llm/post-training`](../../llm/post-training/)。本系列负责的是如何把改动应用到更少的参数上；那个系列负责的是训练目标。
- 把量化本身作为一个主题：见 [`llm/quantization`](../../llm/quantization/)。这里的第 4 阶段保留了 QLoRA 所需要的那一部分，并链接到那里去看通用理论；这条界线是在写量化系列时划定的。部署时的量化见 [`llm/inference`](../../llm/inference/)。
- 把蒸馏本身作为一个主题：见 [`llm/distillation`](../../llm/distillation/)。本系列负责的是如何把一次训练应用到更少的参数上；那个系列负责的是蒸馏的目标和数据。
- 搭建部署基础设施，超出在现有的栈上运行适配器之外的部分：见 [`llm/inference`](../../llm/inference/)。

## 学习路线

共七个阶段，从零到资深。一个阶段包含若干课程，边界并不严格；一个阶段是否完成，取决于能力，而不是课程数量。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. 地基 | 0001 至 0004 | 前向传播计算什么、权重矩阵在哪里、分词器、聊天模板、训练改变了什么 | 能指出适配器会触及哪些张量，以及原因 |
| 2. 内存的论证 | 0005 至 0007 | 参数、梯度与优化器状态、AdamW 的两个矩、激活内存、梯度检查点 | 能以字节为单位，算出全量微调为什么在给定设备上行不通 |
| 3. LoRA | 0008 至 0013 | `ΔW = BA`、秩、alpha 与缩放、初始化、目标模块的选择、运行它、解读运行、合并 | 能训练一个适配器，并能为每个超参数辩护 |
| 4. 量化与 QLoRA | 0014 至 0017 | int8/int4、NF4、双重量化、穿过冻结的量化基础模型做反向传播、什么会退化 | 跑过真正的 NF4，并能说出它在质量上付出了什么代价 |
| 5. DoRA 与变体全景 | 0018 至 0020 | 幅度与方向的分解、为什么在低秩时帮助最大、如何评估一个新变体的主张 | 能在运行之前就预测 DoRA 何时胜过 LoRA |
| 6. 数据与评测 | 0021 至 0024 | 数据集的构建、数据污染、留出集设计、任务指标与损失、回归测试集 | 有一个确实抓住过退步的评测 |
| 7. 运维与判断 | 0025 至 0027 | 不合并与合并的适配器部署、多适配器部署、成本与延迟、何时*不*该微调 | 值得信任去判断一项任务到底该不该微调 |
