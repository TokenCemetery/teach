# 第 9 课：秩、alpha 与初始化

**使命关联:** 使命要求你根据任务来论证每一个超参数。这三个，恰恰是大多数人在重复民间经验的地方。
**主要来源:** [文档：LoRA，Hugging Face PEFT](https://huggingface.co/docs/peft/main/en/developer_guides/lora)
**前置知识:** [第 8 课](0008-the-low-rank-idea.md)

## 热身

1. ▢ 写出 LoRA 的前向方程。

<details markdown="1"><summary>检查</summary>

`h = W₀x + (α/r) · BAx`，其中 `W₀` 冻结，只有 `A` 和 `B` 可训练。

</details>

2. ▢ 一个目标层的适配器参数量是多少？

<details markdown="1"><summary>检查</summary>

`r × (d_in + d_out)`。由较大的那个维度主导。

</details>

3. ▢ 为什么合并后的适配器在推理时不花任何代价？

<details markdown="1"><summary>检查</summary>

更新是加性的、线性的，所以它折叠进基础权重，留下的是一个普通的矩阵。

</details>

## 要点

### 初始化，以及它为什么不是随意的

`A` 随机初始化，用高斯分布或 Kaiming 均匀分布。`B` 初始化为**恰好为零**。

因此在第零步，`BA = 0`，所以 `ΔW = 0`，所以**第一次更新之前，适配后的模型与基础模型逐位完全相同。** 这是一个刻意设计的、重要的性质：

- 训练从一个已知良好的模型出发，而不是一个被扰动过的模型。
- 预训练得到的行为没有受到初始冲击，所以也没有需要挽回的早期损害。
- 你观察到的任何退化，都是训练造成的，而不是初始化造成的。

![B 画成一格格的零，A 画成一格格各不相同的值，它们的乘积是一格格的零，下方标出了两种被否决的初始化方式。](images/zero-whatever-a-holds.svg)

`A` 的各项清晰可见，却没有一项起作用：每一项在进入乘积的路上，都要乘以一个零。

这种不对称是必要的。如果两者都是零，两者的梯度都为零，就永远学不到任何东西：乘积需要有一个因子非零，才能传递信号。如果两者都是随机的，`ΔW` 一开始就是有结构的噪声，被注入每一个目标层。

这也是 LoRA 能容忍比全量微调高得多的学习率的原因。你不是在轻推那些已经编码了模型所知一切的权重，而是在让一个项从零长出来。

### alpha 与缩放因子

`α`（`lora_alpha`）是一个固定的标量。更新按 `α/r` 缩放。

除以 `r` 的用意，是让有效的更新幅度大致与秩无关，这样改变秩时，就不必重新调学习率。**要紧的是比值 `α/r`，而不是其中任何一个数字单独的值。**

| `r` | `α` | `α/r` | 效果 |
|---|---|---|---|
| 8 | 16 | 2.0 | 常见的基线 |
| 16 | 32 | 2.0 | 容量更大，更新的尺度不变 |
| 16 | 16 | 1.0 | 容量更大，更新更弱 |
| 64 | 16 | 0.25 | 容量大得多，被大幅压低 |

最后一行是一个值得点名的陷阱：提高秩，却让 `α` 保持不变，会*降低*更新的尺度。人们提高秩，是希望获得更强的表达能力，却忘了 `α`，于是得出结论，说更高的秩有害。其实不是秩的错，而是他们悄悄地把适配器调低了 8 倍。

惯常的起点是 `α = 2r`。把它当作有道理的惯例，而不是什么发现。

**rsLoRA**（[arXiv:2312.03732](https://arxiv.org/abs/2312.03732)）认为，除以 `α/r` 在高秩时压得过头，提出改用 `α/√r`，从而在秩增大时保持学习稳定。如果你打算在秩 64 或更高的地方工作，这是需要了解的设置：

```python
LoraConfig(r=64, lora_alpha=16, use_rslora=True, ...)
```

### 选择秩

秩就是**容量**。它限定了适配器能表达多复杂的更新。

| 秩 | 适用于 |
|---|---|
| 4 到 8 | 风格、语气、输出格式；小数据集 |
| 16 到 32 | 有几千个样本的真实任务 |
| 64 到 128 | 更难的任务、更大的数据集、推理密集的行为 |
| 256+ | 在大型 SFT 数据集上，接近全量微调的容量 |

有两项诊断胜过猜测：

**欠拟合。** 训练损失停在了高于你所需的位置，增加 epoch 也没用。容量不够：提高秩，或增加目标模块（通常是更好的做法，见第 10 课）。

**过拟合。** 训练损失持续下降，而留出集损失上升。对这些数据来说容量太大，或 epoch 太多。降低秩、加入 dropout、获取更多数据，或者提早停止。

注意它与内存那一课的不对称：秩消耗的内存很少（第 7 课），所以多加秩的代价是过拟合的风险和一点算力，而不是内存放不放得下。这与许多人从内存还是约束瓶颈的年代带来的直觉正好相反。

### Dropout

`lora_dropout` 对适配器的输入施加 dropout。典型值是 0.0 到 0.1。当留出集损失在上升、而你又无法获取更多数据时，可以用它。在大型数据集上，它往往没有必要，只会拖慢收敛。

### 配置

```text
config := {
    rank: 16,
    alpha: 32,               # α/r = 2
    dropout: 0.05,
    adapt_bias: false,
    target_modules: [...],   # Lesson 10
}

model := attach_adapter(model, config)
print(model.trainable_parameter_count())
```

最后一行不是可选的。它是检验你的目标模块到底有没有匹配上任何东西的办法，而且它应该与你在第 8 课里算出的结果吻合。参数名请从所安装版本的文档中读取，而不要凭记忆，因为这块接口在不同版本之间会变。

## 练习

1. ▢ 为什么 `B` 初始化为零、`A` 随机初始化，而不是两者都为零或都随机？

<details markdown="1"><summary>检查</summary>

`B` 为零，使开始时 `ΔW = 0`，所以训练恰好从基础模型出发，没有需要恢复的扰动。`A` 随机，使乘积的梯度非零，学习才能开始。

两者都为零：梯度消失，什么也学不到。两者都随机：模型一开始就是每个目标层里“基础模型加噪声”。

</details>

2. ▢ 你把秩从 8 提高到 64，`α` 保持 16。损失几乎不动。诊断一下。

<details markdown="1"><summary>检查</summary>

尺度 `α/r` 从 2.0 降到了 0.25。适配器的容量是原来的八倍，影响力却只有八分之一，所以净效果是更新被压低了，而不是更强了。

把 `α` 提高到 128 以保持比值，或者设 `use_rslora=True`，让除数变成 `√r`。

</details>

3. ▢ 训练损失在一个太高而没有用的水平上变平，第四个 epoch 也没有帮助。这是什么，你有哪两个选择？

<details markdown="1"><summary>检查</summary>

欠拟合：适配器缺乏表达所需更新的容量。

提高秩，或者扩大目标模块，覆盖模型更多的部分。增加目标模块通常是更好的第一步，因为 MLP 持有大部分参数，缺失的容量往往就在那里。更多的 epoch 解决不了容量的上限。

</details>

4. ▢ 哪一组搭配给出最强的更新尺度？

    - a) `r = 8` 配 `alpha = 8`
    - b) `r = 8` 配 `alpha = 32`
    - c) `r = 32` 配 `alpha = 32`
    - d) `r = 64` 配 `alpha = 64`

<details markdown="1"><summary>检查</summary>

**b)** `r = 8` 配 `alpha = 32`，得到 `α/r = 4`。

其余的 `α/r` 都是 1。它们之间容量不同，更新尺度却相同，而这恰恰是 `α/r` 这个设计想要做出的区分。

</details>

5. ▢ 为什么 LoRA 可以使用比全量微调高十倍到一百倍的学习率？

<details markdown="1"><summary>检查</summary>

可训练参数从零贡献开始，它们本身并不是预训练知识的存储之处。没有积累下来的结构可供破坏，而且这一项要从无到有地长出来，所以需要大得多的步长，才能在合理的步数内有意义地移动。

</details>

6. ▢ 即使适配器欠拟合，什么时候你也*不会*提高秩？

<details markdown="1"><summary>检查</summary>

数据集很小的时候。在很少的样本上增加容量，买到的是记忆，而不是泛化：训练损失下降，留出集损失上升。

此时正确的应对，是更多或更好的数据，或者更窄的任务，而不是更大的适配器。

</details>
