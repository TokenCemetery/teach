# 第 12 课：解读训练运行

## 要点

### 光看训练损失，几乎什么也看不出来

训练损失在下降，意味着模型在拟合它看得见的数据。这既符合模型在学任务的情形，也符合它在死记训练集的情形。**要区分这两者，你需要一份留出的划分，而且没有任何东西可以替代它。**

开始之前就先留出一份：

```python
split = dataset.train_test_split(test_size=0.05, seed=0)
args = SFTConfig(..., eval_strategy="steps", eval_steps=50)
trainer = SFTTrainer(..., train_dataset=split["train"], eval_dataset=split["test"])
```

### 各种形状及其含义

| 训练损失 | 留出集损失 | 诊断 | 做法 |
|---|---|---|---|
| 下降 | 下降 | 在学习 | 继续 |
| 下降 | 先变平再上升 | 从拐点起过拟合 | 在最小值处停下；更多数据或更小容量 |
| 很快降到约 0 | 立刻上升 | 在死记硬背 | 对这个容量来说，数据集太小了 |
| 在高位变平 | 在高位变平 | 欠拟合 | 更大的秩、更多的目标模块、更高的学习率 |
| 从第 1 步起就平坦 | 平坦 | 流水线坏了 | 第 11 课的四项检查 |
| 出现尖峰，或 `NaN` | 无关 | 不稳定 | 降低学习率；检查 fp16 是否溢出；加预热 |

有用的检查点是**留出集损失的最小值**处，而不是最后一步。定期保存检查点，并留下最好的那个；留出集损失在第 400 步触底，却跑到第 1000 步才结束的运行，白白训练了 600 步的损害。

### 更仔细地按形状诊断

**更多训练也降不下去的损失下限**，是容量的上限。适配器无法表达任务所需要的更新。增加 epoch 修不好它；增加秩或目标模块可以。

**出现尖峰又恢复的损失**，通常是某个批次里包含了不寻常的东西：长度异常的样本、损坏的文本、重复的块。把它找出来。在小数据集的运行里，单个有问题的样本就能让整个运行发生变化。

**变成 `NaN` 的损失**是溢出。在 fp16 里这很常见，损失缩放的存在就是为了防止它；在 bf16 里，它通常意味着更糟的事，比如数据流水线里除以零，或者学习率高到把权重推向了无穷大。

**呈干净阶梯状下降的损失**，台阶落在 epoch 的边界上，意味着模型在认出它见过的样本。这是记忆直接显现在曲线里。

### 损失完全看不见的东西

这是这一课的重点。

交叉熵给你的数据分布上的下一个 token 预测打分。对以下几点，它保持沉默：

- **生成的结果是否可用。** 模型可以得分很高，却产出永不停止的输出，或者无视所要求的格式。
- **别的东西是否坏了。** [灾难性遗忘](../GLOSSARY.md)，即与你的任务无关的能力发生退化，在你任务的损失里根本不会出现。你的留出集损失可以单调改善，而模型在它原本能做的其他一切事情上变得更差。
- **改善是真实的，还是数据污染。** 如果你的留出样本是训练样本的近似重复，留出集损失度量的就是记忆，却被叫作泛化。

所以：**每一次都要生成。** 在训练之前先固定一小组提示词。让它们过一遍基础模型，保存输出。再以相同的采样设置，让它们过一遍适配后的模型，并做对比。花十分钟读真实的生成结果，能抓到曲线上任何指标都抓不到的东西。

```python
PROBES = [
    "<a representative task prompt>",
    "<an edge case you care about>",
    "<something unrelated to the task, to check for forgetting>",
]
```

第三类是人们漏掉的那一类，遗忘就是这样被发布出去的。

### 可复现性

记录得足够多，以便你能重新运行：基础模型及其版本、数据集及其确切的划分、随机种子、每个超参数，以及库的版本。适配器微调的配置面足够大，“我记得好像是秩 32”算不上记录。

只有当两次运行之间恰好有一处不同时，比较它们才有意义。改秩*或*学习率，不要两个一起改，并保持随机种子和数据固定。这听上去显而易见，却经常被违反，通常是因为一次运行要花很久，让耐心变得昂贵。

## 练习

1. ▢ 训练损失是 0.2，还在下降。留出集损失在两百步前触底于 0.9，现在是 1.1。发生了什么，你发布哪个检查点？

<details markdown="1"><summary>检查</summary>

过拟合。模型现在拟合的是训练集特有的噪声。

发布留出集损失最小值处的检查点，大约在两百步之前。下次则降低容量、增加数据，或者提早停止。

</details>

2. ▢ 两个损失都在一个太高而没有用的水平上变平。秩 8，只作用于注意力。你改什么，不改什么？

<details markdown="1"><summary>检查</summary>

改容量：把目标扩展到所有线性层，并提高秩。考虑学习率是不是太低了。

不要增加 epoch。容量的上限不会随着对同样的数据多过几遍而移动。这正是这个诊断的定义。

</details>

3. ▢ 留出集损失一路改善。你发布了。用户反映模型在它原先能做的事情上变差了。你没有度量的是什么？

<details markdown="1"><summary>检查</summary>

灾难性遗忘。你的留出集取自你任务的分布，所以它看不到在这个分布之外的能力的退化。

补救办法是一个回归测试集，覆盖你没有在训练的能力：通用的遵循指令、拒答行为、其他格式。那是第 24 课，而这种失败就是它存在的原因。

</details>

4. ▢ 哪一项观察最有力地表明是流水线坏了，而不是超参数不好？

    - a) 损失曲线停在一个远高于零的值上
    - b) 在全部五十步里，损失恰好一点没变
    - c) 留出集损失上升，而训练损失下降
    - d) 损失在某一步向上冲出一个尖峰，随后恢复

<details markdown="1"><summary>检查</summary>

**b)** 在全部五十步里，损失恰好一点没变。

平台是欠拟合，一对分道扬镳的曲线是过拟合，尖峰通常是一个坏批次，这些都是真实的训练行为。损失*完全*不动，意味着没有任何梯度传到任何参数，这是接线上的故障。

</details>

5. ▢ 为什么你的生成探针中，至少要有一个与任务无关？

<details markdown="1"><summary>检查</summary>

因为这是在运行期间发现遗忘的唯一廉价办法。与任务相关的探针和与任务相关的留出集损失，在无关能力衰退的同时都会改善，所以你已经在度量的任何东西，都不会向你发出警告。

</details>

6. ▢ 损失呈阶梯状下降，每个 epoch 边界处下降一截。诊断一下。

<details markdown="1"><summary>检查</summary>

模型在认出它已经见过的样本。这是记忆，直接显现在曲线里。每个新的 epoch 都会降一截，因为数据已经不新鲜了。

检查留出集损失，它多半是平的或在上升，然后减少 epoch 或降低容量。

</details>
