# 第 14 课：从第一性原理看量化

**使命关联:** QLoRA 就是 LoRA 加上一个想法。这一课单独把那个想法讲清楚，好让下一课简短一些。
**主要来源:** [论文：“LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale”，Dettmers 等，arXiv:2208.07339](https://arxiv.org/abs/2208.07339)
**前置知识:** [第 5 课](0005-counting-parameters-and-bytes.md)、[量化](../GLOSSARY.md)

## 热身

1. ▢ fp32、bf16 和 4 位，每个参数各多少字节？

<details markdown="1"><summary>检查</summary>

四字节、两字节和半字节，4 位的情形还要加上量化常数，本课会讲清楚。

</details>

2. ▢ 对于一个 7B 的基础模型加 20M 的适配器，训练内存都花在哪里？

<details markdown="1"><summary>检查</summary>

14 GB 的冻结基础权重、约 0.3 GB 的适配器状态，以及可能超过这两者的激活值。冻结的基础模型是最大的固定项，本阶段要对付的就是它。

</details>

3. ▢ 为什么合并进量化的基础模型会损失质量？

<details markdown="1"><summary>检查</summary>

它需要反量化、加上更新、再重新量化。重新量化这一步会丢弃信息。

</details>

## 要点

量化是用比训练时更少的位数来存储数字。请回忆[术语表](../GLOSSARY.md)：在本工作区里，它始终指的是**冻结的基础模型**，而不是适配器。

### 机制

要把一个高精度的张量存进小的整数类型，你需要在实数范围和整数范围之间建立一个映射。有两种方案：

**对称的，absmax。** 取最大的绝对值，缩放后让它落在整数的最大值上。

```text
s = absmax(x) / 127          # for int8
q = round(x / s)             # store q, an int8
x̂ = q · s                    # recover, approximately
```

**非对称的，仿射。** 还要存一个零点偏移，这样范围就不必以零为中心。

```text
s = (max(x) − min(x)) / 255
z = round(−min(x) / s)
q = round(x / s) + z
```

Transformer 里的权重分布大致是对称的，中心靠近零，所以对权重来说，对称的 absmax 是常见的选择。

无论哪种，误差都是**舍入误差**：每个值都挪到最近的可表示的档位上。4 位有十六档，8 位有 256 档。

### 离群值问题

这就是朴素的量化在 Transformer 上失败的原因。张量里单独一个很大的值，决定了 `absmax`，也就决定了缩放因子，于是所有可表示的档位被摊开，去覆盖一个几乎所有其他值都用不到的范围。典型的值于是全都被舍入到寥寥几档里，这个张量的大部分信息，就被一个离群值毁掉了。

这并不是假想。Transformer 的激活值会形成系统性的大幅度特征，这个观察是 LLM.int8() 工作的核心：少数几个离群的维度承载着不成比例的重要性，朴素地处理它们，会在规模上毁掉质量。

### 分块量化，解决办法

不要用一个缩放因子去量化整个张量。把它切成 64、128 或 256 个元素的小的连续**块**，给每个块各自的缩放因子。

```text
per-tensor:  one absmax  → one outlier ruins everything
per-block:   one absmax per 64 → one outlier ruins 64 values
```

![两条数轴，档位相同，都是十六档。第一条里，缩放因子由一个离群值决定，五个典型的值挤塌到靠近中心的两档上。第二条里，没有离群值的块自己决定缩放因子，同样的五个值落在五个不同的档位上。](images/outlier-sets-the-scale.svg)

两行都有十六档，间距相同。唯一变了的，是这十六档要覆盖多大的数值范围，而这由计算缩放因子时所覆盖的那一批值里最大的那个决定。把档位花在数据从不涉足的范围上，数据就只能落到寥寥几档；把它花在数据实际占据的范围上，每个值都保有自己的一档。

损害被控制住了。这就是分块量化成为标准、而整张量量化不是的原因。

它是有代价的，而这个代价正是下一课的全部主题。每个块都需要存下它的缩放因子，而这个因子是个实数：

```text
4-bit weights, block size 64, fp32 scales:
  weights = 0.5 bytes/param
  scales  = 4 bytes per 64 params = 0.0625 bytes/param
  total   = 0.5625 bytes/param, i.e. 4.5 bits, not 4
```

在 4 位的预算之上，多出百分之十二的开销，纯粹是为了记账。记住这个数字。

### 存储精度与计算精度

量化后的权重不会以量化的形式被使用。前向传播会**把一个块反量化回 bf16，做矩阵乘法，然后丢弃反量化出来的副本。**

```text
stored:   4-bit + per-block scale
computed: bf16
```

所以量化买来的是内存，付出的是计算：每次前向传播，每个块都要多一步反量化。净效果是更快还是更慢，完全取决于你原来是受内存限制还是受计算限制，以及反量化内核针对你所用的硬件优化得有多好。

最后这一点，正是硬件真正介入的地方。*算术*在各处都一样。因后端而异的，是对某个位宽和块大小，有没有融合的、经过优化的内核，还是库退回到较慢的通用路径。第 16 课给出当前的情形。

### 在这里，量化是用来做什么的

有两种用途，不能混淆：

**面向推理的量化**，把模型缩小，让它放得下、部署得便宜。权重被量化，那就是你发布的产物。把它当作一个独立的主题，不在本工作区的范围之内。

**面向训练的量化**，也就是 QLoRA 所做的，缩小的是*冻结的基础模型*，好让适配器训练放得下。适配器保持较高精度，你发布的产物，之后可以合并进全精度的基础模型。基础模型的精度是训练时的预算决策，而不是结果的属性。

## 练习

1. ▢ 用对称 absmax 把值 `[0.1, −0.3, 0.2, 8.0]` 量化成 int8。前三个值会怎样？

<details markdown="1"><summary>检查</summary>

`absmax = 8.0`，所以 `s = 8.0/127 ≈ 0.063`。这些值映射为 `round(0.1/0.063) = 2`、`round(−0.3/0.063) = −5`、`round(0.2/0.063) = 3`，以及 `127`。

恢复后：0.126、−0.315、0.189、8.0。小的值现在带有可观的相对误差，因为一个离群值占掉了整个范围。在 4 位、十六档的情形下，前三个值会塌缩到几乎同一个值。

</details>

2. ▢ 为什么分块量化有帮助，它的代价是什么？

<details markdown="1"><summary>检查</summary>

离群值只决定它自己那个块的缩放因子，所以它损害的是 64 个值，而不是整个张量。

代价是每块要存一个缩放因子。在块大小为 64、fp32 缩放因子的情形下，每个参数 0.0625 字节，在 4 位的预算上约有 12% 的开销。

</details>

3. ▢ 4 位权重，块大小 128，fp32 缩放因子，每个参数总共多少字节？

<details markdown="1"><summary>检查</summary>

0.5 + 4/128 = 0.5 + 0.03125 = 0.53125 字节，即 4.25 位。

块越大，缩放因子的开销越小，对离群值的控制越差。这就是块大小所设定的权衡。

</details>

4. ▢ 在量化的前向传播中，矩阵乘法是在哪种精度下进行的？

<details markdown="1"><summary>检查</summary>

更高的精度，通常是 bf16。每个块被反量化成 bf16，相乘，然后反量化出来的副本被丢弃。

量化是一个*存储*上的决定。计算精度是另一回事，单独配置。

</details>

5. ▢ 为什么 Transformer 的量化比单从算术上看要难？

<details markdown="1"><summary>检查</summary>

因为存在系统性的离群特征。少数几个维度幅度非常大，重要性也不成比例，所以把所有值当作可以互换、每个张量只用一个缩放因子的方案，会毁掉普通的值，却保住离群值。

应对办法是分块量化，而在 LLM.int8() 里，则是把离群的维度整个分出来，用更高的精度处理。

</details>

6. ▢ 区分面向推理的量化和面向训练的量化。

<details markdown="1"><summary>检查</summary>

面向推理时，量化后的权重*就是*产物：你发布它们，质量上的代价是永久的。

面向训练时，量化冻结的基础模型是一个内存预算上的决定。适配器保持高精度，发布的结果可以合并进全精度的基础模型，所以量化的代价根本不必延续到产物中。

</details>
