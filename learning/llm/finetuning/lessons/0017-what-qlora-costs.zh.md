# 第 17 课：QLoRA 的真实代价

**使命关联:** 使命说的是“解释测得的差异，而不是宣传的差异”。这一课就是那个测量。
**主要来源:** [论文：“QLoRA: Efficient Finetuning of Quantized LLMs”，Dettmers 等，arXiv:2305.14314](https://arxiv.org/abs/2305.14314)
**前置知识:** [第 16 课](0016-training-through-a-quantized-base.md)

## 热身

1. ▢ 为什么冻结的 4 位基础模型仍然能传递梯度？

<details markdown="1"><summary>检查</summary>

它是计算图里的一个常量。传递梯度需要的是以高精度读取它，而不是对它求导，而且没有任何梯度为它存下来。

</details>

2. ▢ QLoRA 的哪个组成部分是真正特定于 CUDA 的？

<details markdown="1"><summary>检查</summary>

分页优化器，它依赖 NVIDIA 的统一内存。而且它对适配器训练最不重要，那里优化器状态很小。

</details>

3. ▢ 针对 4 位基础模型训练出来的适配器，要在哪里合并？

<details markdown="1"><summary>检查</summary>

合并进全精度的基础模型，如果需要，之后再量化。

</details>

## 要点

### 精确地陈述论文的主张

QLoRA 的头条结果是，在所测的任务上，4 位 NF4 的适配器微调可以追平 16 位微调的表现。这是个有分量的结果，而且是真实的。

它同时也是关于**特定设置、特定基准**的主张。它没有确立的是：

- NF4 在*你的*任务上是免费的。遵循指令的基准，并不是你的生产环境分布。
- 量化在每种规模上都是免费的。量化误差是一个固定的相对扰动，小模型能用来吸收它的冗余更少，所以退化一般在小模型上比在大模型上更明显。
- 每一种 4 位实现都是等价的。量化类型、块大小、是否开启双重量化、计算的数据类型和内核的质量，都各不相同。

把论文的主张读成“量化是免费的”，恰恰就是使命里“测得的，而不是宣传的”这句话所针对的失败模式。

### 把两项代价分开

有两个不同的质量问题，把它们混为一谈，会让结果无法解读。

**代价 1。量化的基础模型在任何训练之前就是一个更差的模型。** 这纯粹是表示方式的属性。

**代价 2。针对量化的基础模型训练，得到的适配器更差。** 这是训练过程的属性，叠加在代价 1 之上。

要分别测量它们：

| 配置 | 隔离出的是 |
|---|---|
| bf16 基础模型，无适配器 | 参照点 |
| 4 位基础模型，无适配器 | 代价 1，单独的量化损害 |
| bf16 基础模型 + 适配器 | 训练的上限 |
| 4 位基础模型 + 适配器 | 代价 1 与 2 合在一起 |
| 4 位训练的适配器合并进 bf16 基础模型 | 代价 1 是否延续到产物中 |

![基础模型的精度对适配器，排成两行两列的网格，放着参照点、训练上限、单独的代价 1 以及两项代价合在一起，网格下方另有第五个方框，是在 4 位下训练、再合并进 bf16 基础模型的适配器。](images/the-one-that-is-not-a-cell.svg)

五种配置里有四种是同一个网格里的格子。第五种不是，因为它训练时用的基础模型和部署时用的不同，而一个没有格子可放的配置，很容易被忘了去运行。

最后一行是有意思的那一行，却常被跳过。你针对一个退化的基础模型训练，但你可以针对全精度的基础模型*部署*。适配器是否学会了补偿量化误差，因此在误差消失时反而失配，是一个经验问题，对你的任务有一个真实的答案。去测量它，而不是想当然地认定哪一边。

### 如何诚实地测量

**保持其他一切固定。** 相同的数据、相同的划分、相同的随机种子、相同的秩、alpha、学习率、调度和步数。只有一个变量：基础模型的精度。一次含有两处改动的比较，不叫比较。

**用任务指标，不用损失。** 损失在各配置之间无法按你想要的方式比较，而且它也不是你关心的东西。第 23 课讲指标的选择。

**报告分布范围，而不是单个点。** 每个配置用三个随机种子运行。如果你的种子间波动是 2 分，而你的量化效应是 1 分，那你什么也没测到，而这种事经常发生。对两种配置做单种子的比较，只是一则轶事。

**同时测量速度和内存。** 它们是你考虑量化的原因，所以应当和质量放在同一张表里。

### 值得产出的结果表

| 配置 | 任务指标 | 峰值内存 | 每步秒数 |
|---|---|---|---|
| bf16 基础模型 + 适配器 | | | |
| NF4 基础模型 + 适配器 | | | |
| 不用双重量化的 NF4 | | | |
| 用 int4 而不是 NF4 | | | |
| NF4，合并进 bf16 后评测 | | | |

在你关心的任务上把它填一遍，比读多少关于量化的东西都更值。尤其是最后一行，会告诉你一些查不到的东西。

### 该预期什么，好让你能感到意外

来自文献和常见做法的粗略预期，是一个有待更新的先验，而不是结果：

- **内存：** 基础权重大约缩小 4 倍。可靠，这是算术。
- **速度：** 每步更慢，常常很明显。反量化是实打实的工作。
- **质量：** 小幅退化，在较大的模型上常常落在种子噪声之内，在较小的模型上和余量很窄的任务上更明显。
- **NF4 与 int4：** 存储相同时，NF4 更好。
- **双重量化：** 节省内存，对质量的影响可以忽略。

如果你的测量与这些严重不符，值得去调查，而不是不当回事。最常见的原因，是你的后端上用了未经优化的内核路径，或者比较中改动了不止一样东西。

### 什么时候该用 QLoRA

**当内存是约束瓶颈时用它**，也就是 bf16 基础模型加激活值放不下，而替代方案是根本不训练，或者训练一个更小的模型的时候。一个 4 位的大模型通常胜过 bf16 的小模型。

**内存不是约束时不要用。** 如果 bf16 放得下，量化就是白白花掉速度和一点质量。教程里总是以 4 位加载的那种条件反射，在你本来就有内存的时候，是没有收益的成本。

## 练习

1. ▢ 陈述 QLoRA 的头条主张，再陈述它没有确立什么。

<details markdown="1"><summary>检查</summary>

主张：在所测的基准上，4 位 NF4 的适配器微调可以追平 16 位微调的表现。

没有确立的：这在你的任务和分布上是否成立，在小模型规模上是否同样成立，或者任何 4 位实现是否与论文中的等价。

</details>

2. ▢ 说出两项独立的质量代价，以及你如何把它们分开。

<details markdown="1"><summary>检查</summary>

代价 1：量化的基础模型在训练之前就是一个更差的模型，所以测量不带适配器的基础模型，量化与否各一次。

代价 2：针对量化的基础模型训练，得到的适配器更差，所以比较在量化与全精度基础模型上训练出的适配器，其他一切保持固定。

</details>

3. ▢ 你测得 bf16 是 71.2，NF4 是 70.8。量化让你付出了 0.4 分的代价吗？

<details markdown="1"><summary>检查</summary>

不知道。没有种子的波动范围，你分不清 0.4 分和噪声，而微调运行的种子间波动，常常超过它。

每个配置用三个随机种子运行，比较分布。这种大小的单种子差异，不是结果。

</details>

4. ▢ 哪项比较最常被跳过，它告诉你什么？

<details markdown="1"><summary>检查</summary>

评测合并进全精度基础模型的、用 4 位训练出来的适配器。

它告诉你，量化的代价是否一定要延续到你部署的产物中。你训练得便宜，但没有什么逼着你也得便宜地部署。它还揭示了适配器是否适应了量化误差本身。

</details>

5. ▢ 你的 bf16 运行内存绰绰有余。你还应该换成 4 位吗？

<details markdown="1"><summary>检查</summary>

不应该。你会为了节省本来就不缺的内存，付出更慢的步骤和一点质量上的风险。

量化是对内存这一约束瓶颈的回应。因为教程这么做，就条件反射地用它，是没有相应收益的成本。

</details>

6. ▢ NF4 让你的 1B 模型任务明显退化，而论文报告没有退化。你是在与论文相矛盾吗？

<details markdown="1"><summary>检查</summary>

不是。量化误差是一个固定的相对扰动，小模型能用来吸收它的冗余更少，所以退化一般在小规模上更明显。你的任务和指标，也与所测的基准不同。

两个结果都可以是对的。这正是使命要求的是测得的差异，而不是宣传的差异的原因。

</details>
