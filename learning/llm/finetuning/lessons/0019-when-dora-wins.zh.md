# 第 19 课：DoRA 何时占优，何时不占优

**使命关联:** “能在运行之前就预测出 DoRA 何时胜过 LoRA”是本阶段的门槛。是预测，不是实验。
**主要来源:** [论文：“DoRA: Weight-Decomposed Low-Rank Adaptation”，Liu 等，arXiv:2402.09353](https://arxiv.org/abs/2402.09353)
**前置知识:** [第 18 课](0018-dora-magnitude-and-direction.md)、[第 17 课](0017-what-qlora-costs.md)

## 热身

1. ▢ DoRA 的重新归一化，阻止 `BA` 做什么？

<details markdown="1"><summary>检查</summary>

改变幅度。重新归一化之后，`BA` 只影响方向，而幅度来自单独训练的 `m`。

</details>

2. ▢ 为什么列范数不能在各步之间缓存？

<details markdown="1"><summary>检查</summary>

它是 `W₀ + BA` 的范数，而 `BA` 在每一步优化器更新时都会变。

</details>

3. ▢ 为什么质量比较必须用多个随机种子？

<details markdown="1"><summary>检查</summary>

因为种子间的波动，常常超过所要测量的效应，所以单种子的差异无法与噪声区分开。

</details>

## 要点

### 报告出的模式

DoRA 相对于 LoRA 的增益，**在低秩时最大，随着秩增大而缩小。**

这个推理直接来自机制。在秩 4 或 8 时，低秩更新的容量很小，花在调整幅度上的任何一点容量，都是没有花在方向上的容量。DoRA 把幅度交给一个单独的、廉价的、专用的参数，把整个低秩的预算腾出来给方向。在秩 128 时，预算已经不再稀缺，所以腾出一点来，改变的也就更少。

所以预测的规则不是“DoRA 更好”，而是：

> **DoRA 恰恰在 LoRA 的容量最紧张的地方帮助最大。**

### 什么时候预期会赢

| 情形 | 预期 | 原因 |
|---|---|---|
| 很低的秩（4 到 16） | 有意义的增益 | 容量稀缺；解耦腾出了一些 |
| 秩被约束强行压低 | 有意义的增益 | 原因相同，而且你没有别的选择 |
| 中等的秩（32 到 64） | 较小的增益 | 容量没那么稀缺 |
| 高秩（128+） | 很少或没有 | 容量不是起约束作用的限制 |
| 你完全可以直接提高秩 | 提高秩 | 按实际耗时算，比 DoRA 每步的代价更便宜 |
| 步骤用时是你的约束 | 跳过 DoRA | 你要为一点点小增益付出几十个百分点 |

第五行是值得内化的那一行。如果秩是个可以自由调整的变量，**提高秩通常比换成 DoRA 更好**，因为多加的秩几乎不花内存（第 7 课），也几乎不花时间，而 DoRA 在每一步都要花实实在在的时间。DoRA 要在秩*不是*自由变量时才有立足之地，也就是当除内存之外的某样东西把它压住的时候。

### 究竟是什么把秩压住

值得说具体些，因为整个建议都取决于它：

- **小数据集上的过拟合。** 秩越多，记忆越多。这时你确实不能提高秩，而 DoRA 是个真正的选项：你从刻意保持很小的秩里，得到了更好的利用。
- **对适配器大小的部署约束。** 少见，但如果你要分发适配器，或者同时在内存里放很多个，大小就可能成为约束。
- **复现已发表的配置。** 你被钉在了他们的秩上。
- **总的训练时间预算。** 注意这一条是*不利于* DoRA 的，而不是有利于它，因为 DoRA 每步更慢。

如果这些都不适用，那么秩就是自由的，更简单的做法就摆在那里。

### 批判地解读这个主张

DoRA 论文报告了在若干任务和模型系列上的增益，并以幅度与方向的分析作为它的机制论证。那个分析确实很有启发，这个方法的动机也很充分。

有三点要记在心里：

**报告的增益在绝对值上往往很小**，在某个基准上一两个点。在把它当作你的任务上真实存在的效应之前，先拿它和你的种子噪声比一比。

**对比的基线很重要。** 秩 8 的 DoRA 对秩 8 的 LoRA，是论文的比较，对于隔离出机制来说，这是正确的比较。秩 8 的 DoRA 对秩 32 的 LoRA，是*你*在决定运行什么时面对的比较，这是另一个问题，答案也可能不同。

**独立复现比 LoRA 或 QLoRA 要少。** LoRA 有多年来在无数任务上的从业者证据。DoRA 的要少一些。这不是对这个方法的批评；而是在你自己的任务上去测量，而不是照搬一个结论的理由。

### 决策流程

1. 秩可以自由提高吗？ → 提高它。不要用 DoRA。
2. 秩被钉在低位吗，被什么钉住？ → 如果是因为过拟合风险或硬性约束，DoRA 是个真正的候选。
3. 步骤用时已经是起约束作用的因素了吗？ → 不要用 DoRA。
4. 否则：两个都跑，用同一组随机种子，其他一切都相同，再对照种子噪声比较。

第 4 步并不是这个流程的失败。能够说出“这里预期的效应很小，我需要去测量”，*就是*资深的回答，这比不加批判地相信论文，或者一概否定它，都要好得多。

## 练习

1. ▢ 为什么 DoRA 的增益随秩上升而缩小？

<details markdown="1"><summary>检查</summary>

它的好处，是把低秩的容量从表示幅度变化的任务中解放出来。当秩稀缺时，腾出来的容量按比例占很大分量；当秩给得宽裕时，容量本来就不是限制因素，所以腾出一些，改变不大。

</details>

2. ▢ 你现在秩为 8，而且可以随意提高秩。选 DoRA 还是更多的秩？

<details markdown="1"><summary>检查</summary>

更多的秩。它几乎不花内存，也几乎不花时间，而 DoRA 则要在今后每一次运行的每一步上都付出一笔每步的代价。

当秩被某样东西钉住时，通常是小数据集上的过拟合风险，才去用 DoRA，而不是在秩是自由变量时。

</details>

3. ▢ 600 个训练样本，秩保持在 8 以限制记忆。值得试试 DoRA 吗？

<details markdown="1"><summary>检查</summary>

值得。这是这个方法最适合的情形：秩被刻意压低，原因是你无法消除的，所以更好地利用它，是唯一可用的改进。

用多个随机种子，与相同秩的 LoRA 对比测量，因为预期的效应很小。

</details>

4. ▢ 区分论文的比较和你的比较。

<details markdown="1"><summary>检查</summary>

论文比较的是秩相同时的 DoRA 与 LoRA，这正确地隔离出了机制。

你的决策是在你负担得起的秩下的 DoRA，和你负担得起的秩下的 LoRA 之间做选择，而因为 LoRA 每步更快，你可能负担得起用它多给些秩。数字相同，问题不同。

</details>

5. ▢ 下列哪项最可靠地预示着 DoRA 会赢？

    - a) 一个有许多多样样本的大型训练数据集
    - b) 因其他原因无法提高的低秩
    - c) 四位 NF4 精度的量化基础模型
    - d) 覆盖所有线性层的目标模块集合

<details markdown="1"><summary>检查</summary>

**b)** 因其他原因无法提高的低秩。

数据集大小、基础模型精度和目标模块的覆盖范围，都与这个机制无关。低秩容量的稀缺，才是 DoRA 缓解的东西。

</details>

6. ▢ 你测得的 DoRA 增益是 0.6 分，种子波动范围是 1.4 分。你得出什么结论，做什么？

<details markdown="1"><summary>检查</summary>

你没有检测到效应。这个差异完全落在噪声之内。

要么运行足够多的种子，分辨出这么小的差异，那可能要很多个，要么接受这里的效应小到无关紧要，采用更快的方法。判断它不值得去分辨，是一个正当的、而且往往正确的结果。

</details>

## 实战练习

- [ ] 在秩 8 下运行 LoRA 和 DoRA，各三个随机种子，其他一切固定。把差异与种子的波动范围比较。
- [ ] 用与秩 8 的 DoRA 相同的实际耗时预算，运行秩 32 的 LoRA。注意哪一个在单位时间内产出的模型更好。
- [ ] 明天：在运行任何东西之前，先写下你的预测：DoRA 在你实际的任务上是否有帮助，以及原因。把它留着，之后再检验。
