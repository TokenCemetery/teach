# 第 21 课：构建数据集

**使命关联:** 在本工作区里，数据质量压倒每一个超参数。第 3 阶段教你拧旋钮，这一阶段教你真正让结果动起来的是什么。
**主要来源:** [论文：“LIMA: Less Is More for Alignment”，Zhou 等，arXiv:2305.11206](https://arxiv.org/abs/2305.11206)
**前置知识:** [第 3 课](0003-tokenizers-and-chat-templates.md)、[第 12 课](0012-reading-a-training-run.md)

## 热身

1. ▢ 在训练任务之前，价值最高的检查是什么？

<details markdown="1"><summary>检查</summary>

解码一个真实的训练样本并读一遍，数出被打分与被屏蔽的位置。它一次就能抓住模板不匹配、缺少回合结束 token、屏蔽缺陷和截断。

</details>

2. ▢ 在 epoch 边界处下降的阶梯状损失曲线意味着什么？

<details markdown="1"><summary>检查</summary>

记忆：模型在认出它已经见过的样本。

</details>

3. ▢ 指令微调通常应该用哪种损失变体？

<details markdown="1"><summary>检查</summary>

仅补全部分的损失。提示词位置被屏蔽为 `-100`，所以只有助手的回复被打分。

</details>

## 要点

### 令人不舒服的比例

如果你的时间有限，就把它花在数据上。一个平庸的数据集和一个好数据集之间的差距，比秩 8 与秩 128 之间的差距大，比 LoRA 与 DoRA 之间的差距大，也比你能调的大多数东西都大。超参数一目了然，调起来也让人满足，所以它们吸走的注意力，与它们的效果不成比例。

LIMA 的结果是对此最尖锐的公开陈述：少量精心挑选的样本，大约一千个的量级，就产生了很强的遵循指令的能力，这支持了一种观点：监督微调主要教的是*格式和风格*，而能力来自预训练。把具体的数字当作与设置有关；认真对待它所指的方向。

### 微调教得好的，与教得差的

| 教得好 | 教得差 |
|---|---|
| 输出格式和结构 | 关于世界的新事实 |
| 语气、语域、领域的口吻 | 原本不具备的推理能力 |
| 始终遵循某个 schema | 任何需要最新信息的东西 |
| 狭窄的分类和抽取 | 只被提到一次的长尾知识 |
| 工具调用和函数的语法 | 算术和精确的计算 |

右边那一列，就是[第 27 课](0027-when-not-to-fine-tune.md)存在的原因。为灌入事实而构建的数据集，做的正是微调最不擅长的事，而每个事实都需要许多多样的样本才能记住，到了那个地步，检索更便宜、更准确，也可以更新。

### 设计样本

**匹配部署时的分布。** 你的训练输入应该看起来像真实的输入。干净、格式规整、长度一致的训练提示词，会产出一个在生产中遇到的杂乱现实上退化的模型，而你的留出划分，取自同一个干净的池子，不会向你发出警告。

**有意地包含困难的情形。** 含糊的输入、边缘情形，以及正确答案是拒绝或“信息不足”的情形。如果每个训练答案都是自信而完整的，你训练出来的就是自信而完整，包括在不该如此的输入上。

**格式要保持一致。** 如果你的样本一半以句号结尾，一半不是，模型学到的就是这种不一致。你留下的每一个任意的变化，都是花在噪声上的容量。

**让输出成为范例。** 模型模仿它的目标。由差强人意的答案组成的数据集，只会产出差强人意的答案，任何超参数都挽回不了。

**变化表面，而不是实质。** 同一个请求的多种措辞，教的是对措辞的稳健性。多个近乎相同的样本，教的是记忆。

### 去重

近似重复，是拼装出来的数据集里最常见的严重缺陷，它们一次造成两种伤害：把重复内容所教的东西权重过高，以及，如果重复项落在你划分的两侧，留出集的分数度量的就是回忆，而不是泛化。

仅做精确匹配的去重是不够的。先用归一化后的哈希，再用 MinHash 或嵌入距离这样的相似度度量来找近似重复。要在划分*之前*做，而不是之后。

### 规模与均衡

一个粗略的参照，不是规则：

| 样本数 | 现实的目标 |
|---|---|
| 50 到 200 | 风格、语气、固定的输出格式 |
| 500 到 2,000 | 范围狭窄、定义明确的任务 |
| 5,000 到 50,000 | 宽泛的任务，或同时具备几种能力 |
| 100,000+ | 对适配器来说收益递减；考虑这到底是不是一个任务 |

凡有类别之处，不平衡就会变成偏见。一个 90% 都是同一类的数据集，教模型去猜那一类。要么把它平衡，要么在你的指标里把不平衡考虑进去，见第 23 课。

### 合成数据

用更强的模型来生成训练数据，是标准做法，也有效，并有两个具体的隐患。

**继承来的错误。** 生成器的错误和偏见成了你的训练目标，而且它们流畅、一致，这让它们很难靠略读发现。要抽样并阅读。

**分布塌缩。** 生成的数据往往比真实数据更一致：相似的结构、相似的长度、相似的语域。你训练出来的模型，能干净地处理一个狭窄的切片，对真实的变化却处理得很差。尽可能用真实的输入来为生成播种，并有意地变化提示词。

另外：检查你用来生成数据的那个模型的许可和条款。输出能否用来训练另一个模型，是实际的约束，而不是形式。

### 格式

把机制做对，一次到位：

- 通过模型自己的聊天模板来渲染（第 3 课）。用 `repr` 验证。
- 屏蔽提示词位置，除非你有意要让它们被打分。
- 包含回合结束 token，否则模型学不会停下来。
- 检查 token 长度的分布，并根据它的高百分位设置 `max_length`，不要用最大值，也不要靠猜。
- 确认截断没有把答案拦腰截断。被悄悄截断的目标，会教模型在句子中间停下。

## 练习

1. ▢ 你想让模型了解公司的 400 个产品 SKU。微调数据集是合适的工具吗？

<details markdown="1"><summary>检查</summary>

不是。那些是事实，而微调灌入事实并不可靠：每个事实都需要许多多样的样本，结果无法验证，目录一变就过时了。

检索才是合适的工具：准确、可引用，更新靠的是编辑一份文档，而不是重新训练。微调在这里*能*有用地教的，是呈现产品信息的格式。

</details>

2. ▢ 你所有的训练提示词，都是干净、标点规范的句子。生产环境的输入简短，满是错别字。会发生什么，为什么你的留出集抓不到？

<details markdown="1"><summary>检查</summary>

模型在干净的输入上表现良好，在真实的输入上退化，因为它从未见过真实的输入。

你的留出划分取自同一个干净的池子，所以带着同样的缺陷。它度量的是在错误分布上的表现，并报告成功。补救办法，是用取自实际部署流量的训练和评测数据。

</details>

3. ▢ 为什么要在划分之前去重，而不是之后？

<details markdown="1"><summary>检查</summary>

因为横跨划分两侧的一对重复，会把一个训练样本放进留出集。留出集的表现于是度量的是记忆，却被报告成泛化，这是让你对一次微调自欺欺人的最有效办法。

划分之后再去重，会让跨划分的重复对原样保留，而那恰恰是要紧的情形。

</details>

4. ▢ 哪种数据集缺陷最可能产出一个永远不会说“我不知道”的模型？

    - a) 严重偏向某一个类别的类别不平衡
    - b) 每一个答案都是自信而完整的
    - c) 近似重复的样本出现在划分的两侧
    - d) token 长度分布有很长的长尾

<details markdown="1"><summary>检查</summary>

**b)** 每一个答案都是自信而完整的。

模型模仿它的目标。没有任何恰当的不确定或拒绝的样本，自信而完整就是它所见过的唯一行为，包括在不支持它的输入上。

</details>

5. ▢ 说出合成数据的两个隐患，各给一个缓解办法。

<details markdown="1"><summary>检查</summary>

继承来的错误：生成器的错误变成了流畅、一致的训练目标。缓解办法是抽取并阅读真实的一小部分，并在存在任何真值的地方，对照真值验证。

分布塌缩：生成的数据比真实数据更一致。缓解办法是用真实的输入为生成播种，并有意地变化生成时用的提示词。

</details>

6. ▢ 你的数据集的 token 长度从 50 到 8000，第 95 百分位是 1200。你把 `max_length` 设成多少，检查什么？

<details markdown="1"><summary>检查</summary>

大约 1200 到 1500。设成 8000，几乎每个样本都会把激活内存浪费在填充上；设成 512，则会截断相当大的一部分。

然后检查截断对超出限制的样本究竟做了什么。如果它把答案拦腰截断，你就是在教模型在句子中间停下，所以要么提高限制，要么有意地丢掉这些样本。

</details>

## 实战练习

- [ ] 把你的数据集里二十个样本，经聊天模板解码，完整地读一遍。记下你发现的每一处不一致。
- [ ] 在划分之前，对整个集合运行近似重复检测。记录你找到了多少，并把它们去掉。
- [ ] 画出 token 长度的分布，并据此挑选 `max_length`。检查三个会被截断的样本。
- [ ] 明天：加入十个有意设计的困难样本：含糊的、边缘情形的，或者正确答案是拒绝的。
