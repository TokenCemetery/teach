# 第 24 课：回归测试集

**使命关联:** “构建一个能在发布前抓住退步的评测”是使命自己的措辞。这一课就是那一课。
**主要来源:** [论文：“An Empirical Study of Catastrophic Forgetting in Large Language Models During Continual Fine-tuning”，Luo 等，arXiv:2308.08747](https://arxiv.org/abs/2308.08747)
**前置知识:** [第 23 课](0023-metrics-that-mean-something.md)、[第 22 课](0022-contamination-and-held-out-design.md)

## 热身

1. ▢ 为什么损失不适合作为决策的依据？

<details markdown="1"><summary>检查</summary>

它给与某一个参考续写的一致程度打分，惩罚正确的替代答案，奖励流畅的错误。用它来选检查点，而不是做决策。

</details>

2. ▢ 模型评判者有哪两种有文献记载的偏差，各自如何缓解？

<details markdown="1"><summary>检查</summary>

位置偏差：随机化顺序，两种顺序都评测。冗长偏差：在长度匹配的条件下比较，或者指示评判者不考虑长度。

</details>

3. ▢ 为什么你任务的留出集对灾难性遗忘是盲的？

<details markdown="1"><summary>检查</summary>

它取自你任务的分布，所以无法观察到这个分布之外的能力的退化。

</details>

## 要点

### 它存在，是为了抓住这种失败

微调把权重推向你的任务。没有得到强化的能力可能退化，这就是**灾难性遗忘**。实证文献发现，在对语言模型做持续微调时，它不是罕见的边缘情形：包括遵循指令在内的通用能力会可度量地下降，而且这种效应可能随模型规模增大，而不是缩小。

危险的地方在于，**你已经在看的每一个数字都朝着正确的方向走。** 训练损失下降，你的留出集任务指标改善，你的探针看起来不错，而模型在你从未度量过的事情上变差了。你发布了，而报告来自你的评测看不到的方向。

留出集度量的是你有没有学会任务。回归测试集度量的是你有没有弄坏别的东西。**它们是不同的仪器，你两个都需要。**

### 里面放什么

四个类别。四个都要，不是挑着选。

**1. 通用的遵循指令。** 它还能遵循与你的任务毫无关系的普通指令吗？总结点什么，回答一个通用的问题，遵循一个多步骤的请求。

**2. 格式与行为的合规。** 它还遵守系统提示词吗？被要求时仍能产出有效的 JSON 吗？该停的时候仍会停吗？在某一种严格格式上训练的模型，有时会失去产出其他任何格式的能力。

**3. 安全与拒答行为。** 如果基础模型拒绝过某些请求，微调后的模型还拒绝它们吗？**在良性数据上微调，可能会附带降低安全对齐。** 这是有文献记载、被反复复现的结果，而不是假设。如果你的对齐行为是从指令模型那里继承来的，那你就继承了检查它是否保留下来的责任。

**4. 相邻的能力。** 你没有训练的、与你的任务相近的东西。在英文客服工单上微调的？检查另一种语言。在一种文档类型上微调的？检查另一种。

### 构建它

小巧、固定，由人来读。

```text
regression/
├── instruction-following.jsonl   # 20 general instructions
├── format-compliance.jsonl       # 20 schema and system-prompt cases
├── safety.jsonl                  # 20 cases the base refused
├── adjacent.jsonl                # 20 near-task, untrained cases
└── baseline/                     # base model outputs, committed
```

总共八十个样本。这是刻意设得小的：足以抓住真正的退步，又小到真的会有人去读这些差异。

关键的、常被遗漏的一步：**在训练之前记录基础模型的输出，并提交。** 退步是一种*变化*，所以你需要“之前”。没有存下的基线，你就只能拿对模型过去行为的记忆来比较，那不是证据。

```python
# Run once, before any training. Commit the result.
for case in regression_cases:
    out = base_model.generate(**tok(case["prompt"]), do_sample=False, max_new_tokens=256)
    baseline[case["id"]] = tok.decode(out[0], skip_special_tokens=True)
```

用贪心解码，这样出现差异，就意味着权重变了，而不是采样掷出了别的结果。

### 解读它

在每个候选检查点上运行这个测试集。与基线做对比。然后给每一处变化归类：

| 结论 | 含义 |
|---|---|
| 没变 | 没问题 |
| 变了，但仍然正确 | 记下来；没问题 |
| 变了，现在错了 | **退步，阻止发布** |
| 变了，现在更好了 | 额外的收获，值得弄明白 |

第三行是全部的要点。安全或遵循指令上一处明确的退步，抵得过任务指标上的几个点，因为这种失败模式是没有上限的，而增益是有上限的。

### 发现遗忘之后，如何减轻

选项大致按它们的代价排序：

1. **更少的步数，或更早的检查点。** 遗忘随训练增加。往往是最便宜的修复，通常也只损失很少的任务表现。
2. **更低的学习率。** 更小的更新，扰动更少。
3. **更低的秩，或更少的目标模块。** 可供覆盖的容量更少。
4. **混入通用的指令数据。** 在你的任务数据旁边，加入百分之几的通用遵循指令样本。有效，也是成熟的做法，付出的是数据集的纯度，而不是模型的质量。
5. **保持适配器不合并，并做路由。** 最彻底的回答：只对需要的请求应用适配器，其余一切都由未被触动的基础模型来服务。遗忘就不再相干，因为基础模型仍然在那里。见第 25 课。

第 5 项是人们忽略的，而它往往是正确的架构。如果你的微调在一个更大的产品里只服务于一个狭窄的用途，你就不需要一个什么都会的模型。

### 把它自动化

这个测试集应该在每个检查点上自动运行，一旦退步就拒绝通过。依赖于有人记得去运行的评测，会在最要紧的那一次被跳过，也就是在最后期限压力下的那一次。

## 练习

1. ▢ 为什么一个单调改善的留出集任务指标，排除不了退步？

<details markdown="1"><summary>检查</summary>

它取自你任务的分布，因此只观察你的任务。这个分布之外的能力对它是不可见的，而它们恰恰是遗忘所损害的东西。

你需要另一个单独的仪器，对准你*没有*在训练的东西。

</details>

2. ▢ 说出四个回归类别。

<details markdown="1"><summary>检查</summary>

通用的遵循指令、格式与行为的合规、安全与拒答行为、相邻的未训练能力。

安全是最常被漏掉的，而在完全良性的数据上微调，也可能降低它。

</details>

3. ▢ 你有一个回归测试集，却没有存下基线。运行它，你能得出什么结论？

<details markdown="1"><summary>检查</summary>

很少。退步是相对于先前行为的变化，所以没有先前的行为，你就无法识别它，只能孤立地评判输出，而那揭示不了细微的退化。

在训练之前记录并提交基础模型的输出。正是这一步，让这个测试集起作用。

</details>

4. ▢ 任务指标提高了 3 个点；模型不再拒绝基础模型拒绝过的某个请求。发布吗？

<details markdown="1"><summary>检查</summary>

不发布。安全上的退步，不论任务上的增益多少，都会阻止发布：下行风险是没有上限的，而三个点是有上限的。

去调查：试试更早的检查点、更低的学习率、混入通用的指令数据，或者保持适配器不合并，只把相关的流量路由给它。

</details>

5. ▢ 哪一项最彻底地消除了遗忘问题？

    - a) 把通用指令数据混入训练集
    - b) 以不合并的方式部署基础模型，并按请求路由
    - c) 降低学习率，并训练更少的步数
    - d) 降低适配器的秩和目标模块的数量

<details markdown="1"><summary>检查</summary>

**b)** 以不合并的方式部署基础模型，并按请求路由。

其余的减少的是遗忘发生的程度。路由则意味着，对你任务之外的一切，未经修改的基础模型仍然可用，所以适配后那条路径上的遗忘就不再要紧了。

</details>

6. ▢ 回归测试集为什么用贪心解码？

<details markdown="1"><summary>检查</summary>

这样与基线的差异，就能归因于权重变了，而不是采样。温度大于零时，每次运行都不同，差异就不携带任何信息。

</details>

## 实战练习

- [ ] 写 20 个回归用例，每个类别五个。至少包含一个基础模型会拒绝的。
- [ ] 在任何训练之前，用贪心方式生成基础模型的基线输出，并提交。
- [ ] 在你现有的适配器上运行这个测试集并做对比。把每一处变化归入这四种结论。
- [ ] 明天：把这个测试集接进你的训练脚本，让它在每个检查点上不用请求就自动运行。
