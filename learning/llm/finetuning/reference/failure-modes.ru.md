# Режимы отказа

Диагностическая шпаргалка. Держите её открытой во время запуска.

## Четыре проверки, прежде чем что-либо ещё

```python
# 1. Did the adapter attach?
model.print_trainable_parameters()          # compare to your arithmetic

# 2. Is the data what you think?
print(repr(tokenizer.decode(ds[0]["input_ids"])))
print(sum(1 for l in ds[0]["labels"] if l != -100), "of", len(ds[0]["labels"]), "scored")

# 3. Does loss move?                        # logging_steps=1 over 50 steps

# 4. Can it overfit two examples?           # loss → ~0 in 100 steps, or the pipeline is broken
```

Проверка 2 за одно чтение ловит несовпадение шаблона, отсутствие токенов конца хода, баги маскирования и обрезку. Это самые ценные десять секунд во всём процессе.

## Симптом → причина

![Шесть набросков потерь против шагов: плоские с шага 1, спад, который останавливается далеко выше нуля, кривые обучения и отложенных данных расходятся, и кривая отложенных разворачивается вверх, лесенка из плоских участков и резких спадов, спуск, прерванный одним всплеском, и спуск, резко обрывающийся на NaN.](images/loss-curve-shapes.svg)

Первые одиннадцать строк ниже называют кривую, а не событие, и несколько из них делят одну форму: три говорят «плоские», две говорят «почти не двигаются». Сопоставьте набросок, затем прочитайте каждую строку, которая его называет, поскольку у одной формы может быть больше одной причины. Начиная со строки двенадцать симптом наблюдался где-то ещё, в выводе, ошибке загрузки или регрессионном наборе, и кривой для сопоставления нет.

| Симптом | Вероятная причина | Проверка |
|---|---|---|
| Потери ровно плоские с шага 1 | Адаптер ни с чем не совпал | `print_trainable_parameters()` |
| Потери ровно плоские с шага 1 | Все метки `-100` | Посчитайте оцениваемые позиции |
| Потери ровно плоские с шага 1 | Скорость обучения на порядки слишком низка | Должна быть ~`1e-4` |
| Потери почти не двигаются | Имена целевых модулей неверны для этой архитектуры | `named_modules()` |
| Потери почти не двигаются | `α/r` случайно крошечное | Подняли `r`, забыли `α` |
| Потери выходят на высокое плато | Потолок ёмкости | Больше ранга или больше целей, а не больше эпох |
| Отложенные растут, обучение падает | Переобучение | Выпускать минимум на отложенных |
| Обучение → 0 быстро, отложенные растут сразу | Датасет намного мал для ёмкости | Больше данных, меньше ёмкости |
| Потери лесенкой на границах эпох | Заучивание | Меньше эпох |
| Потери всплескивают и восстанавливаются | Один патологический батч | Найдите выбросный пример |
| Потери → `NaN` | Переполнение или плохие данные | Предпочесть bf16; ниже скорость обучения; добавить прогрев |
| Отложенные подозрительно хороши | Загрязнение через разбиение | Дедупликация обучения и теста, прочитайте пары с наибольшим сходством |
| Модель никогда не прекращает генерировать | В обучающих данных нет токена конца хода | Декодируйте пример |
| Вывод игнорирует запрошенный формат | Несовпадение шаблона между обучением и обслуживанием | Сравните через `repr` |
| Ответы обрываются посреди предложения | `max_length` обрезает цели | Проверьте распределение длин |
| Ответы на вопросы, которых не задавали | Упаковка сломала маскирование потерь или границы | Проверьте, что `-100` переживает упаковку |
| Хуже в несвязанном | Катастрофическое забывание | Регрессионный набор против сохранённой базовой линии |
| Больше не отказывает на то, на что отказывала база | Регрессия безопасности | **Блокирует выпуск** |
| Слитый ≠ неслитый вывод | Баг слияния или было включено сэмплирование | Проверьте заново жадным декодированием |
| Слитая модель деградировала | Слито в квантизованную базу | Слить в полную точность, затем квантизовать |
| Адаптер не загружается | Неверная базовая модель или ревизия | Адаптер это разность; ему нужна точная база |
| Ошибки градиентов на 4-битной базе | Пропущена `prepare_model_for_kbit_training` | Добавьте её |
| Отличная оценка, плохой продакшен | Несовпадение распределений обучения и обслуживания | Обучайте на настоящих входах, а не на чистых |
| Результат пропал при повторе | Шум зёрен, эффекта никогда не было | Несколько зёрен, парное сравнение |

## Тихие сбои: нет ошибки, неверный результат

Опасный набор. Ничто не падает, всё выглядит нормально.

1. **Несовпадение шаблона** между обучением и обслуживанием.
2. **Отсутствие токена конца хода.** Обучается нормально, никогда не останавливается.
3. **Неверное маскирование потерь.** Непреднамеренное обучение на промптах.
4. **Загрязнение.** Отложенные данные измеряют заучивание, а докладывают об обобщении.
5. **Утечка по группе или во времени.** Разбиение по неверному ключу.
6. **Катастрофическое забывание.** Каждое число, за которым вы следите, улучшается.
7. **Адаптер подключён ни к чему.** Обучается, пишет потери, ничему не учится.
8. **Оценка не того артефакта, который вы выпускаете**, например оценка в bf16 и развёртывание в 4 битах.

У каждого есть конкретный шаг обнаружения выше. Ни один не объявляет о себе сам.

## Как уменьшить забывание

Сначала самое дешёвое:

1. Меньше шагов или более ранний чекпоинт
2. Более низкая скорость обучения
3. Более низкий ранг или меньше целевых модулей
4. Подмешайте несколько процентов общих инструктивных данных в обучение
5. **Оставьте адаптер неслитым и маршрутизируйте**, чтобы база осталась нетронутой, а забывание перестало иметь значение

## Гигиена сравнения

- По одной переменной за раз; зафиксируйте зерно, данные и разбиение
- Несколько зёрен, поскольку вариация часто больше эффекта
- Парное сравнение на идентичных примерах
- Сообщайте `n` и интервал, никогда голое число
- Каждый раз читайте настоящие генерации, включая неудачи

## Что записывать для каждого запуска

Базовая модель **и ревизия** · конфигурация адаптера дословно · датасет и точное разбиение · зерно · эффективный размер батча · скорость обучения и расписание · шаги · выбранный чекпоинт и число, которое это оправдало · версии библиотек · результаты оценки и регрессионного набора.
