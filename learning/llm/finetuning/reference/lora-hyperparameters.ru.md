# Гиперпараметры LoRA

Шпаргалка для решений. Точные имена параметров читайте в установленной версии библиотеки, потому что эта поверхность меняется между релизами.

## Уравнение

```text
h = W₀x + (α/r) · BAx
```

`A` случайна, `B` нулевая, поэтому `ΔW = 0` на шаге 0 и модель начинает идентичной базе.

![Вход подаётся на два пути, которые суммируются. Верхний это замороженная базовая матрица. Нижний это обученный адаптер, где A проецирует вниз в полосу шириной всего r, B проецирует обратно вверх, а результат масштабируется на альфа к r.](images/lora-bottleneck.svg)

Полоса между `A` и `B` имеет ширину `r` значений, и это единственный путь адаптера от входа к выходу. Именно это следующий раздел называет ёмкостью: повышение ранга расширяет эту полосу и ничего больше на рисунке не меняет, поэтому оно покупает выразительность почти без затрат памяти.

## Ранг

Ёмкость. Ограничивает, насколько сложное обновление способен выразить адаптер.

| Ранг | Подходит для |
|---|---|
| от 4 до 8 | Стиль, тон, формат вывода; небольшие датасеты |
| от 16 до 32 | Настоящая задача, несколько тысяч примеров |
| от 64 до 128 | Более трудные задачи, больше данных, поведение с тяжёлыми рассуждениями |
| 256+ | Приближение к ёмкости полного дообучения на больших данных SFT |

Ранг почти не стоит памяти. Его настоящая цена это риск переобучения на малых данных.

## Альфа

**Важно только `α/r`.** Соглашение `α = 2r`.

| `r` | `α` | `α/r` | |
|---|---|---|---|
| 8 | 16 | 2,0 | база |
| 16 | 32 | 2,0 | больше ёмкости, тот же масштаб |
| 16 | 16 | 1,0 | более слабое обновление |
| 64 | 16 | 0,25 | **ловушка**: ёмкость выше, влияние ниже в 8 раз |

Повышение `r` без повышения `α` *приглушает* адаптер. При ранге ≥ 64 подумайте о `use_rslora=True`, который использует `α/√r`.

## Целевые модули

| Ситуация | Цели |
|---|---|
| Значение по умолчанию для настоящей задачи | все линейные |
| Небольшой датасет (< ~1 тыс.) | только внимание, низкий ранг |
| Только стиль или тон | только внимание, низкий ранг |
| Нужны новые различения | обязательно включить MLP |
| Воспроизведение статьи | ровно их |

`"all-linear"` разрешается относительно загруженной модели, поэтому не устареет на незнакомых именах. Только внимание это абляция 2021 года, а не значение по умолчанию.

Типичные имена, но **проверяйте через `named_modules()`**:

```text
attention: q_proj  k_proj  v_proj  o_proj
mlp:       gate_proj  up_proj  down_proj
```

## Скорость обучения

| Метод | Диапазон |
|---|---|
| Адаптерное дообучение | от `1e-4` до `2e-4` |
| Полное дообучение | от `1e-5` до `5e-5` |

Перенос скорости обучения от полного дообучения в запуск с адаптером это одна из главных причин разочаровывающего первого результата. Используйте прогрев (несколько сотен шагов) и косинусное затухание.

## Прочие настройки

| Настройка | Значение по умолчанию | Примечания |
|---|---|---|
| `lora_dropout` | от 0,0 до 0,05 | Повышайте, только если потери на отложенных данных растут |
| `bias` | `"none"` | Редко решающая; усложняет слияние |
| Эпохи | от 2 до 3 | На небольших инструктивных данных; больше обычно приводит к заучиванию |
| Чекпоинтинг градиентов | включён | Почти значение по умолчанию для адаптеров |
| `use_cache` | выключен при обучении | Конфликтует с чекпоинтингом; для обучения бесполезен |

## Варианты по осям

| Ось | Метод | Помогает, когда |
|---|---|---|
| Масштабирование | rsLoRA | Высокий ранг |
| Скорости обучения | LoRA+ | Отдельные скорости для `A` и `B` |
| Инициализация | PiSSA, OLoRA | Быстрее сходимость; отказ от нулевой инициализации |
| Инициализация | LoftQ | Обучение против квантизованной базы |
| Структура | DoRA | Ранг закреплён низким по другой причине |
| Структура | AdaLoRA | Слоям нужен неравный ранг |
| Структура | VeRA | Размер адаптера это ограничивающий фактор |

**База для превосхождения:** all-linear, достаточный ранг, подобранная скорость обучения. Большинство вариантов не превосходят её больше, чем на шум зёрен.

## Квантизованная база (QLoRA)

```python
BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",             # not "fp4"
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,  # do not leave at default
)
```

Затем `prepare_model_for_kbit_training(model, use_gradient_checkpointing=True)`. Если её пропустить, получаются неустойчивые запуски или непрозрачные ошибки градиентов.

Все остальные гиперпараметры не меняются. **QLoRA это LoRA с более дешёвой базой.**

Сливайте в базу **полной точности**, никогда в квантизованную.

## Диагностика по кривой

| Обучение | Отложенные | Диагноз | Действие |
|---|---|---|---|
| ↓ | ↓ | Идёт обучение | Продолжать |
| ↓ | ↑ после провала | Переобучение | Выпускать минимум; меньше ёмкости или больше данных |
| → высоко | → высоко | Недообучение | Больше ранга, больше целей, выше скорость обучения |
| Плоские с шага 1 | Плоские | Сломано | Проверьте, что адаптер подключился и метки не все `-100` |
| `NaN` | тоже `NaN` | Переполнение | Ниже скорость обучения; добавить прогрев; предпочесть bf16 |
