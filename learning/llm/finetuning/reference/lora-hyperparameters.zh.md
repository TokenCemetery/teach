# LoRA 超参数

决策用的速查表。请阅读所安装的库版本，以确认确切的参数名，因为这块接口在不同版本之间会变。

## 方程

```text
h = W₀x + (α/r) · BAx
```

`A` 随机，`B` 为零，所以在第 0 步 `ΔW = 0`，模型一开始与基础模型相同。

![输入分成两条路径，再相加。上面一条是冻结的基础矩阵。下面一条是训练出来的适配器，A 向下投影到只有 r 宽的一条窄带，B 再向上投影回来，结果按 alpha 除以 r 缩放。](images/lora-bottleneck.svg)

`A` 和 `B` 之间的那条窄带有 `r` 个值宽，它是适配器从输入到输出唯一的通路。下一节所说的容量就是这个意思：提高秩，就是把这条窄带加宽，而图里的其余部分都没有变，这就是它几乎不花内存却能买来表达能力的原因。

## 秩

容量。限定适配器能表达多复杂的更新。

| 秩 | 适合 |
|---|---|
| 4 到 8 | 风格、语气、输出格式；小数据集 |
| 16 到 32 | 真实的任务，几千个样本 |
| 64 到 128 | 更难的任务、更大的数据、推理密集的行为 |
| 256+ | 在大型 SFT 数据上，接近全量微调的容量 |

秩几乎不花内存。它真正的代价，是小数据上的过拟合风险。

## Alpha

**只有 `α/r` 起作用。** 惯例是 `α = 2r`。

| `r` | `α` | `α/r` | |
|---|---|---|---|
| 8 | 16 | 2.0 | 基线 |
| 16 | 32 | 2.0 | 容量更大，尺度不变 |
| 16 | 16 | 1.0 | 更新更弱 |
| 64 | 16 | 0.25 | **陷阱**：容量上升，影响力下降 8 倍 |

提高 `r` 而不提高 `α`，会把适配器*调低*。在秩 ≥ 64 时，考虑 `use_rslora=True`，它使用 `α/√r`。

## 目标模块

| 情形 | 目标 |
|---|---|
| 真实任务的默认做法 | 所有线性层 |
| 小数据集（< ~1k） | 只作用于注意力，低秩 |
| 只涉及风格或语气 | 只作用于注意力，低秩 |
| 需要新的区分能力 | 必须包含 MLP |
| 复现一篇论文 | 恰好是论文所用的 |

`"all-linear"` 是对照已加载的模型来解析的，所以面对不熟悉的命名，它不会过时。只作用于注意力是 2021 年的一项消融实验，不是默认做法。

典型的名称如下，但要**用 `named_modules()` 验证**：

```text
attention: q_proj  k_proj  v_proj  o_proj
mlp:       gate_proj  up_proj  down_proj
```

## 学习率

| 方法 | 范围 |
|---|---|
| 适配器微调 | `1e-4` 到 `2e-4` |
| 全量微调 | `1e-5` 到 `5e-5` |

把全量微调的学习率照搬进适配器的运行，是第一次结果令人失望的主要原因。使用预热（几百步）和余弦衰减。

## 其他设置

| 设置 | 默认值 | 说明 |
|---|---|---|
| `lora_dropout` | 0.0 到 0.05 | 只有留出集损失在上升时才调高 |
| `bias` | `"none"` | 很少起决定作用；会让合并变复杂 |
| Epoch | 2 到 3 | 在小型指令数据上；再多通常就会记忆 |
| 梯度检查点 | 开 | 对适配器来说近乎是默认做法 |
| `use_cache` | 训练时关 | 与检查点冲突；对训练没有用 |

## 变体，按轴来分

| 轴 | 方法 | 何时有帮助 |
|---|---|---|
| 缩放 | rsLoRA | 高秩 |
| 学习率 | LoRA+ | 给 `A` 和 `B` 用不同的学习率 |
| 初始化 | PiSSA、OLoRA | 收敛更快；放弃了零初始化 |
| 初始化 | LoftQ | 针对量化的基础模型训练 |
| 结构 | DoRA | 秩因其他原因被钉在低位 |
| 结构 | AdaLoRA | 各层需要不同的秩 |
| 结构 | VeRA | 适配器的体积是起约束作用的因素 |

**要打败的基线：** 作用于所有线性层、秩足够、学习率经过调优。大多数变体超出它的幅度，都没有超过种子噪声。

## 量化的基础模型（QLoRA）

```python
BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",             # not "fp4"
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,  # do not leave at default
)
```

然后是 `prepare_model_for_kbit_training(model, use_gradient_checkpointing=True)`。跳过它，会得到不稳定的运行，或者含糊不清的梯度错误。

其他每个超参数都不变。**QLoRA 就是基础模型更便宜的 LoRA。**

合并进**全精度**的基础模型，绝不要合并进量化的那个。

## 按曲线诊断

| 训练 | 留出集 | 诊断 | 做法 |
|---|---|---|---|
| ↓ | ↓ | 在学习 | 继续 |
| ↓ | 先降后 ↑ | 过拟合 | 发布最小值处的检查点；更小的容量或更多数据 |
| → 高位 | → 高位 | 欠拟合 | 更大的秩、更多的目标、更高的学习率 |
| 从第 1 步起平坦 | 平坦 | 坏了 | 检查适配器已挂上，且标签不全是 `-100` |
| `NaN` | 也是 `NaN` | 溢出 | 降低学习率；加预热；优先用 bf16 |
