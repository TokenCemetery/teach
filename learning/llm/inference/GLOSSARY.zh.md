# 推理服务术语表

为已训练好的模型提供服务时使用的规范术语：服务器在内存中保存什么，以及它在延迟和吞吐量上有哪些可调的杠杆。

## 术语

**注意力汇聚点（Attention sink）**:
序列最前面的几个 token 无论实际内容是什么，都会获得异常大的注意力分数。所以把它们从滑动窗口缓存中丢掉，会导致质量崩溃，而不是平缓地丢失旧上下文。只要在通常的滑动窗口之外，把这几个初始 token 的 KV 条目永久保留在缓存里，就能恢复完整注意力的大部分表现（StreamingLLM 技术）。
_避免使用_: 以为丢掉任何旧 token 都会造成同样的损害（只有最初的“汇聚点”token 带有这种异常大的权重；窗口之外的其他旧 token 丢掉后，质量是平缓下降，而不是崩溃）

**冷启动（服务，Cold start (serving)）**:
从自动扩缩容器决定增加一个副本，到这个副本真正能够处理请求之间的间隔。它主要取决于把大模型的检查点加载进内存所需的时间，这可能要几十秒，远远超过生成单个 token 的时间。
_避免使用_: 把它当作请求排队问题（调度器或路由器对它没有影响；它完全由检查点的大小和它必须经过的存储路径决定）

**约束（引导）解码（Constrained (guided) decoding）**:
在采样之前，先把所有会违反所需结构（合法的 JSON、某种语法）的 token 屏蔽掉，使输出的结构由构造本身来保证，而不只是被鼓励。做法是把语法重新表述为有限状态机，并预先一次性算好一份索引，记录从每个状态出发哪些 token 是合法的，这样每个 token 的开销就很小。
_避免使用_: 在生成完成之后再检查输出是否合法（这什么也保证不了，因为模型始终可以自由地采样出非法 token；在采样前屏蔽，才使这个保证成为结构性的）

**每百万 token 成本（Cost per million tokens）**:
GPU 的每小时租用成本，除以实测的吞吐量（token/秒，换算成 token/小时），再放大到一百万个 token。它由第 6 课的批大小权衡所得出的同一个实测吞吐量推导而来，而不是引用供应商在另一种工作负载的批大小下测得的单 token 标价。
_避免使用_: 供应商给出的固定单 token 价格（吞吐量，因而每 token 的成本，取决于测量时的批大小和工作负载，换一种配置就不再适用）

**草稿模型（Draft model）**:
一个小而便宜的模型（或者 n-gram 匹配这类非模型机制，或者装在目标模型自身上的额外头），它提出若干个候选的下一个 token，交给目标模型在一次并行计算中验证，而不是由目标模型自己一个一个地生成。
_避免使用_: 目标模型的一个更小、质量更低的替代品（草稿模型的输出从不被直接使用；它只会被目标模型验证，并在必要时被纠正）

**错误预算（Error budget）**:
1 减去服务级别目标：在服务被认为不符合该目标之前，允许未达标的量。单个未达标的请求本身不是问题；要看的是未达标的速率，是否比 SLO 的测量窗口所允许的更快地消耗着这份预算。
_避免使用_: 把任何一次未达标的测量都当作问题（预算的存在，正是因为一定比例的未达标是预期之中、可以容忍的；只有相对于窗口的消耗速率才要紧）

**KV 缓存（KV cache）**:
为每个已生成的 token 在每一层存下的键向量和值向量，保存它们是为了让服务器永远不必为后面的 token 重新计算它们。它的大小随序列长度线性增长，在服务中常常成为内存瓶颈，而不是模型自身的权重。
_避免使用_: 注意力缓存（attention cache）、键值存储（key-value store）

**KV 缓存感知路由（KV-cache aware routing）**:
一种集群级的请求路由策略：把新请求发给已持有该请求最高缓存命中率的那台服务器，而不是只按负载来路由（轮询、最少连接数）。它把前缀缓存在单台服务器上的收益，扩展到多服务器集群，办法是让路由决策本身知道匹配的缓存在哪里。
_避免使用_: 普通的负载均衡（轮询或最少连接数完全忽略缓存的局部性，可能把一个适合命中缓存的请求发给必须从头重做预填充的服务器）

**受内存带宽限制（Memory-bandwidth-bound）**:
一种计算，其主要开销在于把数据（比如模型权重）从内存搬到计算单元，而不是数据到达之后所做的算术。普通的自回归解码受内存带宽限制，这恰恰使推测解码能够在一次计算中验证多个候选 token，而开销大致只相当于生成一个 token。
_避免使用_: 受算力限制（compute-bound）（那是相反的状态，算术占主导；把二者混为一谈，就看不出为什么额外的验证工作在解码阶段几乎是免费的）

**流水线气泡（Pipeline bubble）**:
流水线并行的设置中，设备在处理一个批次的开始（流水线填充时）和结束（流水线排空时）所花的空闲等待时间，因为在这两个时刻并不是每个设备都有活干。把一个批次拆成更多的微批次，可以缩小这部分空闲占比，但永远消除不了它。
_避免使用_: 以为微批处理能把气泡完全消除（它只是相对于总工作量缩小了空闲占比；无论微批次有多少，启动和排空的延迟始终存在）

**流水线并行（Pipeline parallelism）**:
把模型按顺序排列的层划分成若干连续的组，分别放在不同的设备上，使数据按层在单个设备上运行时的同一顺序流过各个设备。通信只发生在一个设备的层组与下一个设备的层组交界处，所以它能容忍比张量并行所需更慢的设备间链路，也能跨越多个节点。
_避免使用_: 切分单层内部的计算（那是张量并行；流水线并行从不切分单层内部发生的事，只决定哪些层放在哪里）

**前缀缓存（Prefix caching）**:
在原本互不相关的请求之间，复用共享前缀已算好的 KV 缓存（共同的系统提示词、被反复查询的文档、对话中较早的轮次）。它用的是 PagedAttention 在单个请求的并行样本之间共享块的同一种机制，只是扩展到了请求之间。它只加快预填充，解码时间不受影响。
_避免使用_: 以为它也能加快解码（它只是对匹配上的前缀跳过冗余的预填充计算；之后生成新 token 的开销，无论有没有它都完全一样）

**RoPE 缩放（RoPE scaling）**:
通过重新缩放旋转位置嵌入编码 token 之间距离的方式，把模型能处理的上下文长度扩展到训练长度之外，而不必从头重新训练（YaRN 的做法：对高频维度少缩放一些，对低频维度多缩放一些）。它丝毫不改变需要缓存多少个 token 的键和值；用这种方式处理的更长上下文，仍然要付出 KV 缓存通常的线性增长的全部代价。
_避免使用_: 以为它能减少 KV 缓存内存或给它设上限（它只是扩展了可用的最大上下文长度；那段更长上下文的缓存，仍然和没做任何缩放时一样增长）

**SLI（服务级别指标，service level indicator）**:
从原始的导出指标中挑出来的一个定量的、与用户相关的比率，例如 TTFT 低于规定阈值的请求所占的比例，它是从用户的体验出发来表述的，而不是从服务器的内部状态。
_避免使用_: 原始指标的直方图本身（直方图是测得的数据；SLI 则是从中挑出来、用来对照目标的那个与用户相关的特定比率）

**滑动窗口注意力（Sliding-window attention）**:
限制每个 token 最多只关注前面固定数量 `W` 个 token，而不是到目前为止的整个序列，并配上一个滚动缓冲区缓存，里面永远只保存 `W` 个 token 的键和值。无论序列实际增长到多长，它都把序列的 KV 缓存限制在一个恒定的大小，这一点不同于 RoPE 缩放那种不变的线性增长。
_避免使用_: 以为它能像 RoPE 缩放那样扩展模型可以有效看到的范围（它是给缓存设上限，并把直接注意力限制在最后 `W` 个 token；超出这个范围的内容，只能通过层层堆叠间接触达，而且没有注意力汇聚点的话，单靠它会出现质量崩溃）

**SLO（服务级别目标，service level objective）**:
针对某个 SLI 设定的目标，例如“在滚动的 28 天内，99% 的请求 TTFT 低于 300ms”。剩下的部分，即 1 减去 SLO，就是错误预算。
_避免使用_: 一次性的基准测试结果（第 16 课中单次测得的 p99 是一个快照；SLO 是对照持续导出的指标始终坚持的目标）

**推测解码（Speculative decoding）**:
先廉价地起草若干候选的下一个 token，再通过目标模型的一次并行前向计算把它们全部验证一遍，接受猜对的，对猜错的重新采样，使最终的输出分布与单独运行目标模型时完全一致。这是一个纯粹的延迟杠杆，不需要在质量上做取舍。
_避免使用_: 一种近似技术（它只改变生成所需的昂贵前向计算的次数，从不改变生成出来的内容）

**张量并行（Tensor parallelism）**:
把单层内部的大矩阵乘法（Transformer 的注意力块和 MLP 块）按列或按行切分到多个设备上，每个设备并行地计算自己的那一份，再在每一层内部的特定位置通过一次通信步骤把真实结果合并起来。它需要快速的互连（如 NVLink），因为这个合并发生在关键路径上，每一层、每一次前向计算都要做。
_避免使用_: 把整层整层地切分到不同设备上（那是流水线并行；张量并行切分的是单层内部的计算，从不把整层分配给不同的设备）
