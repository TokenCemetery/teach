# 第 2 课：指令数据与聊天模板

**使命关联:** “写出一个对非助手 token 做损失掩码的 SFT 训练循环，并解释不加这个掩码训练出来的聊天模型会出什么问题”是“成功的标准”下的第一条。本课讲 SFT 数据长什么样，以及它的各个片段是如何标记的；掩码本身留到第 3 课。
**主要来源:** [论文：“Llama 2: Open Foundation and Fine-Tuned Chat Models”，Touvron 等，2023](https://arxiv.org/abs/2307.09288)
**前置知识:** [第 1 课](0001-what-post-training-buys.md)

## 热身

1. ▢ 什么是对齐税？Ouyang 等人发现什么办法可以部分抵消它？

<details markdown="1"><summary>检查</summary>

在某些公开的 NLP 基准上度量到的表现下降，它伴随着后训练带来的对齐收益而出现。把 PPO 的更新与提高原始预训练数据似然的更新混合起来（PPO-ptx），找回了大部分损失的表现，同时没有放弃偏好收益。

</details>

## 要点

### SFT 数据实际长什么样

**监督微调**（SFT）的数据是一组提示词与回答的配对，正是第 1 课的第 1 步所描述的形态。Touvron 等人给出了 Llama 2 自己的 SFT 标注中的真实例子：一个提示词要求写一首关于元素周期表前十个元素的诗，配的是标注员写的、回应它的一首诗；另一个提示词要求一段刻意刻薄的“吐槽”（roast），配的是标注员写的拒绝，并解释了为什么拒绝。二者都只是一个提示词，加上标注员希望模型学会为它生成的那条确切回应。

### 标出一个片段在哪里结束、下一个从哪里开始

在这种数据上训练，意味着把许多提示词与回答的配对拼接成训练语料，而模型需要某种办法分辨提示词在哪里结束、回答从哪里开始，因为纯文本本身并不会标出这条边界。Touvron 等人描述的正是这一点：“用一个特殊 token 来分隔提示词片段和回答片段。”这就是后来所说的**聊天模板**的萌芽：用特殊 token，以固定、一致的方式标出角色边界（提示词片段、回答片段，以及在多轮对话中的系统消息和每个后续轮次），使同样的结构在训练中每次都出现，并且在服务时可以被精确复现。

### 为什么这条边界在训练和服务时必须一致

聊天模板不只是格式上的方便；它是模型实际训练内容的一部分。模型学会了把标记“回答从这里开始”的特殊 token，与真正产生训练中紧随这些 token 之后的那种回答联系起来。用不同的模板、不同的特殊 token、不同的角色顺序，或者缺少系统消息的约定来服务这个模型，就是让它面对一种它从未见过与所学行为配对出现的结构，结果是它的行为变差或变得不可预测。在服务时复现训练时那一份完全相同的模板，不是可有可无的收尾工作；它是正确使用这个模型的一部分。

### 多轮是同一个想法的重复

多轮对话把同样的片段标记思路扩展到不止一次交流：先是系统消息（如果有的话），然后是交替的用户轮次和助手轮次，每一个都用同一类特殊 token 标记，就像分隔任何单个提示词与它的回答那样。多轮的情形并没有发明任何新东西；它是同一个边界标记原则，只是按每个轮次而不是按每个样本应用一次。

## 练习

1. ▢ 为什么如果没有某种标记，模型仅凭纯粹拼接起来的文本，就无法学会提示词在哪里结束、回答从哪里开始？

<details markdown="1"><summary>检查</summary>

因为纯文本里没有任何内在的信号，能把“这是被问的内容”与“这是我应当学着生成的回答”区分开；没有标记，这两者之间的边界就不会在训练数据本身的任何地方得到表示。

</details>

2. ▢ 一个团队用一种聊天模板微调了模型，却在生产中用另一种模板（标记角色边界的特殊 token 不同）来服务它。最可能的后果是什么？

    - a) 没有影响；模型完全忽略格式
    - b) 模型的行为变差或变得不可预测，因为它面对的是一种它从未见过与训练中所学行为配对出现的结构
    - c) 模型会自动检测并适应新模板
    - d) 只有系统消息受到影响；用户轮次和助手轮次仍然正常工作

<details markdown="1"><summary>检查</summary>

**b)** 才是实际的后果：聊天模板是模型训练内容的一部分，而不是装饰性的包装，所以不匹配就是呈现一种没训练过的结构。(a)、(c) 和 (d) 都假定模型对模板不匹配有一种稳健性，而训练并没有给出任何理由让人这样期待。

</details>

3. ▢ 多轮对话的聊天模板，与 Touvron 等人为 SFT 描述的单个提示词与回答的模板是什么关系？

<details markdown="1"><summary>检查</summary>

它们是同一个片段标记的思路，被重复应用：如果有系统消息就先放系统消息，然后依次是每个用户轮次和助手轮次，每一个都用与分隔单个提示词和回答相同的那类特殊 token 来标记，而不需要一种根本不同的机制。

</details>

## 实战练习

- [ ] 找到你能用到的某个开源模型的聊天模板（许多都以模板文件的形式发布，或有直接的文档），并找出它用来标记系统消息、用户轮次和助手轮次的特殊 token。
- [ ] 阅读 Touvron 等人的两个 SFT 标注示例（链接见上，表 5），并结合“吐槽”被拒绝的例子，用你自己的话写出，一个好的 SFT 回答与一个只是听起来合理的回答，区别在哪里。
- [ ] 明天：不要往后看，给第 3 课写一句预测：如果聊天模板把提示词和回答不留空隙地拼成一个序列，而训练在整个序列上使用普通的下一个 token 预测损失，那么对提示词 token 本身，模型会开始学着去做什么不该做的事？
