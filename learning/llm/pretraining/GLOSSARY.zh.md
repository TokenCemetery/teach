# LLM 预训练术语表

从随机初始化开始、大规模训练一个模型时使用的规范术语：数据和算力预算由什么构成，以及内存和计算如何分摊到许多设备上。

## 术语

**激活检查点（Activation checkpointing）**:
在前向计算中丢弃中间激活值，到反向计算时再重新算出来，用额外的计算换取更低的内存占用。
_避免使用_: 梯度检查点（gradient checkpointing，实践中更常见的叫法，但它检查点化的是激活值，而不是梯度，这个不准确的名字会让人误解究竟拿什么换什么）

**算力最优（Compute-optimal）**:
在参数量与训练 token 数的权衡中，使固定训练算力预算下损失最小的那个点，与之相对的是：用比这个点所暗示的更少的 token 去训练的更大模型。
_避免使用_: 最优（optimal，没有说明是对什么而言的最优；务必与“算力”或“推理”搭配，说明固定的是哪一种预算）

**数据并行（Data parallelism）**:
把一个训练批次拆分到多个设备上，每个设备都持有模型的完整副本，各自独立计算梯度，并在优化器步骤之前通过一次 all-reduce 同步梯度。
_避免使用_: 分布式训练（distributed training，数据并行只是其中一种形式；这个笼统的说法没有指明被拆分的是哪种资源）

**去重（Deduplication）**:
在分词之前，把训练语料中近似重复或完全重复的文档删除，因为重复的文本是造成记忆和算力浪费的主要原因。
_避免使用_: dedup（非正式场合可以，但概念一旦确定，术语表就写出全称）

**梯度裁剪（Gradient clipping）**:
在优化器步骤使用梯度之前，按比例缩放梯度，使它的全局范数永远不超过选定的阈值，这样无论是什么产生了异常大的梯度，单次更新的幅度都有上限。
_避免使用_: 梯度截断（gradient clamping，截断通常是指对每个值单独设上限；这里的裁剪是用同一个系数缩放整个梯度向量，以限制它的范数）

**学习率预热（Learning rate warmup）**:
在训练最初的一小段时间里，把学习率从接近零逐步升到预定的最大值，而不是一开始就用最大值，让网络最缺乏信息的早期更新对权重的影响小一些。
_避免使用_: burn-in（预烧，其他领域里表示稳定期的术语；本工作区的预热专指学习率的爬升）

**损失尖峰（Loss spike）**:
训练过程中训练损失突然、急剧地升高，通常由数值上不稳定的批次或累积的优化器状态漂移引起，要把它与普通噪声区分开，看损失能否自行恢复。
_避免使用_: 发散（divergence，发散是损失尖峰没有恢复时的结局；二者不是同一个事件）

**流水线并行（Pipeline parallelism）**:
把模型的层拆分到多个设备上，每个设备持有堆叠中连续的一段，并把激活值传给下一个设备，让多个微批次流水线式地通过，使每个设备都保持忙碌。
_避免使用_: 模型并行（model parallelism，本术语和张量并行都归属的更宽泛的说法；一旦需要区分，就用具体的那一个）

**缩放定律（Scaling law）**:
模型的损失与训练所用的算力、参数量或数据量之间，经验上的幂律关系，用来在花钱之前预测一次训练运行的损失。
_避免使用_: 缩放曲线（scaling curve，缩放定律是拟合出的关系；曲线只是它的一幅图）

**张量并行（Tensor parallelism）**:
把单层的权重矩阵拆分到多个设备上，使一次矩阵乘法被算成各个设备部分乘积之和，代价是每个被拆分的层都要多一个通信步骤。
_避免使用_: 模型并行（model parallelism，本术语和流水线并行都归属的更宽泛的说法）

**每参数 token 数比（Tokens-per-parameter ratio）**:
训练 token 数除以模型参数量，这个单一的数字是制定算力最优训练计划时所围绕的核心。
_避免使用_: 数据与模型之比（data-to-model ratio，文献中对其倒数的用法不一致；本工作区始终指 token 数除以参数量）

**ZeRO 阶段（ZeRO stage）**:
在数据并行设备之间分片的状态，由少到多共三个级别：优化器状态（阶段 1），优化器状态和梯度（阶段 2），或优化器状态、梯度和参数（阶段 3），每一级都用更多的通信换取更低的单设备内存。
_避免使用_: FSDP（FSDP 是 PyTorch 对 ZeRO 阶段 3 式分片的实现；ZeRO 是底层技术，本工作区在讨论思想时用这项技术的名字，在讨论 API 时用 FSDP）
