# LLM 预训练

能够规划并运行一次从随机初始化开始的预训练任务：搭建数据管线，训练分词器，针对给定的参数量选出算力最优的 token 预算，让一次持续数天的分布式训练既不发散、也不因节点故障而停滞，并向那些本来会直接微调一个现成基础模型的人，为这整套选择辩护。

**最新课程：** [0024. 评审别人的训练运行配置](lessons/0024-reviewing-someone-elses-training-run-config.md)

## 成功的标准

- 从原始来源构建一份经过去重和质量过滤的预训练语料，并说清每个过滤步骤删掉了什么、为什么删。
- 训练一个分词器，并就词表大小对序列长度和嵌入表大小的影响，为所选的词表大小辩护。
- 给定参数量和算力预算，算出算力最优的 token 数，并针对 Kaplan 式的训练不足方案为它辩护。
- 解释 ZeRO/FSDP 分片的是什么，为什么单靠数据并行会在算力耗尽之前先耗尽内存，以及张量并行或流水线并行在什么时候值得付出它们的通信成本。
- 读懂一次训练运行的损失曲线和梯度范数，并判断一个尖峰是可以恢复的，还是意味着要从更早的检查点重新开始。
- 为一次持续数天的运行设计检查点方案，使它在节点故障后丢失的进度不超过几分钟。
- 判断一项给定的任务应该用预训练、继续预训练，还是微调一个现成的基础模型，并从成本上为这个选择辩护。

## 约束

- 贴近框架，而不是与框架无关。分布式训练技术（ZeRO 分片、张量并行和流水线并行）已经足够稳定，所以课程会点名所描述的真实库和 API，这与 `llm/agents` 面对变化更快的接口时使用与服务商无关的伪代码不同。
- 没有哪一课会训练前沿规模的模型。练习的规模都很小（在少数几块 GPU 上训练 GPT-2 规模的模型，或者模拟的多节点环境），再由此推理，在所引论文描述的规模上会有什么不同。
- 假定你已学过 `llm/transformers`：注意力机制、训练循环、交叉熵损失、AdamW、混合精度和梯度裁剪是前置知识，不会再复习。
- 假定你能使用多块 GPU（哪怕只有两块，或者用多进程的 CPU 来模拟集合通信操作）来做分布式训练的练习。

## 范围之外

- Transformer 架构本身、交叉熵损失、反向传播、AdamW、混合精度和梯度裁剪：见 [`llm/transformers`](../../llm/transformers/)。当那个训练循环需要在数百块 GPU 上、针对数万亿个 token 运行时，本系列才接手，不会更早。
- 用 LoRA、QLoRA 或 DoRA 适配一个现成的基础模型：见 [`llm/finetuning`](../../llm/finetuning/)。预训练从随机权重开始，而不是从检查点开始，这是改变模型权重的两种方式，二者是并列关系，而不是一个包含另一个。
- 服务时的并行与量化：见 [`llm/inference`](../../llm/inference/)。本系列讲的是训练时的并行（梯度同步，激活值和优化器的分片），不讲服务。
- 评测方法与留出数据的设计：见 [`llm/evals`](../../llm/evals/)。这里只把它当作预训练运行需要的那一项能力来讲，即在运行中途验证一个检查点，并且是链接过去，而不是重述。
- 把预训练好的模型对齐成助手：见 [`llm/post-training`](../../llm/post-training/)。
- 把蒸馏当作一种训练信号，包括预训练期间使用教师的分布：见 [`llm/distillation`](../../llm/distillation/)。那个系列讲的是损失和数据的选择；运行预训练任务则留在这里。

## 学习路线

共十个阶段，从没有任何先验知识到资深的判断力。它不是课程清单：一个阶段包含若干课程，边界并不严格。

| 阶段 | 课程 | 内容 | 完成的标志 |
| --- | --- | --- | --- |
| 1. 数据管线 | 0001 至 0002 | 来源、去重、质量过滤 | 能从原始来源构建一份经过过滤和去重的语料，并为每一步删掉了什么辩护 |
| 2. 分词器训练 | 0003 至 0004 | 从零实现 BPE 和 SentencePiece，词表大小的权衡 | 能训练一个分词器，并为词表大小的选择辩护 |
| 3. 缩放定律 | 0005 至 0006 | Kaplan 对比 Chinchilla，算力最优的 token 与参数之比 | 给定算力预算，能推导出算力最优的 token 数并为它辩护 |
| 4. 数据并行 | 0007 至 0008 | 梯度 all-reduce，为什么单靠它无法继续扩展 | 能说清为什么单靠数据并行会在算力耗尽之前先耗尽内存 |
| 5. 切分内存 | 0009 至 0011 | ZeRO 阶段 1 到 3、FSDP、激活值和优化器的分片 | 能说清每个 ZeRO 阶段分片的是什么，以及它在通信上的代价 |
| 6. 模型并行 | 0012 至 0014 | 训练中的张量并行和流水线并行 | 能判断张量并行或流水线并行在什么时候比单纯分片更值得付出通信成本 |
| 7. 大规模下的数值与稳定性 | 0015 至 0017 | 大规模混合精度、损失尖峰、梯度范数、预热与衰减调度 | 给定一条损失曲线，能判断尖峰是可以恢复的，还是需要从更早的检查点重新开始 |
| 8. 检查点与容错 | 0018 至 0019 | 保存并恢复一次持续数天的运行，挺过节点故障 | 能设计一套检查点方案，使节点故障后丢失的进度有上限 |
| 9. 监控一次训练运行 | 0020 至 0021 | 损失曲线、周期性的评测检查点，链接到 `llm/evals` | 能读懂训练仪表盘，并判断这次运行是否在正轨上 |
| 10. 判断 | 0022 至 0024 | 预训练、继续预训练与微调的对比，为算力预算辩护，评审别人的训练运行配置 | 值得信任去做出决定，并向他人解释清楚 |

## 课程

请按顺序学习。

| # | 课程 | 内容 |
|---|---|---|
| [0001](lessons/0001-sourcing-and-mixing-a-pretraining-corpus.md) | 预训练语料的来源与混合 | 预训练语料由什么构成，以及为什么来源的混合比字节总量更重要 |
| [0002](lessons/0002-deduplication-and-quality-filtering.md) | 去重与质量过滤 | 为什么近似重复的文本和低质量的文档要在训练前删掉，以及跳过这一步要付出什么代价 |
| [0003](lessons/0003-byte-pair-encoding-from-scratch.md) | 从零实现字节对编码 | 把罕见词和未知词变成一串习得的子词单元的算法，手工演算一遍 |
| [0004](lessons/0004-sentencepiece-and-the-vocabulary-size-tradeoff.md) | SentencePiece 与词表大小的权衡 | 不用预分词器就对原始文本分词，以及更大或更小的词表究竟要付出什么 |
| [0005](lessons/0005-scaling-laws-what-kaplan-predicted.md) | 缩放定律：Kaplan 预测了什么 | 一条经验幂律让你在花钱之前预测训练运行的损失，以及它对如何花掉算力预算做出了什么预测 |
| [0006](lessons/0006-chinchilla-the-compute-optimal-correction.md) | Chinchilla：算力最优的修正 | 为什么模型规模和 token 数应该一起放大，以及如何把算力预算变成 token 数 |
| [0007](lessons/0007-data-parallelism-and-gradient-all-reduce.md) | 数据并行与梯度 all-reduce | 把一个批次拆分到各自持有完整模型副本的设备上，以及是什么让每个副本保持一致 |
| [0008](lessons/0008-why-data-parallelism-alone-runs-out-of-memory.md) | 为什么单靠数据并行会耗尽内存 | 精确数出混合精度 Adam 优化器为每个参数持有什么，以及它在哪里撞墙 |
| [0009](lessons/0009-zero-stage-1-and-2-partitioning-optimizer-state-and-gradients.md) | ZeRO 阶段 1 和 2：切分优化器状态和梯度 | 免费去掉数据并行多余的副本，此时通信成本还完全不必增长 |
| [0010](lessons/0010-zero-stage-3-and-fsdp-partitioning-parameters-too.md) | ZeRO 阶段 3 与 FSDP：连参数也切分 | 把参数本身也分片，意味着要在需要时把它们重建出来，这是它首先要付出的代价 |
| [0011](lessons/0011-activation-memory-and-zero-r.md) | 激活内存与 ZeRO-R | 对模型状态分片解决了一个内存问题，却留下了第二个问题：激活值 |
| [0012](lessons/0012-tensor-parallelism-splitting-a-layers-matrices.md) | 张量并行：切分一层的矩阵 | 选择沿哪个轴切分权重矩阵，使整个 Transformer 块只需要一次 all-reduce |
| [0013](lessons/0013-pipeline-parallelism-splitting-the-models-layers.md) | 流水线并行：切分模型的层 | 把连续的层分配给不同的设备，以及这在每个批次开始和结束时造成的空闲时间 |
| [0014](lessons/0014-combining-all-three-when-tensor-and-pipeline-parallelism-earn-their-cost.md) | 三者合用：张量并行和流水线并行何时值回成本 | 让每种并行策略与它能容忍的互连相匹配，以及单靠分片什么时候不够 |
| [0015](lessons/0015-mixed-precision-at-scale-bfloat16-and-stochastic-rounding.md) | 大规模混合精度：bfloat16 与随机舍入 | 一种范围与 fp32 相同、精度更低的数值格式，以及直接用它更新参数要付出什么 |
| [0016](lessons/0016-loss-spikes-and-the-optimizers-own-instabilities.md) | 损失尖峰与优化器自身的不稳定 | 同一个尖峰可能来自一个坏批次，也可能来自优化器本身，要区分二者，需要做一次对照比较 |
| [0017](lessons/0017-warmup-decay-and-growing-the-batch-mid-run.md) | 预热、衰减与训练中途增大批大小 | 先慢后快地起步，按调度衰减，并让批大小本身在训练途中改变 |
| [0018](lessons/0018-what-a-checkpoint-has-to-hold.md) | 检查点必须保存什么 | 只保存权重的检查点无法精确地恢复一次运行，而选择多久保存一次本身就是一种权衡 |
| [0019](lessons/0019-surviving-a-node-failure.md) | 挺过节点故障 | 暂停，诊断，隔离出故障的部分，再从最近的检查点恢复，不论这要付出什么代价 |
| [0020](lessons/0020-reading-a-loss-curve.md) | 读懂损失曲线 | 单靠训练损失曲线会低估问题；另外两种信号能抓住它漏掉的东西，而且抓得更早 |
| [0021](lessons/0021-periodic-held-out-evaluation.md) | 周期性的留出评测 | 训练损失只说明模型在拟合它自己的训练数据；只有留出的检查才能说明其余部分的情况 |
| [0022](lessons/0022-pretraining-is-usually-the-wrong-default.md) | 预训练通常是错误的默认选择 | 在现成的模型上做第二阶段的预训练，不必再次付出全部成本，就能得到大部分收益 |
| [0023](lessons/0023-defending-a-compute-budget.md) | 为算力预算辩护 | 一份预训练计划是由许多独立决定组成的一次赌注，为它辩护，就是按各自的道理为每一个决定辩护 |
| [0024](lessons/0024-reviewing-someone-elses-training-run-config.md) | 评审别人的训练运行配置 | 把计划按顺序过一遍本系列涵盖的每个阶段，并从一手来源而不是一篇博客来裁定有争议的声明 |

## 使用方式

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
