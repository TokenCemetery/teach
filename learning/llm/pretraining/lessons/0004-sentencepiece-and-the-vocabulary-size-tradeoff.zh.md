# 第 4 课：SentencePiece 与词表大小的权衡

**使命关联:** “训练一个分词器，并就词表大小对序列长度和嵌入表大小的影响，为所选的词表大小辩护”是“成功的标准”下的第二条。第 3 课构建了合并算法；本课讲如何在不假定词边界的前提下训练它，以及词表大小这个决定本身。
**主要来源:** [论文：“SentencePiece: A simple and language independent subword tokenizer and detokenizer for Neural Text Processing”，Kudo 和 Richardson，2018](https://arxiv.org/abs/1808.06226)
**前置知识:** [第 3 课](0003-byte-pair-encoding-from-scratch.md)

## 热身

1. ▢ 在字节对编码算法中，执行的合并操作次数决定了什么？

<details markdown="1"><summary>检查</summary>

最终的词表大小：它等于起始的字符集，加上每执行一次合并所新增的一个符号。

</details>

2. ▢ 为什么第 3 课演算范例中的三个对（`(e, s)`、`(s, t)`、`(t, </w>)`）会在几步之内全都被合并，而不论先合并的是哪一个？

<details markdown="1"><summary>检查</summary>

它们并列于同一个频率，因为它们都来自同一个重复的子串“est”。合并其中任何一个，都只是把其余的重新标记为同样计数的新对，而没有消除平局，所以不论先合并哪一个，这三者都很快被折叠到了一起。

</details>

## 要点

### 为什么假定词边界会行不通

如第 3 课所述，字节对编码通常运行在一个**预分词器**之上：它先把原始文本切分成词，这样 BPE 只需要学习词内部的合并。对英语来说，按空白切分是一种简单、基本可靠的预分词器。但它并不与语言无关：许多广泛使用的书面语言，包括日语和中文，根本不用空格来分隔词，所以在 BPE 开始之前，空白预分词器就没有任何合理的切分依据。为每种语言或每种文字各造一个不同的预分词器，就破坏了“一套在哪里都适用的分词器训练流程”这个想法。

### 直接在原始句子上训练

Kudo 和 Richardson 的 SentencePiece 没有去逐语言地修补预分词，而是干脆去掉了这一步：它直接在原始的句子文本上训练子词模型，不内置任何预先存在词边界的假设。空白本身被当作输入中的一个普通符号，通常用一个专门的标记来表示，这样在反分词时就能精确还原原来的间距，而不是把它当作训练开始前要据以切分的东西。这使得同一套训练流程与语言无关，论文用一个英日机器翻译实验来证明这一点：直接在原始句子上端到端地训练，达到的准确率，与在已经由另一个工具做过分词的文本上训练相当。

### 一个工具包，两种训练算法

SentencePiece 不是与 BPE 竞争的第二种算法；它是一个工具包，实现了 BPE（第 3 课的合并流程），同时还实现了第二种训练算法，即 **unigram 语言模型**训练器，它的方向正好相反。它不是从单个字符出发、向上增长合并，而是从一大批候选子词出发，反复修剪到目标词表大小，每一步都删去模型似然最不会错过的那些片段。两种训练算法产生的结果形态相同：一份固定的子词片段词表，以及一种把新的原始文本确定性地切分成这些片段的方法。

### 词表大小的权衡

目标词表大小，不论是怎样训练出来的，都是一个同时向多个方向拉扯的数字：

- **更大**的词表，平均用更少的 token 编码同样的文本，因为更多常见的子串获得了自己的单个符号。更短的 token 序列，意味着在注意力计算和生成同样的输入上花费的算力更少。
- **更大**的词表，也意味着更大的嵌入表和更大的输出投影（通常是同一个矩阵，绑定在一起），这部分参数量直接随词表大小而增长，与模型其余部分有多深、多宽无关。
- **更大**的词表，会把训练信号摊得更薄：同一份语料被切成更多可供选择的不同片段，于是任何一个具体的 token，尤其是较罕见的那个，每遍数据中被看到的次数更少。
- **更小**的词表，则把这三点都反过来：每个输入的 token 序列更长，嵌入表和输出表更小，每个 token 的训练信号更密，代价是把普通的词各自切成更多片段。

没有哪个词表大小能在所有维度上同时胜出，所以它是针对具体模型的形状和预算来选的，而不是从某个公式里读出来的。一个真实的、可以核对的例子：LLaMA 论文报告说，它通过 SentencePiece 的实现，用字节对编码来对训练数据分词，把所有数字都拆成单个数位，并且对于训练出的词表没有涵盖的任何 UTF-8 字符，退回到用原始字节来表示，这样无论选定的词表有多大，都不会有任何输入字符真正无法表示。

## 练习

1. ▢ 一个建立在空白预分词器之上、只在英语上训练的分词器，原封不动地用到了词与词之间没有空格的日语文本上。会出什么问题，SentencePiece 的做法有什么不同，从而避免了它？

<details markdown="1"><summary>检查</summary>

空白预分词器没有任何合理的切分依据，因为日语不用空格分隔词，所以它无法交给 BPE 大小合理的、词一级的块来在其中做合并。SentencePiece 通过直接在原始的句子文本上训练来避免这一点，它不假定预先存在词边界，而是把空白当作普通符号，而不是必须预先切分的依据。

</details>

2. ▢ 一个团队把分词器的词表大小翻了一倍，同时保持模型的隐藏维度和深度完全不变。下面哪一项最能描述结果？

    - a) 序列平均变短，嵌入表和输出表缩小
    - b) 序列平均变短，但嵌入表和输出表变大
    - c) 序列平均变长，但嵌入表和输出表缩小
    - d) 序列长度和参数量都不受词表大小影响

<details markdown="1"><summary>提示</summary>

词表大小影响两个不同的东西：一段文本会变成多少个 token，以及把每个 token 映射到一个向量的表有多大。分别考虑每一个。

</details>

<details markdown="1"><summary>检查</summary>

**b)** 更大的词表意味着更多常见的子串获得了自己的 token，这会缩短序列，而嵌入表和（通常绑定的）输出投影表都直接随词表大小增长，所以它们会变大。(a) 和 (c) 各把两个效应中的一个搞反了，(d) 则把两个都忽略了。

</details>

3. ▢ 说出一个较小的词表比较大的词表更好的维度，和一个它更差的维度。

<details markdown="1"><summary>检查</summary>

更好：每个 token 的训练信号更密（在同一份语料上，每遍数据中每个 token 被看到得更频繁），或者嵌入表和输出表更小。更差：每个输入的 token 序列更长，因为普通的词被切成了更多片段，在注意力计算和生成上要花更多算力。

</details>

4. ▢ 下面哪一项最能描述 SentencePiece 作为一款软件是什么？

    - a) 一种取代字节对编码的全新分词算法
    - b) 一个同时实现了字节对编码和 unigram 语言模型训练器的工具包，直接作用于原始文本，不需要预分词步骤
    - c) 只是一个预分词器，要在另外的 BPE 实现之前运行
    - d) 一种完全不需要任何固定词表就能训练模型的方法

<details markdown="1"><summary>检查</summary>

**b)** SentencePiece 打包了两种训练算法，字节对编码和 unigram 语言模型，它与众不同之处在于直接从原始句子训练。(a) 是错的，因为它仍然实现了 BPE，而不是取代它。(c) 把 SentencePiece 的实际贡献说反了，它的贡献是去掉预分词步骤。(d) 描述的不是本系列所讨论的任何真实的分词器；两种算法产生的仍然是一份固定的词表。

</details>

## 实战练习

- [ ] 找出你能拿到的某个分词器所报告的词表大小，不论是通过某个库，还是通过某个托管模型公布的分词器文件。
- [ ] 如果你能拿到两个词表大小明显不同的分词器，用两者对同一个句子编码，并直接比较得到的 token 数。
- [ ] 明天：针对一个你了解其规模的具体项目或用例（聊天助手、专注代码的模型、面向低资源语言的工具），定性地判断你会倾向于采用比主流模型更大还是更小的词表，并写下是权衡中的哪一个维度促成了你的答案。
