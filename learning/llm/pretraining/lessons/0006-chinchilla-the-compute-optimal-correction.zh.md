# 第 6 课：Chinchilla：算力最优的修正

**使命关联:** “给定参数量和算力预算，算出算力最优的 token 数，并针对 Kaplan 式的训练不足方案为它辩护”是“成功的标准”下的第三条。第 5 课讲了 Kaplan 等人的建议；本课讲推翻它的那项范围更广的研究，以及应用它所用的算术。
**主要来源:** [论文：“Training Compute-Optimal Large Language Models”，Hoffmann 等，2022](https://arxiv.org/abs/2203.15556)
**前置知识:** [第 5 课](0005-scaling-laws-what-kaplan-predicted.md)

## 热身

1. ▢ 按 Kaplan 等人的说法，对于固定的算力预算，算力效率最优的训练，是指用相对很少的数据去训练买得起的最大模型，还是用预算允许的尽可能多的数据去训练一个较小的模型？

<details markdown="1"><summary>检查</summary>

买得起的最大模型，用相对很少的数据训练，并在收敛之前就停下。正是因为更大的模型样本效率更高，才使这成为对固定预算所推荐的分配。

</details>

2. ▢ GPT-3 在 3000 亿个 token 上训练了一个 1750 亿参数的模型。这大约是每个参数多少个 token？

<details markdown="1"><summary>检查</summary>

大约是每个参数 1.7 个 token（3000 亿除以 1750 亿）。

</details>

## 要点

### 大得多的扫描，不同的答案

Hoffmann 等人做了与 Kaplan 等人同类的缩放定律研究，但规模大得多，控制也更仔细：超过 400 个模型，参数量从 7000 万到 160 多亿，训练所用的 token 数从 50 亿到 5000 亿不等。他们对这批扫描拟合了一条缩放定律，得出了一个不同的实践结论：要做到算力最优的训练，模型规模和训练 token 数应该**等比例**地放大。算力预算翻倍，就意味着模型规模和 token 数都要翻倍，而不是像 Kaplan 等人的建议所暗示的那样，把几乎所有额外的算力都花在更大的模型上。

### 让这套算术成立的近似

两篇论文对一次训练运行要花多少算力，用的是同一个粗略近似：`FLOPs(N, D) ≈ 6ND`，其中 `N` 是参数量，`D` 是训练 token 数。Hoffmann 等人把这个近似，在一系列模型规模上直接与更精确的 FLOP 计数做了核对，发现差别小到不影响他们的结论。这意味着，算力预算 `C`、参数量 `N` 和 token 数 `D` 并不是三个相互独立的选择：固定其中任意两个，就确定了第三个，关系是 `D ≈ C / (6N)`。

### Chinchilla，以及标题背后的数字

Hoffmann 等人训练了一个模型 Chinchilla，700 亿参数，在 1.4 万亿个 token 上训练，所用的训练算力与 Gopher（一个 2800 亿参数的模型）相同。这大约是每个参数 20 个 token（1.4 万亿除以 700 亿）。他们自己对其他算力预算所做的最优分配推算，落在类似的范围内，只是并非每次都落在完全相同的数字上：一个算力最优的 1750 亿参数模型，预计需要超过 4.2 万亿个 token（约每个参数 24 个），而在更大的预算下，一个 2800 亿参数的模型，约需 6.8 万亿个 token（约每个参数 24 个）。正确的结论是“在这篇论文核对过的范围内，算力最优的分配大致是每个参数 20 到 25 个 token”，而不是一个单一的通用常数。

与此相比，GPT-3 在 3000 亿个 token 上训练 1750 亿个参数，也就是本课热身中得到的每个参数约 1.7 个 token，远低于这个范围。这个差距，恰恰就是 Chinchilla 论文摘要里称当时的大语言模型“明显训练不足”的含义：同样的训练算力，本可以用来训练一个较小的、达到更低损失的模型，或者用几倍的数据去训练同样大小的模型，两者对算力的利用，都会比实际花掉的方式更好。

### 让这次修正站稳脚跟的结果

Chinchilla 以 Gopher 的算力预算、但只有它四分之一的参数量、四倍的 token 数来训练，在范围很广的下游评测上，一致且显著地胜过了 Gopher（280B）、GPT-3（175B）、Jurassic-1（178B）和 Megatron-Turing NLG（530B），其中几个的规模是它的好几倍，包括在 MMLU 上达到了当时最先进的 67.5%，比 Gopher 高出 7 个多百分点。Chinchilla 的规模只有 Gopher 的四分之一，也使它在推理时的运行成本低得多，这是算力最优训练在本课所讲的训练时论证之外，额外换来的一项独立的、部署时的好处。

## 练习

1. ▢ 一个团队要训练一个 130 亿参数的模型，并希望落在 Chinchilla 大致每个参数 20 到 25 个 token 的范围内。这意味着大约需要多少训练 token？

<details markdown="1"><summary>检查</summary>

大约 2600 亿到 3250 亿个 token（130 亿乘以 20 到 25）。这个范围的任何一端都是可以辩护的答案；而远在这个范围之外的数字，比如 GPT-3 的每个参数 1.7 个，则不是。

</details>

2. ▢ 一个团队的算力预算是 `1.2 × 10^22` FLOPs，并计划训练一个 100 亿参数的模型。用 `FLOPs(N, D) ≈ 6ND`，这份预算大约能负担多少个 token？

<details markdown="1"><summary>提示</summary>

在 `C = 1.2 × 10^22`、`N = 10^10` 的条件下，解 `D ≈ C / (6N)`。

</details>

<details markdown="1"><summary>检查</summary>

大约 2000 亿个 token：`1.2 × 10^22 / (6 × 10^10) = 2 × 10^11`，也就是 2000 亿，约为每个参数 20 个 token，正好在本课给出的范围之内。

</details>

3. ▢ 对于固定的算力预算，下面哪一项最能概括 Kaplan 等人的建议与 Hoffmann 等人的修正在实践上的差别？

    - a) Kaplan 建议把大部分预算花在用相对很少的数据去训练更大的模型上；Hoffmann 建议让模型规模和 token 数等比例放大
    - b) 两篇论文得出的建议完全相同，只是措辞不同
    - c) Kaplan 说模型规模与损失无关；Hoffmann 说只有模型规模才重要
    - d) Hoffmann 认为在同样的算力下，更大的模型总是比更小的模型更差

<details markdown="1"><summary>检查</summary>

**a)** 才是本课和第 5 课所讲的实际差别。(b) 抹去了两篇论文之间一个真实的、在实践上影响重大的分歧。(c) 和 (d) 都不是任何一篇论文的主张。

</details>

4. ▢ GPT-3 在 3000 亿个 token 上训练了 1750 亿个参数，约为每个参数 1.7 个 token。按 Chinchilla 算力最优范围大致是每个参数 20 到 25 个 token，相对于它的规模，GPT-3 在数据上更接近训练过度还是训练不足？

<details markdown="1"><summary>检查</summary>

训练不足。它的比值比 Chinchilla 的结果所暗示的算力最优范围低了十倍以上，这意味着同样的训练算力，很可能本该用来训练一个较小的、达到更低损失的模型，或者用多得多的数据去训练同样的 1750 亿参数模型。

</details>

## 实战练习

- [ ] 找出一个 2022 年之后发布的开源模型已公布的参数量和训练 token 数（Llama、Mistral 或类似的模型都会公布这两个数）。计算它的每参数 token 数比，并与本课大致每个参数 20 到 25 个的范围做比较。
- [ ] 用 `FLOPs(N, D) ≈ 6ND`，估算 GPT-3 实际训练运行（1750 亿参数，3000 亿个 token）用掉的训练算力（以 FLOPs 计），并另外估算一次算力最优的 1750 亿参数运行，在 4.2 万亿个 token 下需要多少算力。比较这两个数。
- [ ] 明天：自选一个假想的算力预算（任何数量级都行），在纸上为同一份预算分别算出 Kaplan 式的分配（偏向大得多的模型，token 数保持相对固定）和 Chinchilla 式的分配（两者一起放大）。把得到的两个 `(N, D)` 对并排写下来。
