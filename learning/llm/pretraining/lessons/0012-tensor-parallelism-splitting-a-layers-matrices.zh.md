# 第 12 课：张量并行：切分一层的矩阵

**使命关联:** “解释 ZeRO/FSDP 分片的是什么，为什么单靠数据并行会在算力耗尽之前先耗尽内存，以及张量并行或流水线并行在什么时候值得付出它们的通信成本”是“成功的标准”下的第四条。本课讲张量并行究竟切分什么、为什么这样切；第 13 课讲流水线并行，第 14 课讲两者何时值得付出代价。
**主要来源:** [论文：“Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM”，Narayanan 等，2021](https://arxiv.org/abs/2104.04473)
**前置知识:** [第 11 课](0011-activation-memory-and-zero-r.md)

## 热身

1. ▢ ZeRO 阶段 3 在静止时对参数分片，但在某一层的前向或反向计算之前，通过 all-gather 按需重建出完整的参数张量。参数重建出来之后，是每个设备都计算同一个完整的层，还是每个设备计算这一层数学运算中不同的一部分？

<details markdown="1"><summary>检查</summary>

每个设备计算的都是同一个完整的层，用的是它自己重建出来的、该层参数的完整副本。ZeRO 分片的是参数在静止时存放的位置；它并没有把任何单个层的计算拆分到各个设备上。

</details>

## 要点

### 拆分计算，而不只是权重的存放位置

**张量并行**采取的做法，与第 5 阶段中的任何东西都不同：它不是在某一个设备上重建出一整层的权重，而是把单层的权重矩阵拆分到各个设备上，使每个设备只持有、也只用它自己的那一片来计算这一层。没有任何设备需要同时拥有完整的权重矩阵。

### 一个演算范例：MLP 块

Transformer 的 MLP 块先计算 `Y = GeLU(XA)`，再计算 `Z = Dropout(YB)`，是两次矩阵乘法，中间夹着一个非线性。Narayanan 等人描述了 Megatron 把它拆开的那种使通信降到最低的特定方式：把第一个权重矩阵 `A` **沿列**拆分，`A = [A1, A2]`，让每个设备得到一片完整的、可以独立计算的输出，`Y1 = GeLU(XA1)` 和 `Y2 = GeLU(XA2)`，计算它们不需要两个设备之间做任何同步。这之所以行得通，是因为沿列拆分，拆开的是*输出*维度，而不是被求和的那个维度，所以每个设备手里的那一片 `Y`，对它负责的那些列来说已经是真实、完整的答案，而逐元素施加的 `GeLU`，可以独立地施加到每一片完整的结果上。

第二个权重矩阵 `B` 随后**沿行**拆分以与之匹配，`B = [B1; B2]`，这样每个设备只用自己本地的那一片 `Y` 和 `B` 来计算 `Yi @ Bi`。这就让每个设备得到一个朝真实输出 `Z` 累加的部分和；两个设备的部分和用一次 all-reduce 合并，只有在那之后，才对完整、正确的结果施加 dropout。

### 为什么先列后行，而不是反过来

如果 `A` 改为沿行拆分（拆开的是被求和的维度，而不是输出维度），那么每个设备算出的 `X @ A` 的那一片，就只是朝真实的激活前数值累加的**部分和**，而不是完整的答案，因为只对收缩维度的一部分求和，对任何一个输出列都得不到正确的数值。`GeLU` 不能先施加到一个部分和上、事后再合并，因为 `GeLU` 是非线性的：`GeLU(a + b)` 不等于 `GeLU(a) + GeLU(b)`。沿列拆分 `A`，从一开始就避免了需要对部分和施加非线性，这恰恰就是 Narayanan 等人选择它所给出的理由。先列后行的配对，使整个两个矩阵的 MLP 块只需要**一次** all-reduce，就在最后，而不是在两次矩阵乘法之间也要多一个同步步骤。

### 同样的模式适用于注意力

多头注意力本来就有一个天然可以拆分的位置：查询、键和值的投影按列并行分片，于是每个设备独立处理一部分注意力头，在注意力计算本身的过程中不需要任何跨设备的协调。随后的输出投影沿行拆分以与之匹配，与 MLP 块一样是先列后行的配对，在注意力块的末尾需要一次 all-reduce。

## 练习

1. ▢ 一个 Transformer 的 MLP 块，按本课所述，`A` 沿列拆分，`B` 沿行拆分。这种方案对整个块，从 `X` 到最终的 `Z`，需要多少次 all-reduce 操作？

<details markdown="1"><summary>检查</summary>

一次，就在第二次矩阵乘法之后，把每个设备的 `Z` 的部分和合并成完整的结果。对 `A` 的列拆分，避免了在两次矩阵乘法之间需要任何同步。

</details>

2. ▢ 如果 `A` 改为沿行而不是沿列拆分，那么在第一次矩阵乘法之后立刻施加 `GeLU`，会出什么问题？

<details markdown="1"><summary>提示</summary>

想一想，当被拆开的是被求和的维度、而不是输出维度时，每个设备的本地结果实际代表什么。

</details>

<details markdown="1"><summary>检查</summary>

每个设备手里只有朝真实的激活前数值累加的部分和，而不是完整的数值，因为每个设备的本地计算只包含了收缩维度的一部分。`GeLU` 是非线性的，所以把它施加到部分和上、事后再合并结果，得不到与施加到完整的和上相同的答案，这意味着在 `GeLU` 能够正确运行之前，需要一个同步步骤。

</details>

3. ▢ 在注意力块中，查询、键和值的投影是怎样拆分的？多头注意力的什么天然特点使这种拆分很方便？

<details markdown="1"><summary>检查</summary>

它们按列并行拆分，与 MLP 块中拆分 `A` 的方式相同。多头注意力本来就是各个头独立于其他头计算自己的注意力，所以把不同的头（或几组头）分给不同的设备，在注意力计算本身的过程中不需要任何协调，就像拆分 MLP 的输出维度也不需要任何协调一样。

</details>

4. ▢ 为什么按本课所述的张量并行，与 ZeRO 阶段 3 不同，从不需要在任何单个设备上重建一层完整的权重矩阵？

<details markdown="1"><summary>检查</summary>

因为每个设备只用它自己的那一片权重矩阵来计算；先列后行的拆分，是专门这样选的，使每个设备上的每一个中间计算，要么是一个完整的、独立的结果（在列拆分之后），要么是一个通过 all-reduce 合并的部分和（在行拆分之后），而不需要完整的矩阵存在于任何地方。

</details>
