# Глоссарий промптинга

Канонические термины для написания, структурирования, версионирования, измерения и защиты промптов, на которых держится функция на основе LLM.

## Термины

**Цепочка рассуждений (chain-of-thought)**:
Промежуточные рассуждения, которые модель пишет перед окончательным ответом. Их вызывают примерами, где такие рассуждения показаны, или инструкцией, которая их требует.
_Не используйте_: CoT в тексте (допустимо в заголовке или таблице), «размышление» (в этом курсе так называется только встроенная фаза рассуждающей модели)

**Чат-шаблон (chat template)**:
Правило конкретной модели, которое превращает список сообщений с ролями в единую последовательность токенов, на которой модель обучалась, включая специальные токены, отмечающие начало и конец каждой роли.
_Не используйте_: формат промпта

**Ограниченное декодирование (constrained decoding)**:
Ограничение того, какие токены модель может сгенерировать на каждом шаге, так что вывод обязан соответствовать грамматике или схеме. Так работает принудительный структурированный вывод у провайдера.
_Не используйте_: грамматическая выборка

**Разделитель (delimiter)**:
Разметка в промпте, например XML-подобный тег или блок в ограждающих кавычках, которая показывает, где заканчивается один вид содержимого и начинается другой. Чаще всего нужна, чтобы отделить данные от инструкций.
_Не используйте_: сепаратор

**Few-shot-промпт**:
Промпт, который перед настоящим входом содержит разобранные примеры задачи, каждый из которых состоит из входа и желаемого выхода.
_Не используйте_: multishot-промпт, обучение в контексте

**Косвенная промпт-инъекция (indirect prompt injection)**:
Промпт-инъекция, которую несёт содержимое, читаемое моделью от имени пользователя, например веб-страница, письмо или найденный документ, а не текст, набранный тем, кто разговаривает с моделью.
_Не используйте_: инъекция второго порядка

**Иерархия инструкций (instruction hierarchy)**:
Порядок приоритета, который модель обучена применять при конфликте инструкций: системный промпт выше хода пользователя, ход пользователя выше содержимого, возвращённого инструментами или поиском.
_Не используйте_: порядок приоритета

**Джейлбрейк (jailbreak)**:
Входные данные, составленные так, чтобы модель выдала то, от чего её отучило обучение безопасности. Он бьёт по собственным ограничениям модели, тогда как промпт-инъекция бьёт по инструкциям приложения.
_Не используйте_: промпт-инъекция (другая цель)

**Смертельная тройка (lethal trifecta)**:
Сочетание доступа к приватным данным, воздействия недоверенного содержимого и возможности отправлять данные наружу, которое делает промпт-инъекцию эксплуатируемой. Если убрать любой из трёх компонентов, путь атаки закрыт.
_Не используйте_: риск инъекции (слишком расплывчато, чтобы действовать)

**Снапшот модели (model snapshot)**:
Зафиксированная версия модели с точным идентификатором, веса которой провайдер не меняет. Удобный псевдоним со временем может указывать на более новый снапшот.
_Не используйте_: версия модели (путается с поколением модели)

**Парное сравнение (paired comparison)**:
Сравнение двух промптов или моделей на одних и тех же входах по тем случаям, где их результаты различаются, а не по двум итоговым показателям.
_Не используйте_: сравнение A/B-оценок

**Промпт (prompt)**:
Всё, что модель получает за один вызов: системный промпт, каждое сообщение разговора на этот момент и любое вставленное содержимое, преобразованные чат-шаблоном в одну последовательность токенов.
_Не используйте_: запрос (это вопрос пользователя внутри промпта)

**Кеширование промпта (prompt caching)**:
Функция провайдера, которая сохраняет обработанное состояние префикса промпта, чтобы последующие вызовы с точно таким же префиксом не вычисляли его заново, что снижает стоимость и задержку.
_Не используйте_: кеширование ответов (это другое: хранятся целые ответы)

**Промпт-инъекция (prompt injection)**:
Входные данные, из-за которых модель выполняет не те инструкции, которые задумал автор промпта.
_Не используйте_: джейлбрейк (джейлбрейк бьёт по обучению безопасности модели, инъекция бьёт по инструкциям приложения)

**Шаблон промпта (prompt template)**:
Неизменяемый текст промпта с именованными слотами, которые при вызове заполняются значениями для конкретного запроса, например сообщением пользователя или найденным документом.
_Не используйте_: строка промпта

**Рассуждающая модель (reasoning model)**:
Модель, обученная создавать внутреннюю фазу рассуждения перед видимым ответом, поэтому она рассуждает без просьбы об этом.
_Не используйте_: думающая модель

**Регрессионный набор (regression set)**:
Фиксированный набор входов, к каждому из которых привязана проверка вывода, и изменение промпта не должно их ломать. Набор строится в основном из сбоев, замеченных в реальной работе.
_Не используйте_: тестовые промпты, золотой набор

**Роль (role)**:
Метка у каждого сообщения разговора, обычно system, user или assistant, которую чат-шаблон превращает в специальные токены. Роль это форматирование, которому модель научилась придавать вес, а не отдельный канал ввода.
_Не используйте_: персона (это описание того, кого должна играть модель)

**Самосогласованность (self-consistency)**:
Сэмплирование нескольких завершений с цепочкой рассуждений для одного и того же промпта и выбор самого частого окончательного ответа.
_Не используйте_: ансамблирование

**Структурированный вывод (structured output)**:
Ответ в машиночитаемом формате, обычно JSON, соответствующий схеме, который разбирает программа, а не читает человек.
_Не используйте_: JSON mode (одна из функций провайдера для этого)

**Системный промпт (system prompt)**:
Сообщение в роли system, которое задаёт модели задачу, ограничения и контекст на весь разговор и стоит выше всего в иерархии инструкций.
_Не используйте_: системное сообщение, преамбула

**Zero-shot-промпт**:
Промпт, который ставит задачу без каких-либо разобранных примеров.
_Не используйте_: простой промпт
