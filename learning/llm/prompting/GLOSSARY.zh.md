# 提示词工程术语表

编写、组织、版本管理、度量和保护 LLM 功能背后提示词时使用的规范术语。

## 术语

**思维链（Chain-of-thought）**:
模型在给出最终答案之前写出的中间推理，由展示推理过程的示例或要求其推理的指令引出。
_避免使用_: 在正文中写 CoT（标题或表格中可以用），thinking（在本术语表中专指推理模型内置的思考阶段）

**聊天模板（Chat template）**:
与具体模型绑定的规则，把一组带角色标签的消息渲染成模型训练时使用的单一 token 序列，其中包含标记每个角色起止位置的特殊 token。
_避免使用_: 提示词格式（prompt format）

**约束解码（Constrained decoding）**:
在每一步限制模型可以生成哪些 token，使输出必须符合某种语法或 schema，服务商提供的强制结构化输出功能就是这样做的。
_避免使用_: 语法采样（grammar sampling）

**分隔符（Delimiter）**:
提示词中用来标明一种内容在哪里结束、另一种内容从哪里开始的标记，例如 XML 风格的标签或围栏代码块，最常见的用途是把数据和指令分开。
_避免使用_: 分隔字符（separator）

**少样本提示词（Few-shot prompt）**:
在真正的输入之前，附带若干任务示例的提示词，每个示例由一个输入和期望的输出配成一对。
_避免使用_: 多样本提示词（multishot prompt），上下文内训练（in-context training）

**间接提示词注入（Indirect prompt injection）**:
由模型代用户读取的内容携带的提示词注入，例如网页、邮件或检索到的文档，而不是由和模型对话的人直接输入。
_避免使用_: 二阶注入（second-order injection）

**指令层级（Instruction hierarchy）**:
指令相互冲突时，模型经过训练后采用的优先级排序：系统提示词高于用户轮次，用户轮次高于工具或检索返回的内容。
_避免使用_: 优先级顺序（priority order）

**越狱（Jailbreak）**:
为了让模型产出其安全训练会拒绝的内容而精心构造的输入。越狱针对的是模型自身的限制，而提示词注入针对的是应用的指令。
_避免使用_: 提示词注入（二者针对的目标不同）

**致命三要素（Lethal trifecta）**:
可访问私有数据、会接触不可信内容、能够向外发送数据，这三者同时具备，提示词注入就会变得可被利用。去掉其中任何一个，攻击路径就被切断。
_避免使用_: 注入风险（过于笼统，无法据此行动）

**模型快照（Model snapshot）**:
模型的固定版本，由确切的模型 ID 命名，服务商不会改动其权重。便利的别名可能会随时间指向更新的快照。
_避免使用_: 模型版本（与模型代际容易混淆）

**成对比较（Paired comparison）**:
在相同的输入上比较两个提示词或两个模型，看的是二者结果不同的那些用例，而不是两个总分。
_避免使用_: A/B 分数比较

**提示词（Prompt）**:
模型在一次调用中收到的全部内容：系统提示词、到目前为止对话中的每条消息，以及任何插入的内容，由聊天模板渲染成一个 token 序列。
_避免使用_: query（那是提示词中用户的问题）

**提示词缓存（Prompt caching）**:
服务商提供的功能，保存提示词前缀的已处理状态，之后共享这段完全相同前缀的调用就可以跳过重复计算，从而降低成本和延迟。
_避免使用_: 响应缓存（另一回事：存储的是完整的回答）

**提示词注入（Prompt injection）**:
使模型遵循的指令不是提示词作者本来意图的那些指令的输入。
_避免使用_: 越狱（越狱针对模型的安全训练，注入针对应用的指令）

**提示词模板（Prompt template）**:
提示词中固定的文本，带有命名的槽位，调用时再用每次请求的值填充，例如用户的消息或检索到的文档。
_避免使用_: 提示词字符串（prompt string）

**推理模型（Reasoning model）**:
经过训练，会在可见回答之前产生内部推理阶段的模型，所以无需被要求就会推理。
_避免使用_: 思考模型（thinking model）

**回归集（Regression set）**:
一组固定的输入，每个输入附带对输出的检查，提示词的任何改动都不能破坏它们，主要由真实使用中见到的失败构成。
_避免使用_: 测试提示词（test prompts），黄金集（golden set）

**角色（Role）**:
对话中每条消息的标签，通常是 system、user 或 assistant，由聊天模板转成特殊 token。角色是模型学会赋予不同权重的格式，而不是一条独立的输入通道。
_避免使用_: persona（那是对模型应扮演谁的描述）

**自洽性（Self-consistency）**:
对同一个提示词采样多条思维链补全，取其中最常见的最终答案。
_避免使用_: 集成（ensembling）

**结构化输出（Structured output）**:
机器可读格式的响应，通常是符合某个 schema 的 JSON，由程序解析，而不是由人阅读。
_避免使用_: JSON mode（某个服务商对它的称呼）

**系统提示词（System prompt）**:
system 角色中的消息，为整个对话设定模型的任务、约束和上下文，在指令层级中位置最高。
_避免使用_: 系统消息（system message），前言（preamble）

**零样本提示词（Zero-shot prompt）**:
陈述任务但不带任何示例的提示词。
_避免使用_: 朴素提示词（plain prompt）
