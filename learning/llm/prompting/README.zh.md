# 学习：提示词工程

为 LLM 功能编写背后的提示词，让它们做到预期的事，作为带版本的模板存放在代码库中，并且只在回归集证明改动有效时才修改。学完后，你能评审别人的生产提示词，并说出其中每个选择的代价，而不是只说一句“读起来怪怪的”。

**最新课程：** [24. 常规建议失效的时候](lessons/0024-when-the-usual-advice-is-wrong.md)

## 成功的标准

- 写出一份角色、指令和结构都能让同事读懂、让模型照着执行的提示词，并说清模型实际收到的是什么。
- 选择、排序并审查少样本示例，说出每个选择带来的偏差风险。
- 判断何时要求模型给出推理，知道推理模型与标准模型的提示方式有何不同，并解释为什么写出来的推理不能当作答案的解释。
- 得到程序可以解析的结构化输出，并安排好长上下文的布局，让模型用上其中的内容。
- 把提示词作为带版本的模板放进代码库，并调整顺序，使稳定的前缀可以被缓存。
- 用回归集和成对比较证明一次提示词改动是否有效，而不是凭少数几条输出下判断。
- 设计能处理不可信输入的提示词，并说明有哪些风险是提示词自身无法防御的。
- 针对一个具体的失败，在更好的提示词、检索和 fine-tuning 之间做出选择，并通过说出每个选择的代价来评审别人的生产提示词。

## 约束

- 以应用为先，在聊天窗口里就能用：第 1 到 6 阶段在任何聊天界面都能完成，第 7 到 10 阶段假定提示词存放在代码中。
- 不限定服务商或模型。示例与服务商无关；某项技术只是某个厂商文档记载的行为时，课程会明确说明。
- 不要求有提示词工程的基础。知道 LLM 是什么，达到“它预测下一个 token”的程度就够了。

## 范围之外

- 基于检索到的上下文构造提示词，以及上下文窗口的预算：见 [`llm/rag`](../../llm/rag/) 及其[基于检索的生成速查表](../../llm/rag/reference/generation-from-retrieval.md)。本系列讲通用的提示词工程，涉及检索的情形则链接到那里。
- 作为提示词一部分的工具描述、带工具的智能体中的提示词注入，以及并发下的提示词缓存：见 [`llm/agents`](../../llm/agents/)。本系列只讲不带工具的提示词，并链接到那些课程，而不重复其内容。
- 评判提示词（judge prompt）的设计与评测方法：见 [`llm/evals`](../../llm/evals/) 及其[通过与否速查表](../../llm/evals/reference/go-no-go.md)。本系列用评测来衡量提示词改动，不教如何构建评测。
- 约束解码，即结构化输出在服务端的实现：见 [`llm/inference`](../../llm/inference/)。本系列从提示词一侧去要求结构。
- 指令遵循和推理能力是如何训练进模型的：见 [`llm/post-training`](../../llm/post-training/)。本系列讲如何从外部使用它们。

## 学习路线

共十个阶段，从提示词对模型意味着什么，到能够评审别人的提示词所需的判断力。一个阶段包含若干课程，边界并不严格；一个阶段是否完成，取决于能力，而不是课程数量。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. 提示词对模型意味着什么 | 0001 至 0002 | token、聊天模板、角色、系统提示词和指令层级 | 能说出某段对话交给模型的是怎样的序列，以及每条指令应放在哪里 |
| 2. 指令与结构 | 0003 至 0005 | 清晰的指令、分隔符与标签、对格式的敏感性 | 能写出新手也能照着做、并把指令与数据分开的提示词 |
| 3. 少样本示例 | 0006 至 0007 | 示例教给模型什么、多数标签偏差、近因偏差和顺序偏差 | 能选择并排序示例，并说出每个选择带来的偏差 |
| 4. 推理 | 0008 至 0010 | 思维链、自洽性、忠实性、给推理模型写提示词 | 能针对某个模型和任务，判断是否要求推理以及如何要求 |
| 5. 结构化输出 | 0011 至 0012 | 要求输出符合 schema、验证它、格式约束与推理质量的权衡 | 得到程序能解析的输出，同时不牺牲答案质量 |
| 6. 长上下文 | 0013 至 0014 | 位置效应、文档布局、引文抽取 | 能安排长上下文的布局，让模型用上位于中间的内容 |
| 7. 代码库中的提示词 | 0015 至 0017 | 模板、针对模型快照的版本管理、面向提示词缓存的布局 | 把提示词作为带版本的模板管理，其稳定前缀可以被缓存 |
| 8. 衡量提示词改动 | 0018 至 0019 | 从真实失败出发建立回归集、用成对比较排除噪声 | 能用一个数字说明提示词 B 是否优于提示词 A |
| 9. 提示词安全 | 0020 至 0021 | 直接与间接提示词注入、提示词能防御什么与不能防御什么 | 能为不可信输入设计提示词，并指出留给系统去应对的风险 |
| 10. 判断力 | 0022 至 0024 | 提示词、RAG 与 fine-tuning 之间的取舍、评审生产提示词、修改他人依赖的提示词、常规建议何时失效 | 能对一份提示词做出判断，并向别人解释清楚 |

## 课程

请按顺序学习。

| # | 课程 | 内容 |
|---|---|---|
| [0001](lessons/0001-what-the-model-sees.md) | 模型看到的是什么 | 提示词以聊天模板构建的单一 token 序列到达模型，所以角色是模型训练时见过的格式，而不是彼此独立的通道 |
| [0002](lessons/0002-system-prompts-and-roles.md) | 系统提示词与角色 | 哪些内容属于系统提示词，哪些属于用户轮次，以及为什么模型会按指令所处的位置给它们排优先级 |
| [0003](lessons/0003-clear-instructions.md) | 清晰的指令 | 写出一条有能力的新手也能照着做的指令：背景、任务、约束，以及怎样算完成 |
| [0004](lessons/0004-structure-and-delimiters.md) | 结构与分隔符 | 用标签和分节把指令与数据分开，让模型分得清哪个是哪个 |
| [0005](lessons/0005-format-sensitivity.md) | 对格式的敏感性 | 为什么一个没有语义的格式改动也能让准确率变化，以及为什么这使每一次提示词编辑都成为需要检验的论断 |
| [0006](lessons/0006-what-examples-teach.md) | 少样本示例教会模型什么 | 示例主要教会模型格式、标签空间和输入分布，这改变了挑选示例的方式 |
| [0007](lessons/0007-few-shot-biases.md) | 少样本的偏差 | 少样本提示词中的多数标签偏差、近因偏差和顺序偏差，以及如何选择和排序示例来对付它们 |
| [0008](lessons/0008-chain-of-thought.md) | 思维链 | 什么时候要求中间推理能改善答案，什么时候只是多花 token |
| [0009](lessons/0009-self-consistency-and-faithfulness.md) | 自洽性与忠实性 | 采样多条推理路径并对答案投票，以及为什么写出来的推理不是忠实的解释 |
| [0010](lessons/0010-prompting-reasoning-models.md) | 给推理模型写提示词 | 为什么已经会思考的模型需要目标和约束，而不是写死的步骤 |
| [0011](lessons/0011-structured-output-from-the-prompt.md) | 从提示词获得结构化输出 | 要求输出程序可以解析的内容，然后加以验证，因为“要求”不等于“保证” |
| [0012](lessons/0012-format-constraints-and-reasoning.md) | 格式约束与推理 | 严格的输出格式可能损害推理质量，以及如何安排字段顺序，让答案出现在思考之后 |
| [0013](lessons/0013-position-in-long-context.md) | 长上下文中的位置 | 模型对长上下文两端信息的利用好于中间，这决定了文档和问题该放在哪里 |
| [0014](lessons/0014-working-with-long-documents.md) | 处理长文档 | 给文档标上元数据标签，并让模型在回答前先抽取引文 |
| [0015](lessons/0015-prompt-templates.md) | 提示词模板 | 把提示词拆成固定模板和每次请求填入的变量，并防止不可信输入破坏结构 |
| [0016](lessons/0016-versioning-prompts.md) | 提示词的版本管理 | 把提示词当作代码：固定到某个模型快照，像对待其他改动一样做版本管理、评审和回滚 |
| [0017](lessons/0017-prompt-caching-and-layout.md) | 提示词缓存与布局 | 把稳定的部分排在前面，让服务商可以缓存前缀 |
| [0018](lessons/0018-a-regression-set-for-a-prompt.md) | 提示词的回归集 | 从真实失败出发，建立一个提示词改动不得破坏的小型用例集 |
| [0019](lessons/0019-comparing-two-prompts.md) | 比较两个提示词 | 用成对比较判断提示词 B 是否优于提示词 A，把改动的效果与每次运行的噪声区分开 |
| [0020](lessons/0020-prompt-injection.md) | 提示词注入 | 输入中的文本如何覆盖作者的指令，无论是直接输入的，还是藏在模型读取的内容里 |
| [0021](lessons/0021-what-a-prompt-cannot-defend.md) | 提示词无法防御什么 | 哪些防御属于提示词，以及为什么真正的防御在于系统允许模型做什么 |
| [0022](lessons/0022-prompt-rag-or-fine-tune.md) | 提示词、RAG 还是 fine-tuning | 根据失败的实际原因，在更好的提示词、检索和 fine-tuning 之间做选择 |
| [0023](lessons/0023-reviewing-a-production-prompt.md) | 评审生产提示词 | 通过说出每个选择的代价来评审别人的提示词，并在不破坏他人依赖的前提下修改一份被多方依赖的提示词 |
| [0024](lessons/0024-when-the-usual-advice-is-wrong.md) | 常规建议失效的时候 | 识别标准的提示词建议在特定模型或任务上何时失效，并回到一手资料解决争议 |

## 使用方式

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
