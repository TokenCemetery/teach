# 第 2 课：浮点格式

**使命关联:** 本系列后面的每一种数值格式，都是在选择如何把有限的几位在范围与精度之间分配，所以你要先能读懂一个位布局，并说出它能装下什么、装不下什么，才能判断一个量化模型丢掉了什么。
**主要来源:** [论文：“A Study of BFLOAT16 for Deep Learning Training”，Kalamkar 等，2019](https://arxiv.org/abs/1905.12322)
**前置知识:** [第 1 课](0001-what-quantization-buys.md)、[指数位](../GLOSSARY.md)、[尾数位](../GLOSSARY.md)

## 热身

1. ▢ fp32、bf16 和 int8 每个参数各用多少字节？一个 7B 参数的模型，权重在这三种格式下各占多少内存？

<details markdown="1"><summary>检查</summary>

fp32 用 4 字节（28 GB），bf16 用 2 字节（14 GB），int8 用 1 字节（7 GB）。这只是权重本身，按名义位宽计算。

</details>

2. ▢ 为什么更小的权重格式通常能让批大小为 1 的解码更快？

<details markdown="1"><summary>检查</summary>

批大小为 1 的解码受内存带宽限制：每生成一个 token，每个权重都要读取一次，却只用于很少的算术，所以每个权重的字节数越少，要读的就越少。仅权重量化并不会让算术本身变快。

</details>

## 要点

### 三个字段

一个浮点数存储一个符号位、若干**指数位**和若干**尾数位**。对于一个规格化的值，指数字段 `e` 和尾数字段 `m` 给出

```text
value = (-1)^sign × 2^(e - bias) × (1 + m / 2^M)
```

其中 `M` 是尾数位数，`bias` 是一个固定的偏移量，使指数可以为负。指数决定这个值靠近 2 的哪一次幂。尾数则在这个 2 的幂与下一个 2 的幂之间的 2^M 个等间距的点里选定一个。指数字段全为 0 时，保留给零和非规格化值，后者比最小的规格化值更小，并以同样的间隔填满通往零的空隙。指数字段全为 1 时，在 IEEE 格式中保留给无穷大和 NaN。

| 格式 | 总位数 | 符号 / 指数 / 尾数 | 偏置 | 最大有限值 | 最小规格化值 | 机器精度 |
|---|---|---|---|---|---|---|
| fp32 | 32 | 1 / 8 / 23 | 127 | 3.4 × 10^38 | 1.2 × 10^-38 | 2^-23，约 1.2 × 10^-7 |
| fp16 | 16 | 1 / 5 / 10 | 15 | 65,504 | 6.1 × 10^-5 | 2^-10，约 9.8 × 10^-4 |
| bf16 | 16 | 1 / 8 / 7 | 127 | 3.4 × 10^38 | 1.2 × 10^-38 | 2^-7，约 7.8 × 10^-3 |

65,504 是 Micikevicius 等人给出的 fp16 所能表示的最大值（[Micikevicius 等，2017](https://arxiv.org/abs/1710.03740)）。其余各项由布局直接得出。**机器精度**是 1 与比它大的下一个值之间的间隔，即 2^-M。

有两个结论对本系列的后面很重要。第一，fp16 和 bf16 都占 2 字节，所以在二者之间选择，对内存毫无影响。这是在多三位尾数和多三位指数之间做选择。第二，bf16 就是去掉低 16 位的 fp32：符号字段和指数字段相同，尾数只保留最高的 7 位。Kalamkar 等人把这一点作为 bf16 有吸引力的原因：它的范围与 fp32 相同，与 fp32 之间的转换也很简单。

### 范围和精度是两回事

指数决定**范围**，即从最小值到最大值的跨度。尾数决定**精度**，即格式在这个跨度之内能多么接近地逼近一个值。二者互相独立，其中一个多出的每一位，都是从另一个那里拿走的。

间隔并不是恒定的。在 2^k 与 2^(k+1) 之间，相邻的值相隔 2^(k-M)，所以间隔在每一个 2 的幂处翻倍，而相对间隔大约保持在 2^-M。在 fp16 中，刚大于 1 的值相隔约 0.001，刚大于 1024 的值恰好相隔 1，刚大于 2048 的值则相隔 2。由此得出两点。一次加法的结果，如果落得离某个已有的值比离中点更近，就会被舍入回去，所以 fp16 中的 `1 + 0.0004` 仍然是 1，由若干个 1 累加起来的和，在 fp16 中到 2048 就不再增长。而且，一个舍入后的值最多偏离半个局部间隔，这就是量化始终会带来的**舍入误差**。

### 为什么 fp16 需要损失缩放而 bf16 不需要

fp16 只有 5 个指数位，所以范围很窄。它能存储的最小正值是 2^-24，比这更小的都会变成零。Micikevicius 等人度量了一次训练中的梯度值，发现约 5% 的权重梯度值的指数低于 -24，它们会丢失。他们的解决办法是**损失缩放**：在反向传播之前把损失乘以一个常数，使每个梯度都放大到 fp16 的范围内，然后在更新权重之前把这个缩放因子除掉。他们选取这个因子，使它与最大梯度绝对值的乘积保持在 65,504 以下，因为溢出会产生无穷大和 NaN，损害权重。

bf16 有 fp32 的 8 个指数位，所以同样的梯度都可以表示。Kalamkar 等人指出，保持 fp32 的范围，意味着收敛不需要调整超参数，而 fp16 需要。他们的仿真把 fp32 值的低 16 位清零，并在转换时比较了就近舍入与直接截断。在他们的一个实验中，就近舍入与 fp32 基线的准确率持平，而截断损失了约 0.02%。bf16 的代价是 7 位的尾数：相对而言，值之间只相隔约 0.8%。

对本系列来说，这一课讲的就是这笔权衡本身。8 位及以下的量化格式把同样的权衡做得难得多，这就是为什么第 4 课要加入一个缩放因子。

## 练习

1. ▢ 下面哪一种说法正确地比较了 fp16 和 bf16？

    - a) fp16 的指数位更多，所以范围更宽
    - b) bf16 的指数位更多，所以范围更宽
    - c) bf16 的尾数位更多，所以间隔更细
    - d) fp16 与 bf16 的总位数不同

<details markdown="1"><summary>检查</summary>

**b)** bf16 把 8 位用在指数上，而 fp16 是 5 位，这使它拥有 fp32 的范围，而它的尾数是 7 位，fp16 是 10 位。(a) 把两种格式说反了。(c) 则反着说反了：间隔更细的是 fp16。(d) 是错的，因为两者都是 16 位，所以内存无法把它们区分开。

</details>

2. ▢ 先预测，再运行。每一行会打印什么？

    ```python
    import numpy as np

    with np.errstate(over="ignore"):
        print(float(np.float16(65504)), float(np.float16(65519)))
        print(float(np.float16(65520)), float(np.float16(70000)))
    ```

<details markdown="1"><summary>提示</summary>

65,504 是 fp16 的最大有限值，再往上的下一个值会是 65,536。中点在哪里？高于中点的数会往哪个方向舍入？

</details>

<details markdown="1"><summary>检查</summary>

```text
65504.0 65504.0
inf inf
```

65,519 低于 65,504 与 65,536 之间的中点，所以向下舍入为 65,504。从 65,520 起，值会越过最大有限数而变成无穷大，在训练中，梯度溢出就是这样开始的。`errstate` 那一行只是让 NumPy 不再发出关于它的警告。

</details>

3. ▢ 先预测，再运行。三个和里，哪几个恰好等于 1？

    ```python
    import numpy as np

    one = np.float16(1)
    for d in (0.0004, 0.0005, 0.001):
        print(d, float(one + np.float16(d)))
    ```

<details markdown="1"><summary>提示</summary>

fp16 中 1 之上的间隔是 2^-10，约为 0.000977。一个和会落到离它更近的那个邻居上。

</details>

<details markdown="1"><summary>检查</summary>

```text
0.0004 1.0
0.0005 1.0009765625
0.001 1.0009765625
```

只有第一个。1 的邻居是 1 和 1.0009765625，中点约为 1.000488。0.0004 落在它的下方，被完全丢失，而 0.0005 则整整跳了一个 2^-10。把一个值加到比它大的值上，并不是“有一点不准”：只要低于局部间隔的一半，它就消失了。

</details>

4. ▢ 先预测，再运行。这段代码会打印什么？它说明了在 fp16 中累加许多小数的什么问题？

    ```python
    import numpy as np

    total = np.float16(0)
    for _ in range(3000):
        total = total + np.float16(1)
    print(float(total))
    ```

<details markdown="1"><summary>提示</summary>

2048 以上，fp16 的间隔是 2。2048 + 1 会怎样？

</details>

<details markdown="1"><summary>检查</summary>

```text
2048.0
```

在 2048 处，间隔是 2，所以 2049 恰好落在两个可表示的值正中间，并舍入到偶数的那个，即 2048。此后剩下的 952 次加法，和一直停在那里。这就是 Micikevicius 等人把 fp16 的乘积累加到 fp32 而不是 fp16 中的原因。

</details>

5. ▢ 先预测，再运行。bf16 就是去掉低 16 位的 fp32。运行之前，先说出前三个值里哪几个在转换后保持不变，以及 1e38 在 fp16 中会怎样。

    ```python
    import numpy as np

    def to_bf16(x):
        bits = np.asarray(x, dtype=np.float32).view(np.uint32) & np.uint32(0xFFFF0000)
        return bits.view(np.float32)

    x = np.array([1 + 2**-7, 1 + 2**-8, 3.14159265, 1e38], dtype=np.float32)
    print([float(v) for v in to_bf16(x)])
    with np.errstate(over="ignore"):
        print(float(np.float16(1e38)))
    ```

<details markdown="1"><summary>提示</summary>

bf16 保留 7 位尾数，所以 1 + 2^-7 是它能容纳的、比 1 大的第一个值。1 + 2^-8 又是多少？

</details>

<details markdown="1"><summary>检查</summary>

```text
[1.0078125, 1.0, 3.140625, 9.969209968386869e+37]
inf
```

1 + 2^-7 保留下来了，1 + 2^-8 被截断成恰好等于 1，而 pi 变成 3.140625，约有三位数字是准确的。1e38 仍然是有限的，因为尾数被截掉了，所以约为 9.97e37，但 fp16 会把它变成无穷大。这个函数做的是截断，Kalamkar 等人描述的他们的仿真也是这样做的，他们把它与就近舍入做了比较。

</details>

6. ▢ 一位队友用 fp16 训练，几百步之后看到损失变成了 NaN，于是提议改用 bf16。请解释这很可能是怎么回事，损失缩放对此做了什么，以及 bf16 会改变什么。

<details markdown="1"><summary>检查</summary>

fp16 的上限是 65,504，所以放大后的损失或者很大的梯度可能溢出成无穷大和 NaN，而低于 2^-24 的小梯度则会变成零。损失缩放选取一个常数，使梯度落在 fp16 的范围之内，并在更新权重之前把缩放因子除掉。bf16 拥有 fp32 的指数范围，所以这两个问题都不会出现，也不需要缩放因子，代价是尾数更粗。只有当这个 NaN 确实是范围问题时，改用 bf16 才是一个站得住脚的修复。由糟糕的学习率或糟糕的批次引起的 NaN，换了格式也还在。

</details>
