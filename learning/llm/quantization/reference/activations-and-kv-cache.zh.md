# 激活值与 KV 缓存：权重之外的量化

把第 5 阶段压缩成便于查阅的形式。[第 13 课](../lessons/0013-weights-activations-or-both.md)讲仅权重量化与权重加激活值量化，[第 14 课](../lessons/0014-smoothquant.md)讲 SmoothQuant，[第 15 课](../lessons/0015-rotations.md)讲旋转，[第 16 课](../lessons/0016-kv-cache-quantization.md)讲 KV 缓存量化。

## 权重、激活值，还是两者兼顾

| 方案 | 以小体积存储的 | 矩阵乘法以什么精度运行 | 买到什么 | 适合 |
|---|---|---|---|---|
| W4A16、W8A16（仅权重） | 权重 | 16 位，在内核里反量化之后 | 内存，每个 token 读取的字节 | 受内存带宽限制：小批量解码 |
| W8A8 int8 或 fp8 | 权重和激活值 | 8 位 | 算术吞吐量，外加内存 | 受算力限制：预填充、大批量 |
| 带旋转的 W4A4 | 权重、激活值，常常还有 KV | 4 位 | 内存和算术 | 只在存在 4 位内核的地方，见第 20 课 |

Kurtic 等人（Llama 3.1 系列，超过 500,000 次评测）：fp8 W8A8 实际上无损，调得好的 int8 W8A8 下降 1% 到 3%，W4A16 int 可媲美 8 位。建议：同步服务用 W4A16，连续批处理用 W8A8。

## 为什么激活值更难

| 性质 | 权重 | 激活值 |
|---|---|---|
| 范围是否已知 | 训练之后就固定了 | 只有运行时才知道 |
| 离群值 | 平坦，容易量化 | 比大多数值大约 100 倍，位于所有 token 上固定的通道中（SmoothQuant） |
| int8 GEMM 允许的缩放因子粒度 | 逐输出通道 | 只能逐张量或逐 token |

int8 GEMM：`Y = diag(s_X) · (X_int8 @ W_int8) · diag(s_W)`。缩放因子只放在外侧维度上；逐输入通道的缩放因子会落在求和内部。

| 激活值缩放因子 | 何时计算 | 代价 | 风险 |
|---|---|---|---|
| 静态 | 离线，根据校准集 | 每个请求没有代价 | 校准集与真实流量不像 |
| 动态 | 运行时，根据张量 | 每次矩阵乘法之前做一次归约 | 很小；对每个输入自适应 |

## SmoothQuant

```text
X @ W = (X @ diag(s)^-1) @ (diag(s) @ W)
s_j   = max(|X_j|)^α / max(|W_j|)^(1 - α)
```

| `α` | 效果 |
|---|---|
| 0 | 激活值不变 |
| 0.5 | 论文中平衡的默认值，OPT 和 BLOOM 的最佳点 |
| 更大，趋向 1 | 更多难度转移到权重上；用于离群值更重的模型，例如 GLM-130B |
| 1 | 每个激活值通道的最大值相同；权重承载全部离群值 |

- `max(|X_j|)` 来自校准集。
- 这个因子被离线融合进产生 `X` 的那一层：没有运行时代价。
- 一种 8 位方法：论文中最高 1.56 倍的加速和 2 倍的内存缩减。

## 旋转

```text
X @ W = (X @ Q) @ (Q.T @ W)      where Q @ Q.T = I
```

| 要点 | 细节 |
|---|---|
| 它做什么 | 把离群值分散到所有通道上；最大值接近均方根 |
| 常用的 `Q` | 随机化哈达玛：元素为 ±1/sqrt(n)，开销 `n log n` |
| 离线融合 | 残差流的旋转，融合进权重 |
| 在线 | 在前馈网络下投影之前；对查询和键做逐头旋转，在 RoPE 之后 |
| QuaRot | 所有权重、激活值和 KV 缓存都是 4 位；Llama 2 70B 的 WikiText-2 困惑度仅差 0.47，保留 99% 的零样本性能 |
| SpinQuant | 随机旋转之间零样本最多相差 13 个点；学习出来的旋转，在 Llama 2 7B W4A4KV4 上把差距缩小到 2.9 个点 |

对任何 W4A4 声明的评审问题：用的是哪个旋转，是针对这个模型选定的还是学习出来的？

## KV 缓存量化

```text
KV bytes per token = 2 x layers x kv_heads x head_dim x bytes_per_value
```

bf16 的 Llama 3 8B（32 层，8 个 KV 头，维度 128）：每个 token 128 KiB，每条 32,768 个 token 的序列 4 GiB。

| 张量 | 沿哪个方向量化 | 原因 |
|---|---|---|
| 键 | 逐通道，尽可能在 RoPE 之前 | 有少数几个固定的离群通道（KIVI）；RoPE 把通道成对混合（KVQuant） |
| 值 | 逐 token | 没有通道模式；注意力输出的误差比逐通道小将近 15 倍（KIVI） |

| 方法或选项 | 位数 | 报告的结果 |
|---|---|---|
| KIVI | 2 | 质量几乎相同，峰值内存减少为 1/2.6，批最大 4 倍，吞吐量 2.35 到 3.47 倍 |
| KVQuant | 3 | 困惑度下降不到 0.1；在一块 80 GB 的 A100 上以 100 万的上下文跑 LLaMA-7B |
| vLLM fp8 KV 缓存 | 8 | 逐张量或逐头的缩放因子；不做校准时默认缩放因子为 1.0，建议校准 |

KIVI 把最新的 token（实验中是 128 个）保留为全精度，直到一个逐通道的键分组完整为止。
