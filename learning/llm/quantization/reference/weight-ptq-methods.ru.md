# Методы PTQ для весов: сравнение округления к ближайшему, GPTQ и AWQ

Этап 4 в сжатом виде для быстрого поиска. [Урок 9](../lessons/0009-round-to-nearest.md) охватывает округление к ближайшему (RTN), [урок 10](../lessons/0010-gptq.md) GPTQ, [урок 11](../lessons/0011-awq.md) AWQ, а [урок 12](../lessons/0012-the-calibration-set.md) калибровочный набор.

## Три метода рядом

| | Округление к ближайшему | GPTQ | AWQ |
|---|---|---|---|
| Идея | Округлить каждый вес до ближайшего уровня | Округлять столбцы по порядку, перекладывая каждую ошибку на ещё не округлённые столбцы | Увеличить масштабом значимые входные каналы до округления, разделить активацию на тот же масштаб |
| Что читает из данных | Ничего | Входы слоя, суммируемые в `H = 2 X X^T` | Среднюю величину активации на канал, плюс выходы слоя, чтобы оценить каждое `alpha` |
| Меняет значения весов | Нет | Да, каждый следующий столбец после каждого округления | Да, масштабом на канал `s = s_X^alpha`, затем округляет к ближайшему |
| Целевая функция | Собственная ошибка каждого веса | `argmin \|\| W X - Ŵ X \|\|^2` на слой | Та же ошибка выхода слоя, поиск по `alpha` в [0, 1] |
| Обратное распространение | Нет | Нет | Нет |
| Стоимость | Пренебрежимая | Около 4 часов GPU для 175 млрд параметров (статья) | Сетка из 20 значений `alpha` на слой (статья) |
| Сетка | Один масштаб на строку или на группу | Фиксируется до цикла; масштаб per-group задаётся, когда цикл доходит до группы | Per-group, 128 в статье |
| Главный риск | Рушится в 3 битах с масштабами по строкам | Переобучается на малый или неподходящий калибровочный набор | Слишком сильное масштабирование вредит незначимым каналам |

## Что каждый делает с числами

| Перплексия на WikiText-2 | 16 бит | RTN | GPTQ | AWQ |
|---|---|---|---|---|
| OPT-175B, 4 бита, сетка по строкам | 8,34 | 10,54 | 8,37 | там не сообщено |
| OPT-175B, 3 бита, сетка по строкам | 8,34 | 7300 | 8,68 | там не сообщено |
| Llama-2 7B, 4 бита, группы по 128 | 5,47 | 5,73 | 5,69 | 5,60 |
| Llama-2 7B, 3 бита, группы по 128 | 5,47 | 6,66 | 6,43 | 6,24 |

Первые две строки взяты из статьи о GPTQ, а последние две из статьи об AWQ. Сетки и модели различаются, поэтому сравнивайте внутри строки и форму между строками, а не числа между ними. Каждая статья оценивает свой метод против другого, поэтому читайте разрывы как запуски авторов.

## Почему ошибка ведёт себя именно так

| Факт | Следствие |
|---|---|
| Каждый убранный бит примерно удваивает шаг | Ошибка округления к ближайшему примерно удваивается на бит |
| В игрушечном примере урока 9 отношения ошибок равны отношениям шагов: 127 / 7 = 18,1 от 8 к 4 битам, 7 / 3 = 2,3 от 4 к 3 | Последние биты самые дорогие |
| Округление к ближайшему минимизирует ошибку каждого веса, а не ошибку выхода слоя | 919 из 2000 случайных округлений побеждают его на коррелированном игрушечном слое |
| Выигрыш GPTQ идёт от коррелированных входов | При независимых входах он почти исчезает (0,2680 против 0,2595 в игрушечном примере) |
| Значимый вес выбирают по его активации, а не по размеру | На OPT-6.7B в 3 битах 1%, выбранный по активации, даёт 11,39, по размеру веса 22,37, обычное округление к ближайшему 23,54 |
| Масштабирование канала на `s` уменьшает его относительную ошибку примерно в `1 / s` раз | Слишком большое `s` повышает шаг для других каналов в группе |

## Три изменения GPTQ для масштабирования и act-order

| Изменение | Что оно исправляет |
|---|---|
| Один порядок столбцов для каждой строки | Одно обновление обратной матрицы на столбец обслуживает все строки |
| Ленивые пакетные обновления, по 128 столбцов за раз | Обновление ограничено памятью, поэтому пакетирование задействует GPU |
| Демпфирование в 1% средней диагонали плюс множитель Холецкого | Численная ошибка, способная сделать обратную матрицу неопределённой |
| Act-order (код авторов, не статья): столбцы отсортированы по диагонали `H`, наибольшие первыми | Исправляет плохие результаты, например OPT-66B в 3 битах (с 14,16 до 9,95); может потребовать изменений инференса, если не использовать статические группы |

## Что делает калибровочный набор

| | GPTQ | AWQ |
|---|---|---|
| Типичный размер | Статья: 128 сегментов по 2048 токенов из C4 | AWQ на 16 последовательностях побеждает GPTQ на 192 на OPT-6.7B, 3 бита (запуск авторов) |
| llm-compressor | Типично 128-512 образцов, начинать с 128-256 | Тот же совет; в его примере 256 |
| Нужно больше данных, потому что | Он оценивает целую матрицу совместной вариации признаков | Он оценивает одно среднее на канал |
| Штраф за несовпадение, OPT-6.7B, 3 бита (статья об AWQ) | Хуже на 2,3-4,9 перплексии | Хуже на 0,5-0,6 |

- Округление к ближайшему не требует данных. GPTQ и AWQ нужен калибровочный набор. Ни один не пропускает через него обратное распространение.
- Калибровочный набор это не обучающие данные, и его предметная область проявляется в результате.
- Подбирайте набор под целевое применение: обычный текст для модели общего назначения, инструктивные данные для инструктивной модели, код для модели для программирования (llm-compressor).
- Оценивайте на отложенном тексте из калибровочной области и на тексте из других областей, которые вы обслуживаете. Выигрыш в одной и потеря в другой это несовпадение.
- Перплексия, измеренная на тексте, из которого взят набор, приукрашена. Статья о GPTQ говорит, что её результаты на C4 по этой причине не вполне zero-shot.
- В игрушечном примере урока 12 слишком малое число образцов (64 на 128 признаков) сделало GPTQ хуже округления к ближайшему даже внутри области.

## Прежде чем доверять чекпоинту с PTQ весов

- Какой метод, какая разрядность и какой размер группы или сетка.
- Какой калибровочный набор, сколько образцов и какой длины. Если карточка модели этого не говорит, это пробел.
- Измерена ли указанная перплексия на калибровочной области.
- Измерялась ли базовая модель без данных на той же сетке на той же оценке.
- Для GPTQ с act-order и группами: нужны ли ему изменения инференса, которые могут стоить скорости, или он сделан со статическими группами.
