# RAG 术语表

检索流水线的规范术语：它把文档切分成什么，以及它如何决定把什么交给生成步骤。

## 术语

**智能体式检索（Agentic retrieval）**:
系统针对每个查询、每一步自行判断：是否需要检索，返回的内容是否足够，是否要根据刚刚得出的信息再检索一次，而不是只走一遍固定的先检索后生成流程。
_避免使用_: 多跳检索（multi-hop retrieval，这是相关但范围更窄的情形：多跳检索专指查询中后面的子问题依赖前一个子问题的答案，而智能体式检索还包括是否需要检索这个问题）

**文本块（Chunk）**:
文档在嵌入和建立索引之前被切分出的一段，大小要让它的嵌入向量聚焦于一个主题，而不是几个主题的平均。
_避免使用_: 片段（segment）、段落（passage，只在引用使用该词的来源时才用）

**分块（Chunking）**:
把文档切分成文本块的过程，可以按固定大小切，按文档自身的结构切，或者通过检测主题的转换处来切。
_避免使用_: 切分（splitting，过于笼统，只在描述机械切割动作的行文中使用，不要用作这一过程的名称）

**上下文窗口利用率（Context window utilization）**:
生成的答案中实际引用的文本块数量，与检索出并放入提示词的文本块数量之比。利用率低，说明 token 花在了模型从未用到的上下文上；利用率一直很高，则可能是在预警：关键材料在被引用之前，就已经被截出了上下文窗口。
_避免使用_: 认为利用率越高越好（在高位时，它是截断的预警信号，而不是单纯的效率提升）

**错误级联（Error cascading）**:
摄取早期步骤中的一个错误（认错了标题，把多栏内容按错误的顺序合并）会传播到之后每一个基于这份已损坏结构的步骤，破坏一整节内容最终生成的所有文本块，而不是只局限在错误直接涉及的那一个元素上。
_避免使用_: 孤立的解析错误（isolated parsing error，低估了影响；把它叫作级联，要点就在于早期的一个错误会不断放大，而不是停留在局部）

**HyDE（Hypothetical Document Embeddings，假设文档嵌入）**:
不嵌入查询本身，而是嵌入语言模型针对该查询生成的假设性答案，再按与该嵌入的相似度在语料库中检索。它能容忍假设文档中事实错误的细节，因为编码器的嵌入步骤会把这些细节过滤掉，同时保留真正的主题相似性。
_避免使用_: 查询改写（query rewriting，这是另一种查询侧的修补：改写是重新表述查询本身，而 HyDE 嵌入的是生成的答案，而不是查询）

**增量索引（Incremental indexing）**:
向已经建好的索引中添加新向量，而不必从头重建。HNSW 对此支持良好，因为它没有训练步骤；IVFFlat 则较弱，它的聚类中心在构建时就已固定，之后不会重新计算，所以与原始训练数据不同的新增内容，可能会聚类得很差。
_避免使用_: 重建索引（reindexing，指从头完整重建，只在嵌入模型改变时才必须进行，与向一个未变的索引增量添加新向量不是同一种操作）

**摄取（Ingestion）**:
把原始来源文档（PDF、HTML 页面或办公文件）转成分块真正处理的那份干净、有结构的文本。它是位于分块上游的一个真正的流水线阶段，有自己的失败模式，而不是流水线可以忽略的底层预处理细节。
_避免使用_: 把分块当作流水线的第一个阶段（分块假定摄取已经产出了干净的文本，而摄取才是真正产出它的那一步）

**元数据过滤（Metadata filtering）**:
除了最近邻相似度之外，再把检索限制在满足结构化属性（文档类型、日期、所有者、权限标签）谓词的文本块上，而不是只按相似度在整个语料库中检索。
_避免使用_: 权限过滤（permission filtering，这是元数据过滤中风险更高的一种具体情形：它一旦失败就是安全事件，而不是质量退化，并且明确要求使用预过滤）

**多跳检索（Multi-hop retrieval）**:
在循环中检索，后一次查询依赖于从前一次检索中得出的事实，而不是事先就确定好的一组固定子问题。当某个子问题在前一个子问题的答案出来之前甚至无法表述时，就需要它，而单靠查询分解处理不了这种情况。
_避免使用_: 查询分解（query decomposition，拆分的是原问题文字里已经可见的子问题，而多跳检索处理的是在前一跳的答案产生之前并不存在的子问题）

**后过滤（Post-filtering）**:
先运行 ANN 搜索，之后再丢弃不满足谓词的结果。它很快，但选择性强的谓词可能会丢掉近似索引在有限候选扫描中找到的大部分结果，使召回率骤降；对于权限过滤来说，这还意味着未授权的内容在被丢弃之前，曾短暂地存在于流水线中。
_避免使用_: 预过滤（pre-filtering，在 ANN 搜索运行之前就限制候选集，针对过滤后的集合保住召回率，并且根本不会让不允许的内容进入流水线）

**预过滤（Pre-filtering）**:
在 ANN 搜索运行之前，先把候选集限制为只含满足谓词的文本块，无论谓词的选择性多强，都能针对这个过滤后的集合保住召回率。访问控制尤其需要它，因为未授权的内容从一开始就不会进入流水线。
_避免使用_: 后过滤（post-filtering，先搜索整个索引，之后再丢弃；召回率以及对权限过滤而言的安全保证本身，都可能受损）

**查询分解（Query decomposition）**:
把复合问题拆成各自独立的子问题，并分别检索，而不是把整个复合问题嵌入成一个向量，那个向量离能很好回答其中任何一部分的段落都很远。
_避免使用_: 多查询扩展（multi-query expansion，这是另一种技术：扩展是为一个问题生成多种完整的改写表述，而分解是把一个问题拆成各自更窄的子问题）

**无参照评分（Reference-free scoring）**:
由 LLM 对每个检索出的文本块给出相关性分数，不需要已知的正确答案，并在一个时间窗口内汇总为命中率或平均相关性。生产环境的监控用它来代替 recall@k 或 MRR，因为后两者都需要带标注的或合成的查询集，而大多数线上流量并没有。
_避免使用_: recall@k、MRR（需要已知正确结果的离线指标；在没有这类标注时，无参照评分正是生产环境中的替代方案）

**重建索引（Reindexing）**:
从头重建向量索引，嵌入模型本身改变时必须这样做，因为每个已有的向量都出自旧模型自己的向量空间，与新模型的嵌入之间没有可比较的距离。这与增量索引是不同的操作，也不同于删除和更新所需的定期维护。
_避免使用_: 增量索引（incremental indexing，向一个未变的索引添加新向量；重建索引专指因为产生向量的模型变了，而把一切重建一遍）
