# 学习：RAG

能够为真实的语料库和用例设计检索流水线，并在现有的 RAG 系统返回错误上下文时，诊断出问题究竟在哪里，而不是靠猜去修。

**最新课程：** [20. 评审检索流水线](lessons/0020-reviewing-a-retrieval-pipeline.md)

## 成功的标准

- 针对给定的语料库和用例，设计检索流水线（分块、嵌入、混合检索、重排序），并对照它论证每一个选择。
- 面对返回了错误或无关上下文的 RAG 系统，诊断出是流水线的哪个阶段出了问题，而不是随机地重新调参。
- 对照测得的检索指标，而不是凭感觉，来调节混合检索的权重。
- 把检索到的上下文一路带到生成的答案，并说明生成步骤本身仍然可能出什么错。
- 评审别人的检索流水线设计，在它上线之前具体指出它会出什么错，并说明什么时候 RAG 本身（而不是某个流水线阶段）就是对所述问题的错误答案。

## 约束

- 假定具备基本的 Python 知识，并了解嵌入是什么；不要求有检索系统的经验。
- 向量存储：pgvector，所以这些概念与 `data/postgres` 中关于向量索引会给数据库带来什么成本的内容相衔接。

## 范围之外

- 提示词工程技巧和一般意义上的生成质量：见 [`llm/prompting`](../../llm/prompting/)。这里只涉及检索到的上下文如何到达生成步骤，不作为独立的主题重述。
- 检索指标本身是如何构建并论证的：见 [`llm/evals`](../../llm/evals/)，只链接过去，不再重述。
- 向量索引在运维上会给数据库带来什么成本：见 [`data/postgres`](../../data/postgres/)，只链接过去，不再重述。

## 学习路线

共十四个阶段，从第一个文本块，到经过诊断、考虑了成本并受到监控的生产流水线，最后以判断力收尾。一个阶段包含若干课程，边界并不严格；一个阶段是否完成，取决于能力，而不是课程数量。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. 分块 | 0001 | 第一个流水线选择，也是之后每个阶段都会继承的选择 | 能为给定的语料库分块，并论证这个选择 |
| 2. 嵌入 | 0002 至 0003 | 嵌入模型、相似度度量、维度的权衡 | 能为给定的语料库选择嵌入模型和度量 |
| 3. 向量搜索与索引 | 0004 至 0005 | ANN 索引（HNSW/IVF）、pgvector 的细节、召回率与延迟的权衡 | 能在 pgvector 上为已分块的语料库搭建向量搜索 |
| 4. 混合检索 | 0006 至 0007 | BM25 加向量搜索、倒数排名融合、调节混合比例 | 能对照测得的检索指标调节混合检索的权重 |
| 5. 重排序 | 0008 至 0009 | 交叉编码器重排序器、重排序何时值回它的延迟成本 | 能加入重排序阶段，并对照成本论证它 |
| 6. 检索评估与诊断 | 0010 至 0011 | Recall@k、MRR、诊断是哪个流水线阶段出了问题 | 面对错误的检索上下文，能指出出问题的阶段 |
| 7. 从检索到生成 | 0012 至 0013 | 基于检索到的上下文构造提示词、上下文窗口预算、生成仍会出的错 | 能把检索到的上下文带到生成的答案，并说出生成阶段的失败模式 |
| 8. 查询侧转换 | 0014 | HyDE、查询改写、多查询扩展、查询分解 | 面对第 11 课的流程抓不到的查询侧失败，能选出并论证合适的补救办法 |
| 9. 元数据过滤与权限感知检索 | 0015 | 元数据过滤、预过滤与后过滤、为什么访问控制尤其需要预过滤 | 能设计权限感知的检索路径，并解释为什么后过滤对它来说不安全 |
| 10. 摄取流水线 | 0016 | 解析 PDF/HTML/办公文档、版面感知与朴素提取、表格结构、错误级联 | 能解释为什么摄取位于分块的上游，以及一次糟糕的解析如何躲过第 11 课的诊断 |
| 11. 新鲜度 | 0017 | 增量索引（HNSW 与 IVFFlat）、删除和更新的维护、模型变更时的重建索引 | 能针对语料库及其索引变得陈旧的三种真正不同的方式做出规划 |
| 12. 多跳检索与智能体式检索 | 0018 | IRCoT 的交错推理与检索、Self-RAG 的自适应检索决策 | 能为单靠分解无法回答的问题设计检索循环 |
| 13. 成本、延迟与生产监控 | 0019 | 整条流水线的延迟预算、上下文窗口利用率、无参照评分、嵌入漂移 | 能为整条流水线制定延迟预算，并在它上线之后，无需真值就监控检索质量 |
| 14. 判断力 | 0020 | 评审流水线、判定 RAG 与长上下文相比何时是正确答案、指出会出什么错 | 值得信任去评审别人的检索设计，并准确解释某个选择为什么会失败 |

请按顺序学习。

| [0005](lessons/0005-pgvector-specifics.md) | pgvector 详解 | 在 Postgres 中搭建向量搜索，并把第 4 课的索引概念对应到 pgvector 实际的运算符和参数上 |
| [0006](lessons/0006-bm25-and-lexical-search.md) | BM25 与词法检索 | BM25 实际在给什么打分，以及为什么精确的词项匹配仍然能抓住语义嵌入漏掉的内容 |
| [0007](lessons/0007-reciprocal-rank-fusion.md) | 倒数排名融合 | 如何在不比较不可比分数的前提下，合并词法排名和向量排名，以及如何对照测得的指标来调节混合比例 |
| [0008](lessons/0008-cross-encoder-rerankers.md) | 交叉编码器重排序器 | 交叉编码器能给双编码器无法打分的什么内容打分，以及为什么重排序是第二阶段，而不是对检索的替代 |
| [0009](lessons/0009-when-reranking-earns-its-cost.md) | 重排序何时值回成本 | 判断一个重排序阶段对给定工作负载是否值得其增加的延迟的决策框架 |
| [0010](lessons/0010-recall-at-k-and-mrr.md) | Recall@k 与 MRR | 两个标准的检索指标，各自能告诉你对方告诉不了的什么，以及如何根据工作负载选择 k |
| [0011](lessons/0011-diagnosing-the-pipeline.md) | 诊断流水线 | 逐阶段排查的流程，找出检索流水线中究竟是哪一部分导致了错误的检索上下文 |
| [0012](lessons/0012-prompt-construction-and-context-budget.md) | 提示词构造与上下文窗口预算 | 为什么检索到的文本块要争夺共享的上下文窗口预算，以及为什么文本块在提示词中的位置，与它有没有被检索到同样重要 |
| [0013](lessons/0013-what-generation-still-gets-wrong.md) | 生成环节仍会出的错 | 即使检索到的上下文正确且位置得当，仍然会存在的失败模式，以及它们与检索失败有何不同 |
| [0014](lessons/0014-query-side-transformation.md) | 查询侧转换 | 第 11 课的诊断流程检查了分块、嵌入、索引、混合权重和重排序，却从不检查查询本身，而一个过短、过于复合、或措辞与语料库毫不相像的查询，需要自己专门的补救办法，而不是再去修一个流水线阶段 |
| [0015](lessons/0015-metadata-filtering-and-access-control.md) | 元数据过滤与权限感知检索 | 失败的访问控制过滤既不会崩溃，也看不出有错，它会产出一个格式完好的答案，其依据是用户本不该看到的文档，这正是为什么后过滤对这一种过滤来说是错误的选择 |
| [0016](lessons/0016-the-ingestion-pipeline.md) | 摄取流水线 | 分块其实从来不是流水线的第一个阶段，它只是假定干净的输入文本已经存在，而分块上游的一次糟糕解析，会破坏其后的一切，在之后的每一种诊断看来，都像是一种完全不同的失败 |
| [0017](lessons/0017-freshness.md) | 数据新鲜度 | 不断变化的语料库需要三种真正不同的应对办法，而不是一种，因为新增文档、删除文档和更换嵌入模型，各自打破了索引赖以构建的一项不同的假设 |
| [0018](lessons/0018-multi-hop-and-agentic-retrieval.md) | 多跳检索与智能体式检索 | 分解把复合问题拆成在原文中就能看到的子问题，但有些问题的后半部分，要等前半部分的答案回来才会显现，这就需要真正的循环，而不是更聪明的事先拆分 |
| [0019](lessons/0019-cost-latency-and-production-monitoring.md) | 成本、延迟与生产监控 | 一条流水线在每一项普通的基础设施指标上都可能看起来完全健康，却悄悄地给出一个自信的答案，其依据是一份从未真正送达模型的文档，而这个缺口，正是针对检索的监控所要弥补的 |
| [0020](lessons/0020-reviewing-a-retrieval-pipeline.md) | 评审检索流水线 | 评审别人的检索流水线设计，在它上线之前具体指出它会出什么错，并说明什么时候 RAG 本身（而不是某个流水线阶段）就是对所述问题的错误答案 |

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
