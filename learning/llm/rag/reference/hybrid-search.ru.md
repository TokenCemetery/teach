# Гибридный поиск

Объединение лексического и векторного рейтингов. Для быстрого поиска при развёртывании или настройке гибридной смеси.

## BM25 оценивает пересечение терминов, а не смысл

Чисто лексическая функция ранжирования, без эмбеддингов и без понятия смысла. Три составляющие:

| Составляющая | Что делает |
|---|---|
| Обратная частота документа (IDF) | Взвешивает термин запроса по редкости в корпусе; частое слово вроде «и» почти ничего не вносит |
| Частота термина, с насыщением | Больше вхождений термина повышают оценку, но с убывающей отдачей, так что одно повторение (набивка ключевыми словами) не может доминировать |
| Нормализация по длине | Снижает преимущество по сырой частоте терминов, которое документ получает просто от того, что он длиннее |

## У BM25 и векторного поиска противоположные слепые пятна

| Вид запроса | BM25 | Векторный поиск |
|---|---|---|
| Точный идентификатор («код ошибки E502») | Находит: буквальная строка есть | Может пропустить: модель эмбеддингов обучена на семантическое сходство, а не на точное совпадение идентификаторов |
| Синонимичная формулировка без общих слов («прорыв трубы» / «протечка в водоводе») | Оценка около нуля: пересечения терминов нет совсем | Находит: две фразы значат одно и то же |

Каждый подход ловит то, что пропускает другой, и на этом целиком держится их объединение.

## Слияние по взаимным рангам (RRF): использовать ранг, а не оценку

Оценка BM25 неограничена и зависит от корпуса; косинусное сходство ограничено отрезком [-1, 1]. Усреднять их напрямую значит изобретать хрупкую, специфичную для корпуса нормализацию. **RRF** обходит проблему шкал, используя только позицию каждого документа в каждом рейтинге:

```text
RRF(d) = sum over rankings r of 1 / (k + rank_r(d))
```

`k` приглушает влияние самых верхних мест (общепринятое значение по умолчанию `k = 60`; меньшее `k` делает различия в позиции у верха значимее, большее `k` приглушает их). Позиция в рейтинге это общая валюта для любого метода ранжирования, поэтому нормализация между BM25 и векторным поиском не нужна.

**Разобранный пример**, `k = 1`, BM25 ставит A первым / B четвёртым / C вторым, векторный поиск ставит A четвёртым / B первым / C вторым:

```text
RRF(A) = 1/(1+1) + 1/(1+4) = 0.500 + 0.200 = 0.700
RRF(B) = 1/(1+4) + 1/(1+1) = 0.200 + 0.500 = 0.700
RRF(C) = 1/(1+2) + 1/(1+2) = 0.333 + 0.333 = 0.667
```

A и B делят первое место, каждый блестящ в одном методе и слаб в другом; C, лишь посредственный в обоих, проигрывает им обоим. RRF вознаграждает документ, в который сильно верит любой один метод, а не только тот, с которым оба метода слегка согласны.

## Настройка смеси

RRF расширяется весом на каждый рейтинг, `sum of w_r / (k + rank_r(d))`, позволяя векторному поиску значить больше или меньше, чем BM25. Верный вес и `k` не угадывают: измерьте качество поиска (recall@k, MRR) на размеченном или синтетическом наборе запросов, репрезентативном для реального трафика корпуса, при нескольких весах-кандидатах и выпускайте ту смесь, которая для этого корпуса действительно чаще находит верные документы, а не разбиение 50 на 50 по умолчанию.
