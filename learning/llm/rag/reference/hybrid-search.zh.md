# 混合检索

合并词法排名和向量排名。便于在搭建或调节混合比例时查阅。

## BM25 给词项重叠打分，而不是给含义打分

这是一种纯粹的词法排序函数，不涉及嵌入，也没有“含义”的概念。三个要素：

| 要素 | 作用 |
|---|---|
| 逆文档频率（IDF） | 按查询词项在语料库中有多罕见来加权；像“the”这样的常见词几乎没有贡献 |
| 饱和的词频 | 词项出现得越多，分数越高，但收益递减，所以单靠重复（关键词堆砌）无法主导 |
| 长度归一化 | 削弱文档仅仅因为更长而获得的原始词频优势 |

## BM25 和向量搜索有相反的盲点

| 查询形态 | BM25 | 向量搜索 |
|---|---|---|
| 精确标识符（“error code E502”） | 能匹配：字面字符串出现了 | 可能漏掉：嵌入模型是为语义相似性训练的，而不是为精确标识符匹配 |
| 没有共同词的同义说法（“broken pipe” / “leaking conduit”） | 得分接近零：完全没有词项重叠 | 能匹配：这两个短语的意思相同 |

每种方法都能抓住另一种漏掉的东西，这正是把它们结合起来的全部依据。

## 倒数排名融合（RRF）：用排名，不用分数

BM25 的分数无界且依赖语料库；余弦相似度则界于 [-1, 1] 之间。直接把二者取平均，就意味着要自己发明一种脆弱的、针对特定语料库的归一化方法。**RRF** 绕开了尺度问题，办法是只使用每篇文档在各个排名中的排名位置：

```text
RRF(d) = sum over rankings r of 1 / (k + rank_r(d))
```

`k` 削弱最靠前几名的影响（常用的默认值是 `k = 60`；较小的 `k` 使靠前位置的排名差异更重要，较大的 `k` 则削弱它们）。排名位置对任何排序方法都是通用的货币，所以 BM25 和向量搜索之间不需要归一化。

**算例**，`k = 1`，BM25 把 A 排第 1 / B 排第 4 / C 排第 2，向量搜索把 A 排第 4 / B 排第 1 / C 排第 2：

```text
RRF(A) = 1/(1+1) + 1/(1+4) = 0.500 + 0.200 = 0.700
RRF(B) = 1/(1+4) + 1/(1+1) = 0.200 + 0.500 = 0.700
RRF(C) = 1/(1+2) + 1/(1+2) = 0.333 + 0.333 = 0.667
```

A 和 B 并列第一，各自在一种方法下表现出色，在另一种方法下表现不佳；而 C 在两种方法下都只是中等，输给了前两者。RRF 奖励的是任何一种方法强烈看好的文档，而不只是两种方法都勉强认同的文档。

## 调节混合比例

RRF 可以扩展为给每个排名加权重，即 `sum of w_r / (k + rank_r(d))`，让向量搜索的分量比 BM25 更重或更轻。合适的权重和 `k` 不是靠猜的：针对能代表语料库真实流量的、带标注的或合成的查询集，在几种候选权重下测量检索质量（recall@k、MRR），上线那个在这个语料库上更常检索到正确文档的混合比例，而不是默认的 50/50 分配。
