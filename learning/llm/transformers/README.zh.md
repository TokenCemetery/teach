# 学习：Transformer

能够从原始张量实现 Transformer 的前向传播及其训练循环，并且能够阅读或修改真实的模型代码，而不让这个架构成为它背后的黑箱。

**最新课程：** [23. 评审对模型代码的改动](lessons/0023-reviewing-a-change-to-model-code.md)

## 成功的标准

- 从原始张量实现缩放点积注意力、多头注意力和完整的 Transformer 块，输出与参考实现一致。
- 从零写出围绕这个块的训练循环，并解释每一部分（损失、反向传播、优化器步骤）对权重做了什么。
- 阅读真实模型的代码（像 `transformers` 或 `llama.cpp` 这样的库），并指出每个推导出来的部件在哪里。
- 评审别人对模型代码的改动，并具体指出它破坏了什么或要付出什么代价（一个到两层之后才会暴露的形状 bug，一个没有对应输出的所谓加速，一个经不起重读论文实际方程的架构声明），而不是轻信拉取请求的描述。

## 约束

- 假定你能自如地使用 Python 和基本的 PyTorch 张量运算，并且把矩阵乘法作为唯一默认你已掌握的数学；不需要事先有深度学习的背景。
- 用 PyTorch 实现，使用原始的张量运算，而不是 `nn.Transformer` 或其他现成的注意力模块；保留 autograd 和 GPU 支持，只有架构本身是手工搭建的。

## 范围之外

- 基本循环之外的优化器和调度器变体，以及分布式训练：见 [`llm/pretraining`](../../llm/pretraining/)，从这个循环必须在许多 GPU 上运行时接着讲。
- 建立在这个块之上的低秩/适配器机制：这条边界见 [`llm/finetuning`](../../llm/finetuning/)。这个工作区推导的是那个工作区只是顺带提到的东西（它第 0003 课里的分词器，它第 0008 课里的低秩思路），而不是重述它们。

## 学习路线

共十二个阶段，从一个方程，到能够阅读真实模型的代码、并在任何规模上从中生成。一个阶段包含若干课程，边界并不严格；一个阶段是否完成，取决于能力，而不是课程数量。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. 注意力 | 0001 至 0003 | 缩放点积注意力、多头注意力、因果掩码 | 从原始张量实现了多头注意力，与参考实现一致 |
| 2. Transformer 块 | 0004 至 0006 | 位置编码、层归一化与残差连接、前馈块 | 从原始张量实现了一个完整的 Transformer 块 |
| 3. 完整的模型 | 0007 至 0008 | 堆叠块、嵌入层与输出层、权重绑定 | 一次完整的前向传播与参考实现的输出一致 |
| 4. 训练循环 | 0009 至 0011 | 词表上的交叉熵损失、反向传播、AdamW 优化器步骤 | 模型从零开始训练，损失如预期那样下降 |
| 5. 阅读真实的模型代码 | 0012 至 0013 | 把每个推导出来的部件对应到真实的库（`transformers` 或 `llama.cpp`），顺带提到的分词器和低秩适配器 | 能指出每个推导出来的部件在真实模型代码里的位置 |
| 6. 现代的位置编码与归一化 | 0014 至 0015 | 旋转位置嵌入、RMSNorm | 能推导 RoPE 的相对位置性质，并解释 RMSNorm 相对于层归一化去掉了什么 |
| 7. 现代的前馈与注意力变体 | 0016 至 0017 | SwiGLU/门控前馈、分组查询注意力与多查询注意力、KV 缓存 | 能推导一个门控前馈块，并解释为什么更少的 KV 头是用质量换缓存大小 |
| 8. 生成与采样 | 0018 | 贪心解码、温度、top-k 与 top-p 采样、向前运行模型来产生文本 | 能用手工搭建的模型生成文本，并解释为什么贪心解码会退化 |
| 9. 训练循环的实践细节 | 0019 至 0020 | Xavier 初始化、学习率预热与衰减、梯度裁剪、混合精度、梯度累积 | 能解释每一项细节防范的是什么，并把它们加进一个可以工作的训练循环 |
| 10. 编码器-解码器与仅编码器架构 | 0021 | BERT 的双向编码器、T5 带交叉注意力的编码器-解码器、给这个工作区的仅解码器模型定位 | 能解释每种架构为什么使用或不使用因果掩码，以及交叉注意力处在什么位置 |
| 11. 混合专家与 FlashAttention | 0022 | 稀疏激活的 MoE 路由、FlashAttention 感知 IO 的分块 | 能解释 MoE 如何把参数量与每个 token 的计算解耦，以及为什么 FlashAttention 是精确的而不是近似的 |
| 12. 判断 | 0023 | 评审别人对模型代码的改动、检查形状和输出的精确性、从一手来源裁定有争议的声明 | 值得信任去评审对模型架构和训练循环的改动，并解释一项改动要付出什么代价或带来什么风险，而不是接受它的描述 |

## 课程

请按顺序学习。

| # | 课程 | 内容 |
|---|---|---|
| [0001](lessons/0001-scaled-dot-product-attention.md) | 缩放点积注意力 | 其余架构都围绕它搭建的那一个方程 |
| [0002](lessons/0002-multi-head-attention.md) | 多头注意力 | 为什么注意力要同时在几个较小的子空间里进行，而不是在完整维度上只做一次 |
| [0003](lessons/0003-causal-masking.md) | 因果掩码 | 为什么查询位置不能关注未来的位置，以及为什么掩码要在 softmax 之前而不是之后施加 |
| [0004](lessons/0004-positional-encoding.md) | 位置编码 | 为什么注意力本身对顺序视而不见，以及正弦编码如何给每个位置一个可区分的特征标记 |
| [0005](lessons/0005-layer-norm-and-residuals.md) | 层归一化与残差连接 | 为什么堆叠许多 Transformer 块需要一条干净的梯度通路和稳定的激活值范围，以及残差连接和层归一化各自如何提供其中一个 |
| [0006](lessons/0006-feed-forward-block.md) | 逐位置前馈块 | Transformer 块的第二个子层在注意力之外增加了什么，以及为什么它从不跨位置混合信息 |
| [0007](lessons/0007-stacking-blocks.md) | 堆叠 Transformer 块 | 为什么每个块都保持相同的形状，为什么深度不是权重共享，以及为什么第 5 课的残差机制在堆叠许多块之后最为关键 |
| [0008](lessons/0008-embedding-output-and-weight-tying.md) | 嵌入层与输出层，权重绑定 | token 如何进入和离开 Transformer 的向量空间，以及为什么承担这件事的两个层可以共用一个矩阵 |
| [0009](lessons/0009-cross-entropy-loss.md) | 词表上的交叉熵损失 | logits 如何变成一个可训练的数字，以及为什么损失是实际下一个 token 的负对数概率 |
| [0010](lessons/0010-backward-pass-and-autograd.md) | 反向传播与自动求导 | 链式法则在记录下来的计算图上自动执行，如何把一个标量损失变成每个权重的梯度 |
| [0011](lessons/0011-adamw-optimizer.md) | AdamW 优化器步骤 | Adam 的动量和自适应缩放比朴素梯度下降多出了什么，以及为什么 AdamW 把权重衰减与梯度更新解耦 |
| [0012](lessons/0012-reading-real-model-code.md) | 阅读真实的模型代码 | 每个推导出来的部件在生产环境模型库里的位置，以及与原始论文相比那些值得认出来、而不是被搞糊涂的细小而常见的偏离 |
| [0013](lessons/0013-tokenizers-and-low-rank-adapters.md) | 分词器与低秩适配器 | 推导字节对编码，以及低秩适配器究竟附着在这个工作区从零搭建的权重矩阵的哪个位置 |
| [0014](lessons/0014-rotary-position-embeddings.md) | 旋转位置嵌入 | 正弦编码在注意力运行之前，给嵌入加上一个固定向量；RoPE 则是旋转 Q 和 K 本身，正是这一处改变，使两个旋转后的向量之间的点积只取决于它们的相对距离 |
| [0015](lessons/0015-rmsnorm.md) | RMSNorm | LayerNorm 做了两件事，重新中心化和重新缩放，而 RMSNorm 之所以存在，是因为重新中心化这一半原来可有可无，留下的是一种更便宜的归一化，当前的模型把它用在第 5 课已经推导过的前归一化分支里 |
| [0016](lessons/0016-swiglu-and-the-gated-feed-forward.md) | SwiGLU 与门控前馈块 | 第 6 课的前馈块先扩张，再施加一个非线性，然后收缩；门控的变体则计算两个投影而不是一个，并把它们相乘，让网络学会让多少自己的计算结果通过 |
| [0017](lessons/0017-grouped-query-attention-and-kv-caching.md) | 分组查询注意力与 KV 缓存 | 自回归生成让注意力重新计算它早已拥有的键和值，而一旦缓存它们成为显而易见的修补办法，缓存本身的大小，就使得用少量质量去换取更少的键/值头变得值得 |
| [0018](lessons/0018-generation-and-sampling.md) | 生成与采样 | 这个工作区搭建并训练的模型，从来没有真正产生过一段文本，因为训练和生成问了它两个不同的问题，而总是取单个最可能的下一个 token，对第二个问题来说，原来不如恰当程度的随机性 |
| [0019](lessons/0019-initialization-warmup-and-gradient-clipping.md) | 初始化、预热与梯度裁剪 | 一个这么深的模型，如果初始权重的尺度不对，在训练开始之前就可能失败，而第 11 课推导的 AdamW 步骤，还需要两道护栏，缓慢的起步和梯度的硬性上限，才能真正撑过实际的训练 |
| [0020](lessons/0020-mixed-precision-and-gradient-accumulation.md) | 混合精度与梯度累积 | 这两种技术的存在，都是为了把一次更大的有效训练运行，塞进比这次运行看上去所需的更小的硬件里，一个靠缩小每个数字的占用，另一个靠模拟一个内存永远无法一次装下的更大批次 |
| [0021](lessons/0021-encoder-decoder-and-encoder-only-architectures.md) | 编码器-解码器与仅编码器架构 | 这个工作区搭建了带因果掩码的单一数据流，因为它只需要做一件事，生成下一个 token，而另外两种架构形态之所以存在，是因为 BERT 和最初的翻译模型需要的是结构上不同的保证 |
| [0022](lessons/0022-mixture-of-experts-and-flashattention.md) | 混合专家与 FlashAttention | MoE 在不增加任何单个 token 被处理所需代价的前提下，增加模型的总参数量，而 FlashAttention 通过重写它访问内存的方式、而不是它所计算的内容，更快地计算出第 1 课完全相同的方程 |
| [0023](lessons/0023-reviewing-a-change-to-model-code.md) | 评审对模型代码的改动 | 评审别人对模型代码的改动，指出它破坏了什么或要付出什么代价，而不是轻信它的描述 |

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
