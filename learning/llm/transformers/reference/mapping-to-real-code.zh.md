# 对应到真实代码

第 5 阶段，压缩成便于查阅的形式。[第 12 课](../lessons/0012-reading-real-model-code.md)讲把这个工作区的推导，转换成 Hugging Face `transformers` 和 llama.cpp 的命名，[第 13 课](../lessons/0013-tokenizers-and-low-rank-adapters.md)讲推导字节对编码，以及低秩适配器附着在权重矩阵的哪个位置。这张速查表把名称对应、标准偏离和这两个推导并排放在一起。

## Hugging Face `transformers` 里的命名

| 真实代码里的名字 | 推导于 | 它是什么 |
|---|---|---|
| `GPT2Attention`（或类似的） | 第 1 至 2 课 | 缩放点积注意力，通常通过一个融合的 QKV 线性层、事后再拆开，这是批量矩阵乘法的效率细节，而不是不同的运算 |
| 一个注册过的下三角掩码缓冲区 | 第 3 课 | 因果掩码，只预先算一次，因为掩码只取决于序列长度，而不取决于输入值，每次调用时复用或切片 |
| `wte`（word token embedding） | 第 8 课 | 输入嵌入表 |
| `wpe`（word position embedding） | 第 4 课 | 位置编码，这里通常是学习得到的表，而不是正弦公式 |
| 一个由块组成的 `ModuleList`，在 for 循环里遍历 | 第 7 课 | 堆叠的 Transformer 块 |
| `lm_head`，与 `wte` 的权重绑定在一起 | 第 8 课 | 输出投影，通过权重绑定 |
| 训练脚本或 `Trainer`，而不是模型类 | 第 9 至 11 课 | 交叉熵损失、`.backward()`、优化器步骤；模型类只定义到 logits 的前向传播 |

## 与原始论文的三处标准偏离

| 部件 | 原始论文 | 生产模型中的常见做法 | 背后仍是同一课 |
|---|---|---|---|
| 位置嵌入 | 正弦公式 | 学习得到的表，或旋转嵌入 | 第 4 课学习得到的替代方案，或进一步的变体 |
| 激活函数 | ReLU | GELU（或 SwiGLU） | 第 6 课先扩张再收缩的形态，换了一种非线性 |
| 归一化的放置 | 后归一化 | 前归一化 | 第 5 课的前归一化替代方案 |

这些都没有改变这个工作区所推导的架构；它们是在几乎每个真实实现中都能看到的标准变化，而不是另一种设计。

## 同样的数学，不同的代码库：llama.cpp

llama.cpp（C 语言，借助 `ggml` 张量库）通过函数调用构建一张显式的计算图，而不是带 `forward` 方法的 `nn.Module` 类。它计算的是同样的数学对象：注意力、位置编码（通常是旋转式）、归一化（通常是 RMSNorm，一种简化的层归一化变体），以及前馈块（通常是 SwiGLU）。区别完全在于计算图是如何构建和运行的，而不在于它计算什么。

## 推导分词器：字节对编码（BPE）

1. 把训练文本表示成一串原始字节或字符，每个都是词表里的独立一项。
2. 统计整个语料里每一个相邻的符号对。
3. 把出现最频繁的那一个对合并成一个新符号，加进词表。
4. 重复，直到词表达到选定的目标大小。

例题，语料 `"low low lower"`：`l, o` 这个对很频繁，合并成 `lo`；下一轮找到 `lo, w`，合并成 `low`。常见的词压缩成一个 token；罕见的词退回成更小、更常见的片段。

`vocab_size` 就是分词器的训练运行了多少个起始符号加合并步骤，训练一结束就固定下来；它正是决定第 8 课的输入嵌入表和输出层大小的东西。

## 低秩适配器附着在哪里

`llm/finetuning` 的适配器机制，`ΔW = BA`，其中 `A` 向下投影到秩 `r`，`B` 再向上投影回来，附着在这个工作区推导出的某个具体的权重矩阵上，例如第 2 课每个头的查询投影：

```text
Q_i = X (W_Q^i + (alpha / r) B_i A_i)
```

| 矩阵 | 是否冻结？ | 适配器训练期间是否接收梯度？ |
|---|---|---|
| `W_Q^i` | 是，与预训练的完全一样 | 否 |
| `A_i`、`B_i` | 否，新加的，大小由秩 `r` 决定 | 是 |

由于更新是加性的、线性的，就像原来的投影一样，训练之后 `W_Q^i + (alpha/r) B_i A_i` 合并成一个普通的矩阵。前向传播不需要任何改变就能为合并后的结果服务，因为它作为一个普通的投影矩阵，直接代入 `Q_i = X W_Q^i`，推理时没有任何额外的计算。

## 阅读真实模型的代码或向它附加东西之前

- [ ] 被拆开的融合 QKV 线性层，被认作效率细节，而不是与每个头各自投影不同的运算。
- [ ] 掩码缓冲区如果是预先算好的，要明白它只取决于序列长度，并没有改变掩码机制本身。
- [ ] 位置嵌入、激活函数和归一化放置的选择，在被当作另一种架构之前，先对照三处标准偏离检查。
- [ ] 低秩适配器的附着点，要指明是某个具体的权重矩阵（哪一层里的哪个投影），而不只是“模型”。
