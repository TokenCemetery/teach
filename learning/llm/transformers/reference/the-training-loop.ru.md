# Цикл обучения: потери, обратный проход и оптимизатор

Этап 4 в сжатом виде для быстрого поиска. [Урок 9](../lessons/0009-cross-entropy-loss.md) охватывает превращение логитов в одно скалярное значение потерь; [Урок 10](../lessons/0010-backward-pass-and-autograd.md) охватывает превращение этого скаляра в градиент для каждого веса; [Урок 11](../lessons/0011-adamw-optimizer.md) охватывает превращение градиентов в обновления весов. Этот лист это три формулы в том порядке, в котором их на самом деле использует обучение.

## Кросс-энтропийные потери

```text
loss = -log(p_correct)
```

| `p_correct` | Потери | Читается как |
|---|---|---|
| 0.8 | `-log(0.8) ≈ 0.223` | Уверенно и верно, малый штраф |
| 0.1 | `-log(0.1) ≈ 2.303` | Уверенно неверно, штраф более чем в 10 раз больше при падении вероятности в 10 раз |

`-log(p)` неограниченно растёт, когда `p` приближается к 0; более простой штраф `1 - p` насыщается на 1 и не отличает «слегка неправа» от «катастрофически уверенно неправа». У неё также чистый градиент по логитам (`softmax_output - one_hot_true_label`), и поэтому softmax и кросс-энтропию почти всегда используют вместе, часто как одну объединённую, численно устойчивую операцию над «сырыми» логитами.

**Teacher forcing.** При обучении в качестве контекста всегда подаются настоящие предыдущие токены, а не собственные предсказания модели. Поскольку каузальное маскирование уже ограничивает каждую позицию вниманием только назад, предсказание каждой позиции, а значит, и потери каждой позиции, вычисляются за один прямой проход, а не за один проход на позицию. Потери по позициям и по батчу усредняются в один скаляр, поскольку градиентному спуску нужна одна величина для минимизации.

## Обратный проход и автоград

Каждая операция прямого прохода (умножение матриц, softmax, сложение для остаточной связи) записывается в **граф вычислений**. `loss.backward()` проходит по нему в обратном порядке, автоматически применяя правило цепочки с помощью уже реализованного локального правила обратного прохода каждой операции и заполняя `.grad` каждого обучаемого параметра.

Разобранный пример правила цепочки: `y = 3x + 1`, `z = y^2`, при `x = 2`: `y = 7`, `dz/dy = 2y = 14`, `dy/dx = 3`, поэтому `dz/dx = 14 x 3 = 42`.

| Подход | Как получает градиент | Стоимость |
|---|---|---|
| Символьное дифференцирование | Выводит замкнутую формулу вручную или с помощью компьютерной алгебры | Автоград этого не делает |
| Численное дифференцирование | Возмущает каждый параметр, заново запускает прямой проход | Неточно, один дополнительный прямой проход на параметр |
| Автоматическое дифференцирование (автоград) | Выстраивает в цепочку уже реализованное локальное правило обратного прохода каждой операции по записанному графу | Точно, один обратный обход сразу для всех параметров |

**Почему остаточные связи на самом деле предотвращают затухающие градиенты.** Для `y = x + Sublayer(x)` имеем `d(loss)/d(x) = d(loss)/d(y) x 1 + [слагаемое через Sublayer]`. Локальная производная тождественного пути в точности равна 1, поэтому прямое слагаемое проходит без масштабирования, как бы мала ни становилась производная самого `Sublayer`. Это механическая причина, а не просто интуиция.

**Градиенты накапливаются, а не перезаписываются.** `.grad` прибавляется к тому, что там уже было, поэтому цикл обучения должен явно обнулять градиенты перед каждым новым вызовом `backward()`, иначе градиент шага загрязняется остатками предыдущего шага.

## Шаг оптимизатора AdamW

```text
plain gradient descent:  w = w - lr * grad
Adam's moments:           m = beta1 * m + (1 - beta1) * grad          (momentum)
                          v = beta2 * v + (1 - beta2) * grad^2        (adaptive scale)
Adam's update:            w = w - lr * m_hat / (sqrt(v_hat) + eps)
AdamW's update:           w = w - lr * (m_hat / (sqrt(v_hat) + eps) + weight_decay * w)
```

(`m_hat`, `v_hat` это `m`, `v` с поправкой смещения, учитывающей, что оба начинаются с нуля.)

| Часть | Добавляет | Исправляет |
|---|---|---|
| Импульс (`m`) | Скользящее среднее прошлых градиентов | Шумные градиенты по батчам; обновление следует устойчивому направлению, а не дрожит |
| Адаптивный масштаб (`v`) | Оценку типичной величины градиента для каждого параметра | Одну фиксированную скорость обучения для каждого веса; параметры с малыми градиентами получают относительно большие шаги, с большими градиентами меньшие |
| Отделённое затухание весов (AdamW) | Затухание весов, применяемое прямо к `w` и никогда не проходящее через `m`, `v` или адаптивный знаменатель | Включение затухания в градиент (исходный Adam) делает его эффективное сжатие зависящим от типичной величины градиента каждого параметра, вместо равномерного сжатия, которым затухание должно быть |

Разобранный пример: `w = 5.0`, `grad = 2.0`, `lr = 0.1`, обычный градиентный спуск: `w = 5.0 - 0.1 x 2.0 = 4.8`.

## Прежде чем доверять реализации цикла обучения

- [ ] Кросс-энтропия принимает «сырые» логиты напрямую (объединённая операция softmax и отрицательного логарифма вероятности), а не ручной softmax с отдельным шагом логарифма.
- [ ] Обучение подаёт эталонные предыдущие токены (teacher forcing), и потери вычисляются для каждой позиции за один прямой проход, а не за один проход на позицию.
- [ ] Градиенты явно обнуляются перед каждым вызовом `backward()`.
- [ ] Оптимизатор это AdamW, а не обычный Adam, если используется затухание весов, и затухание весов применяется прямо к весам, а не включается в градиент.
