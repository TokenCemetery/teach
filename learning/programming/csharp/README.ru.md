# Обучение: C\#

Станьте инженером, которому команда доверяет сервис на C#: умеющим моделировать предметную область, правильно выбирая между struct, class и record, писать `async`/`await` и рассуждать о нём, свободно запрашивать и преобразовывать данные с помощью LINQ, выпускать типизированный и покрытый тестами бэкенд на ASP.NET Core и объяснять, что CLR делает с написанным вами кодом.

**Последний урок:** [45. Упаковка и версионирование в NuGet](lessons/0045-nuget-packaging-and-versioning.md)

## Каким выглядит результат

- Вы моделируете предметную область, правильно выбирая между struct, class и record, и защищаете выбор, опираясь на реальное поведение CLR.
- Вы пишете код с `async`/`await` и объясняете, что происходит с выполнением метода на каждом `await`.
- Вы свободно запрашиваете и преобразуете данные с помощью LINQ.
- Вы выпускаете типизированный и покрытый тестами бэкенд-сервис на ASP.NET Core, спроектированный идиоматично для C#.
- Получив код на C#, написанный по привычке, которая лишь компилируется (class там, где место struct, колбэк вместо `async`/`await`), вы называете привычку и переписываете код идиоматично.

## Ограничения

- Знание C# не предполагается. Опыт в другом объектно-ориентированном языке (Java, Kotlin) сокращает ранние этапы, но не обязателен, и он приносит привычки, которые C# тихо наказывает: class там, где место struct или record, колбэк там, где `async`/`await` читается лучше.
- Контекст ASP.NET Core и бэкенд-сервисов; не .NET в целом без этого фокуса.

## За рамками курса

- Unity и разработка игр на C#: контекст достаточно другой, чтобы здесь его не рассматривать.
- Внутреннее устройство JIT, а также написание или ручная настройка сборщика мусора: этап 8 охватывает поколенческую кучу, режимы GC и профилирование на уровне, который нужен владельцу сервиса, чтобы измерить и защитить выбор, а не на уровне реализации.
- Образы контейнеров: упаковка опубликованного сервиса в образ, а также запуск, защита и отладка этого контейнера относятся к [`infrastructure/containers`](../../infrastructure/containers/).
- Запуск сервиса в кластере, включая то, что Kubernetes делает с его проверками liveness и readiness, относится к [`infrastructure/kubernetes`](../../infrastructure/kubernetes/).

| [0043](lessons/0043-api-compatibility.md) | Совместимость API | Изменение, которое чисто перекомпилируется, всё равно может сломать каждого вызывающего, который не перекомпилируется, изменение, которое не компилируется, может быть совершенно нормальным для вызывающих, у которых уже есть рабочий бинарник, а изменение, которое не делает ни того ни другого, всё равно может тихо делать что-то иное, и именно о таком семантическое версионирование вообще существует, чтобы предупреждать вызывающего |
