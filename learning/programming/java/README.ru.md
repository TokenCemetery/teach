# Обучение: Java

Станьте инженером, которому команда доверяет сервис на Java: умеющим моделировать предметную область на современной Java, а не на иерархиях наследования, которых язык требовал раньше, рассуждать о конкурентности исходя из модели памяти, а не из эксперимента, доводить чтение профиля и лога сборки мусора до решения и проводить ревью чужого кода на Java, конкретно называя, во что обходится абстракция.

**Начните здесь:** [0001. Ссылки это значения](lessons/0001-references-are-values.md)
**Последний урок:** [0052. Рефлексия и аннотации](lessons/0052-reflection-and-annotations.md)

## Каким выглядит результат

- Вы предсказываете, что сделают сравнение ссылок, сломанный `hashCode` и общее изменяемое поле, до запуска кода.
- Вы моделируете предметную область с помощью record, sealed-интерфейсов и enum и говорите, почему иерархия наследования была бы хуже.
- Вы формулируете, что гарантирует каждый из `synchronized`, `volatile` и конкурентной коллекции, в терминах модели памяти Java.
- Вы используете виртуальные потоки там, где они окупаются, и называете, что всё ещё блокирует поток-носитель.
- Вы читаете лог сборки мусора и профиль и затем подбираете размер кучи по этим данным, а не по значению по умолчанию.
- Вы выпускаете сборку, которую может запустить кто-то другой: объявленные зависимости, набор тестов, запускаемый артефакт.
- Вы проводите ревью pull request и точно говорите, почему иерархия классов, проверяемое исключение или цепочка стримов там неподходящий инструмент.
- Вы разрешаете спор о языке по спецификации и JEP, которым была введена возможность.

## Ограничения

- Знание Java не предполагается. Опыт в другом языке сокращает ранние этапы, но не обязателен, и он приносит привычки, которые Java тихо наказывает: геттер для каждого поля, интерфейс с одной реализацией, класс там, где record выразил бы это лучше.
- Базовая версия это текущий релиз с долгосрочной поддержкой. Каждая возможность языка вводится вместе с релизом, в котором она появилась, потому что код на Java читают на многих версиях, а «современная Java» стареет.
- Нужны только JDK и терминал на любой поддерживаемой ОС. IDE помогает, но никогда не обязательна, и ничто в курсе не требует платных инструментов или облачного аккаунта.
- Большинство упражнений это маленькие программы, которые укладываются в один подход. Исключение составляет этап 6: для профиля нужна программа, работающая достаточно долго, чтобы её профилировать.
- Утверждения, зависящие от версии, проверяются по спецификации, документации API и индексу JEP, а не по книге, потому что полугодовой цикл релизов обгоняет любую книгу из списка.

## За рамками курса

- Фреймворки как самостоятельные темы: Spring, Jakarta EE, Quarkus, Hibernate. Оценка того, оправдывает ли фреймворк своё место, это навык ревью и относится к этапу 7.
- Другие языки JVM: Kotlin, Scala, Clojure, Groovy.
- Android и мобильные платформы в целом.
- Сравнение инструментов сборки. Курс учит задачам, которые должна выполнять сборка, и выполняет их одним инструментом, а не спорит о том, каким.
- Внутреннее устройство JVM за той точкой, где оно перестаёт предсказывать поведение программы: реализация JIT, инженерия байткода, написание сборщика мусора.
- Kubernetes и инфраструктура сверх того, что нужно одному сервису для работы. Упаковка запускаемого артефакта в образ контейнера, а также запуск, защита и отладка этого контейнера относятся к [`infrastructure/containers`](../../infrastructure/containers/). Запуск в кластере относится к [`infrastructure/kubernetes`](../../infrastructure/kubernetes/).

## Структура курса

Восемь этапов: от нуля до уровня senior. Это не список уроков: этап занимает несколько уроков, границы нечёткие.

| Этап | Уроки | Что охватывает | Готово, когда |
|---|---|---|---|
| 1. Основы | с 0001 по 0006 | Примитивы и ссылки, `null`, строки и их пул, массивы, фреймворк коллекций, `equals` и `hashCode`, `Comparable` | Можете предсказать идентичность против равенства и алиасинг, не запуская код |
| 2. Моделирование | с 0007 по 0014 | Классы и интерфейсы, record, sealed-типы, enum, обобщения и стирание, сопоставление с образцом, неизменяемость по умолчанию | Моделируете предметную область, не хватаясь первым делом за наследование |
| 3. Идиоматика и библиотека | с 0015 по 0021 | Исключения и что делать с проверяемыми, `Optional`, стримы и коллекторы, итерация, файлы и ввод-вывод, API времени, текстовые блоки | Пишете на Java так, что ревьюер не назовёт это неидиоматичным |
| 4. Конкурентность | с 0022 по 0028 | Потоки, модель памяти, `synchronized` и `volatile`, `java.util.concurrent`, исполнители, виртуальные потоки, структурированная конкурентность, ловушки | Можете назвать гарантию, которую нарушила сломанная конкурентная программа |
| 5. Тестирование и сборка | с 0029 по 0035 | JUnit 6, параметризованные тесты, тестовые двойники и когда их не использовать, объявление зависимостей, воспроизводимый запускаемый артефакт | Кто-то другой может клонировать, собрать, протестировать и запустить проект |
| 6. Среда выполнения | с 0036 по 0042 | Области памяти, раскладка объекта и escape-анализ, сборщики мусора и их компромиссы, чтение лога GC, JMH, профилирование, сокращение выделений памяти | Оптимизируете по профилю и доказываете выигрыш бенчмарком, которому можно доверять |
| 7. Суждение | с 0043 по 0049 | Проектирование API и обратная совместимость, объявление устаревшим, ревью, чтение спецификации и JEP в поисках ответов | Вам доверяют принять решение и объяснить его другому; этап 8 дополняет это механизмом, рефлексией и аннотациями, из которого на самом деле построен каждый оцениваемый фреймворк |
| 8. Модули и рефлексия | с 0050 по 0052 | Система модулей, `module-info.java`, `requires` и `exports`, сильная инкапсуляция, образы среды выполнения `jlink` и `jpackage`, рефлексия и аннотации | Осознанно объявляете границу модуля, выпускаете построенный по ней образ среды выполнения и читаете, чего на самом деле касается рефлексия фреймворка, прежде чем судить, оправдывает ли он своё место |

Каждый урок короткий и самодостаточный. Ключи ответов свёрнуты: сначала вспомните, потом открывайте. Практика на реальных задачах важнее чтения, и в том, чтобы разносить её во времени, весь смысл. Всё, что осталось неясным в конце урока, стоит довести до первоисточника, прежде чем идти дальше.
