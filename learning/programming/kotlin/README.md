# Learning: Kotlin

Become the engineer trusted to own Kotlin on a team, in a backend service or an Android app, able to ship idiomatic Kotlin instead of Kotlin that merely compiles because it was written with Java habits.

**Latest lesson:** _none yet_

## Success looks like

- Ship a typed, tested Kotlin backend service or Android component, designed idiomatically rather than as translated Java.
- Given Kotlin written with a Java habit (defensive null checks instead of the type system, a callback instead of a coroutine), name the habit and rewrite it idiomatically.
- Compare Kotlin coroutines against Java 21 virtual threads and explain what each buys you and what it costs.

## Constraints

- Assumes professional Java background, per `programming/java`'s own `NOTES.md`; teaches the contrast rather than duplicating what the JVM does underneath.
- Covers both backend/server-side and Android contexts, touching each where they diverge.

## Out of scope

- What the JVM does underneath (bytecode, the memory model, the garbage collector): that is `programming/java`, linked to rather than retaught.
