# 学习：Python

成为团队中值得信任、能掌控 Python 的工程师：能交付一个有类型、有测试、已打包的 Python 服务或工具，能把一个 traceback 或一份性能剖析结果追溯到根本原因而不是靠猜，并能具体说出为什么别人对 Python 动态特性的巧妙运用会让他们吃苦头。

**从这里开始：** [0001. 名字是绑定，不是盒子](lessons/0001-names-are-bindings.md)
**最新课程：** [0044. 判断力](lessons/0044-judgment.md)

## 成功的标准

- 在运行代码之前，预测可变默认参数、对循环变量的闭包以及共享的列表会做出什么。
- 交付一个能在编写它的机器之外的机器上安装并运行的包。
- 添加能被类型检查器验证的类型提示，并修复它报告的问题，而不是让它闭嘴。
- 编写失败时能给出有用信息的 `pytest` 测试，使用 fixture 和参数化，而不是复制粘贴测试体。
- 用性能剖析器找出慢的部分，并用一次度量证明修复有效。
- 根据工作负载的形态，在线程、进程和 `asyncio` 之间做出选择，并说出 GIL 能阻止什么、不能阻止什么。
- 在数据模型需要时实现双下划线方法或上下文管理器，并能看出什么时候一个普通函数才是更好的答案。
- 评审别人的 Python 代码，准确说出为什么在那里类、元类或继承链是错误的工具。

## 约束

- 不要求有 Python 基础。另一门语言的经验能缩短前面的阶段，但并非必需，而且它会带来 Python 悄悄惩罚的习惯：一个函数就够的地方用了类，推导式读起来更好的地方用了循环，做了语言本来就已经做过的防御性复制。
- 只需要 CPython 和任意受支持操作系统上的终端。路线中没有任何内容需要付费工具、云账号或第二台机器。
- 整条路线都以 CPython 作为参考实现。其他实现只在行为确实不同的地方出现。
- 练习都是一次就能完成的小程序。把它们分散到多天进行，正是学习机制本身，而不是一种不便。
- 类型和打包的变化比语言本身更快。对版本敏感的说法会依据当前文档和相关的 PEP 来核对，任何依赖特定版本的课程都会注明是哪个版本。

## 范围之外

- 把 Web 框架本身作为学习对象：Django、FastAPI、Flask。
- 把科学计算和机器学习技术栈作为学习对象：NumPy、pandas、PyTorch。这条边界见 [`llm/finetuning`](../../llm/finetuning/)。
- 发布到包索引的 wheel 之外的分发方式：conda、操作系统软件包、冻结的单文件二进制。
- 超出预测程序行为所需深度的 CPython 内部机制：字节码、C API、编写扩展模块。
- Python 2，以及从它迁移。
- 容器镜像：把 wheel 及其解释器放进镜像，以及运行、加固和调试这个容器，见 [`infrastructure/containers`](../../infrastructure/containers/)。

## 学习路线

共七个阶段，从零基础到资深。这不是课程清单：一个阶段包含若干课程，边界并不严格。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. 基础 | 0001 至 0007 | 对象与名字、可变性与别名、列表、字典、集合、元组、真值、推导式、函数与参数传递 | 不运行代码就能预测别名和修改的效果 |
| 2. 惯用法 | 0008 至 0014 | 迭代器与生成器、上下文管理器、作为控制流的异常、`dataclasses`、模块与包、值得了解的标准库 | 会选用生成器或上下文管理器，而不是手写循环和 `try/finally` |
| 3. 类型与工具 | 0015 至 0021 | 注解、泛型、`Protocol`、检查器的严格程度、代码检查与格式化、虚拟环境、依赖与项目管理、构建 wheel | 严格的检查器能通过，别人也能安装这个成果 |
| 4. 数据模型 | 0022 至 0027 | 双下划线方法、`__init__` 与 `__new__`、property、描述符、类属性与实例属性、方法解析顺序、为什么元类几乎从来不是答案 | 能实现一个类型所需的协议，并能说出什么时候不该这样做 |
| 5. 测试 | 0028 至 0033 | `pytest` 的机制、fixture 与作用域、参数化、基于属性的测试、什么值得 mock、什么不值得、把覆盖率当作信号而不是目标 | 拥有一套在人发现之前就抓住了回归的测试 |
| 6. 并发与性能 | 0034 至 0039 | 线程、进程、`asyncio`、GIL 实际串行化了什么、事件循环中的阻塞调用、性能剖析、属性查找与分配的开销 | 根据工作负载选择并发模型，并依据剖析结果证明收益 |
| 7. 判断力 | 0040 至 0044 | API 与包的设计、弃用、代码评审、从标准库和 PEP 中寻找答案 | 可以信赖他做出判断，并向别人解释清楚 |

## 使用方式

整条路线已经完成：七个阶段全部写好，从第 0001 课到第 0044 课。请按顺序学习，或者从你还无法证明自己达到其“完成的标志”的那个阶段开始。

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
