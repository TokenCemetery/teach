# 学习：SQL

成为团队放心把数据库交给你的工程师：能把一个问题表达为恰好回答它的查询，读懂执行计划来找出查询为什么慢，凭证据而不是直觉选择索引，推理并发事务可能观察到什么，并设计和迁移一个能把坏数据挡在外面、在表不断增长时依然很快的 schema。

**从这里开始：** [0001. 表、行与类型](lessons/0001-tables-rows-and-types.md)
**最新课程：** [0053. 触发器、存储过程，以及逻辑应该放在哪里](lessons/0053-triggers-stored-procedures-and-where-logic-belongs.md)

## 成功的标准

- 用连接、聚合和窗口函数写出回答所提问题的查询，并解释为什么结果恰好是这些行，包括 `NULL` 在内。
- 读懂带有真实耗时的执行计划，并指出问题出在哪一步。
- 根据执行计划和选择性选择一个索引，或者否决它，然后用测量证明其中的差异。
- 说出处于给定隔离级别的事务可能观察到什么，并指出一个并发 bug 所依赖的异常。
- 用键、类型和约束设计 schema，让坏数据不可能出现，而不只是不被鼓励。
- 在线上系统中修改 schema，既不停机，也不让迁移背后排起锁队列。
- 拿到一条由 ORM 生成的慢查询，解释它为什么慢，并重写它。
- 评审别人的查询或 schema，具体说出当行数变为十倍时它会付出什么代价。

## 约束

- 不要求事先了解 SQL，也不要求有数据库管理经验。
- 以 PostgreSQL 作为参考引擎，因为它的文档是关于真实的查询规划器和真实的并发模型如何运作的、可免费获取的最完整描述。在练习完全不该需要服务器的地方使用 SQLite。凡是引擎之间确实存在差异的地方，课程都会说明，并在有标准行为时指出它。
- 只需要本地引擎和任一受支持操作系统上的终端。学习路线中没有任何内容需要付费工具、云账号或托管数据库。
- 练习需要数据，而只有十行的表会在索引上教给你错误的结论。学习路线使用同一个数据集，它会增长到足够大，让规划器的选择变得真实。
- 规划器的行为在主版本之间会发生变化。与版本相关的说法会对照当前文档核实，任何依赖某个版本的课程都会说明是哪一个。

## 范围之外

- 作为主题的数据库管理：备份与恢复、复制、故障转移、连接池、版本升级。见 [`data/postgres`](../../data/postgres/)，它负责运行中的实例。
- 作为独立主题的 ORM 和查询构建器。它们的输出会在第 7 阶段被阅读和批评；如何配置它们则不讲。
- 从部署流水线运行迁移：迁移相对于需要它的代码何时运行，以及扩展与收缩模式如何把一次改动分摊到多次部署中。这属于 [`infrastructure/ci-cd`](../../infrastructure/ci-cd/)，它的 [部署](../../infrastructure/ci-cd/reference/deployments.md) 速查表记录了迁移的顺序。
- 分析型数据仓库及其方言：BigQuery、Snowflake、Redshift、Spark SQL。列式执行会改变性能建议，而本学习路线不去追逐它。见 [`data/warehouses`](../../data/warehouses/)，它负责列式执行及其带来的变化。
- 作为对比对象的非关系型存储。其中有自己专门课程系列的是 [`data/redis`](../../data/redis/)。
- 超出能解释查询和事务行为这一程度的引擎内部机制：磁盘格式、预写日志的内部机制、规划器的源代码。

## 学习路线

共七个阶段，从零基础到资深。这不是课程清单：一个阶段包含若干课程，边界并不严格。

| 阶段 | 课程 | 内容 | 完成的标志 |
|---|---|---|---|
| 1. 关系模型 | 0001 至 0006 | 表、行与类型、`NULL` 与三值逻辑、`SELECT`、过滤、排序、集合与多重集的对比、键是什么 | 能说出一条查询为什么恰好返回了这些行，包括被 `NULL` 去掉的那些 |
| 2. 查询 | 0007 至 0013 | 各种连接、聚合与 `GROUP BY`、`HAVING`、子查询、公用表表达式、集合运算 | 不靠反复试错，就能把一个问题表达为一条查询 |
| 3. 进阶 | 0014 至 0020 | 窗口函数与窗口帧、lateral 连接、递归查询、在确有价值之处使用 `JSON` 列 | 在 SQL 中而不是在应用代码中解决排名和累计求和问题 |
| 4. schema 设计 | 0021 至 0027 | 规范化以及何时停止、主键与外键、约束、有意识地选择类型、代理键与自然键的对比 | 坏数据不可能出现，而不只是不被鼓励 |
| 5. 事务 | 0028 至 0034 | 作为四项独立承诺的 ACID、隔离级别及其各自允许的异常、多版本并发控制、加锁、死锁、显式行锁、幂等性 | 在复现之前，就能指出一个并发 bug 所依赖的异常 |
| 6. 性能 | 0035 至 0041 | 先讲 B 树索引再讲其他索引、选择性与基数、统计信息、读懂带耗时的执行计划、连接策略、分页、问题不在查询本身的情形 | 依据执行计划进行优化，并用测量证明收益 |
| 7. 运维与判断力 | 0042 至 0048 | 不停机的迁移、评审查询和 schema、阅读 ORM 的输出、跨引擎的可移植性、SQL 何时是错误的工具 | 可以信赖他做出判断，并向别人解释清楚；第 8 阶段补全了本阶段检查清单本身所预设的授权与过程式逻辑的评审问题 |
| 8. 安全与专用工具 | 0049 至 0053 | SQL 注入与参数化语句、角色与最小权限、行级安全、全文搜索、触发器与存储过程 | 像评审一条查询或一次 schema 变更那样，具体地评审授权边界和一段过程式逻辑 |

## 课程

请按顺序学习。

| # | 课程 | 内容 |
|---|---|---|
| [0001](lessons/0001-tables-rows-and-types.md) | 表、行与类型 | 列类型是你免费得到的一项约束，而选错了很难挽回 |
| [0002](lessons/0002-select-and-evaluation-order.md) | SELECT 与求值顺序 | 各子句的执行顺序与书写顺序不同，这解释了大多数初学者的错误 |
| [0003](lessons/0003-null-and-three-valued-logic.md) | NULL 与三值逻辑 | WHERE 只保留为真的行，所以未知表现得和假一样，而 NOT IN 可能什么也不返回 |
| [0004](lessons/0004-sets-and-bags.md) | 集合与多重集 | 表是多重集，所以重复是真实存在的，而 UNION 会悄悄付出代价去掉它们 |
| [0005](lessons/0005-sorting-and-collation.md) | 排序与排序规则 | 文本的顺序取决于排序规则，而没有唯一键来打破的平局排序是不稳定的 |
| [0006](lessons/0006-keys-and-constraints.md) | 键与约束 | 键是数据库强制执行的一项声明，而你漏掉的每一项声明都会变成一个 bug |
| [0007](lessons/0007-joins-and-what-they-do.md) | 连接，以及连接实际做了什么 | 连接是经过过滤的笛卡尔积，所以 ON 条件在其他一切运行之前就决定了哪些行存在 |
| [0008](lessons/0008-outer-joins-and-missing-rows.md) | 外连接与不存在的行 | 外连接会保留没有匹配到任何东西的行，而一个 WHERE 子句会悄悄地把它们再次丢掉 |
| [0009](lessons/0009-aggregation-and-group-by.md) | 聚合与 GROUP BY | 聚合函数会忽略 NULL，而一个让行数成倍增加的连接也会让总数成倍增加 |
| [0010](lessons/0010-having-and-filter.md) | HAVING、FILTER 与一次完成多种分组 | 条件放在哪里，决定了它还能看到哪些行，而一次扫描就能回答多种分组 |
| [0011](lessons/0011-subqueries.md) | 子查询，以及哪一种能回答问题 | 标量子查询、IN、EXISTS 和派生表回答的是四个不同的问题，其中一种在出现 NULL 时会给出错误的答案 |
| [0012](lessons/0012-common-table-expressions.md) | 公用表表达式 | WITH 为一个步骤命名，让长查询可以自上而下阅读，而在当前版本中它不是优化屏障 |
| [0013](lessons/0013-set-operations.md) | 集合运算，以及用一条查询回答一个问题 | UNION、INTERSECT 和 EXCEPT 按位置合并结果集，并且除非明确要求，否则会去掉重复 |
| [0014](lessons/0014-window-functions.md) | 窗口函数 | 窗口函数跨其他行进行计算，而不会把当前所在的行折叠掉 |
| [0015](lessons/0015-window-frames.md) | 窗口帧 | 默认的窗口帧包含与当前行并列的每一行，这就是累计求和会突然跳变的原因 |
| [0016](lessons/0016-navigating-within-a-window.md) | 在窗口内导航 | lag、lead 和取值函数直接访问其他行，其中两个函数遵循窗口帧 |
| [0017](lessons/0017-lateral-joins.md) | lateral 连接 | LATERAL 让 FROM 中的子查询能看到它旁边的行，这正是取每组前几条的方法 |
| [0018](lessons/0018-recursive-queries.md) | 递归查询 | 递归 CTE 把自己的输出反馈回去，直到不再产生新的结果，这就是遍历层级结构的方式 |
| [0019](lessons/0019-json-columns.md) | JSON 列 | 只要知道哪个运算符返回文本、哪个返回 JSON，查询文档列就只是普通的 SQL |
| [0020](lessons/0020-choosing-the-tool.md) | 选择工具 | Top-N、累计求和和去重各有两三种正确的写法，而选择取决于问题问的是什么 |
| [0021](lessons/0021-normalisation.md) | 规范化 | 每一种范式都消除了两行对同一事实说法不一致的一种可能 |
| [0022](lessons/0022-choosing-a-key.md) | 选择键 | 代理键换来了稳定性，放弃了含义，而你选择的生成方式决定了它还要付出什么代价 |
| [0023](lessons/0023-foreign-keys.md) | 外键，以及删除时会发生什么 | 外键是对存在的行的一项承诺，而你选择的动作决定了某行消失时由谁来买单 |
| [0024](lessons/0024-constraints-that-hold.md) | 真正守得住的约束 | CHECK 只在条件为假时失败，所以缺失的值几乎能满足你写下的每一条规则 |
| [0025](lessons/0025-choosing-types.md) | 有意识地选择类型 | 类型决定了数据库会接受什么、会悄悄改变什么，以及永远无法收回什么 |
| [0026](lessons/0026-denormalising-on-purpose.md) | 有意地反规范化 | 一个事实的第二份副本就是第二次出错的机会，除非由数据库来维护它 |
| [0027](lessons/0027-making-bad-data-impossible.md) | 让坏数据不可能出现 | 拿一个允许错误行存在的 schema，堵上每一个漏洞，然后说出这个设计仍然无法承诺什么 |
| [0028](lessons/0028-what-a-transaction-promises.md) | 事务承诺了什么 | 四项承诺共用一个缩写，而其中只有一项是由你来权衡的 |
| [0029](lessons/0029-mvcc.md) | 多版本并发控制 | 更新会写入一个新的行版本而不是修改原有的，这就是读者永远不必等待写者的原因 |
| [0030](lessons/0030-isolation-levels.md) | 隔离级别 | PostgreSQL 以四个名称提供三种不同的级别，每一种允许的意外各不相同 |
| [0031](lessons/0031-the-anomalies.md) | 各种异常，以及如何认出你遇到的那一种 | 每一个并发 bug 都有名字，叫出它的名字，就能知道哪个级别或哪种锁本可以防止它 |
| [0032](lessons/0032-locks.md) | 有意获取的锁 | 行锁是让一个决定保持不变的方式，而每一种行锁都有一个值得你去选择的失败模式 |
| [0033](lessons/0033-deadlocks.md) | 死锁 | 两个事务各自持有对方需要的东西，唯一的解药是事先约定一个顺序 |
| [0034](lessons/0034-idempotency-and-retry.md) | 幂等性与正确的重试 | 重放相同语句的重试会复现它本想修复的 bug，所以它必须重新读取、重新决定 |
| [0035](lessons/0035-reading-a-plan.md) | 读懂执行计划 | 执行计划告诉你数据库做了什么、预期了什么，而二者之间的差距正是要下功夫的地方 |
| [0036](lessons/0036-what-an-index-does.md) | 索引实际做了什么 | B 树把对每一行的扫描变成沿着几个页面向下的查找，而执行计划会说出它用了四种读取方式中的哪一种 |
| [0037](lessons/0037-selectivity-and-statistics.md) | 选择性与统计信息 | 每个执行计划都建立在你的数据的一份样本之上，所以糟糕的计划通常源于糟糕的估算，而不是糟糕的规划器 |
| [0038](lessons/0038-choosing-an-index.md) | 选择索引 | 列的顺序决定了索引能回答哪些查询，而最好的索引往往是你决定不建的那一个 |
| [0039](lessons/0039-join-strategies.md) | 连接策略 | 有三种连接方式，规划器按估算成本挑选，所以错误的估算会表现为错误的策略 |
| [0040](lessons/0040-pagination-and-counting.md) | 分页与计数 | OFFSET 会读取并丢弃它跳过的每一行，而精确计数要付出扫描整张表的代价 |
| [0041](lessons/0041-when-the-query-is-not-the-problem.md) | 问题不在查询本身的时候 | 证明收益需要一个可以重复的测量，而原因往往在于表、流量或客户端 |
| [0042](lessons/0042-migrations-without-downtime.md) | 不停机的迁移 | 一次只需一毫秒的迁移，仍然可能因为排在它后面的东西而让这张表上的所有读取停下来 |
| [0043](lessons/0043-changing-what-has-data.md) | 修改已有数据的部分 | 给一张满是数据的表加约束需要两条语句，而回填是一个循环，而不是一条 UPDATE |
| [0044](lessons/0044-reviewing-a-query.md) | 评审查询 | 先看查询返回了哪些行，再看它的速度，因为快速给出的错误答案更糟 |
| [0045](lessons/0045-reviewing-a-schema-change.md) | 评审 schema 变更 | 问清这次迁移会锁住什么、会重写什么，以及在两个版本的代码同时在线时会运行什么 |
| [0046](lessons/0046-portability.md) | 可移植性及其代价 | 本学习路线的大部分内容在引擎之间通用，而不通用的部分，正是值得你有意识地依赖的部分 |
| [0047](lessons/0047-reading-orm-output.md) | 读懂 ORM 生成的内容 | ORM 写出了你没有写的 SQL，而知道它发送了什么的唯一方法就是去看 |
| [0048](lessons/0048-trusted-with-the-database.md) | 值得托付数据库的人 | 七个阶段最终归结为一个习惯：指出让某个决定站得住脚的那一行、那把锁或那个执行计划 |
| [0049](lessons/0049-sql-injection-and-parameterised-statements.md) | SQL 注入与参数化语句 | 字符串拼接让一个值能改变语句的含义，而不只是它匹配的内容，而参数化语句消除了这种可能，而不是试图对每一种情况进行清理 |
| [0050](lessons/0050-roles-and-least-privilege.md) | 角色与最小权限 | 角色包含了过去的用户和组的概念，所有权本身就授予了全部权限而无需 GRANT，而最小权限完全关乎其他所有人被允许做什么 |
| [0051](lessons/0051-row-level-security.md) | 行级安全 | GRANT 决定对整张表的访问，行安全策略逐行决定访问，而引擎会在每一条访问路径上强制执行它，而不只是开发者记得去过滤的那一条 |
| [0052](lessons/0052-full-text-search.md) | 全文搜索 | tsvector 把文档归约为 GIN 索引可以搜索的规范化词位，tsquery 询问它们是否存在，而与专用搜索引擎的分界线，就在排序和规模超出单个列能力的地方 |
| [0053](lessons/0053-triggers-stored-procedures-and-where-logic-belongs.md) | 触发器、存储过程，以及逻辑应该放在哪里 | 这是第 8 阶段的收尾课：触发器在到达一张表的每一条路径上运行，存储过程可以提交或回滚它自己的事务，而需要判断的是，这种不可见性什么时候真正值得它的代价 |

## 使用方式

每节课都简短且自成一体。答案默认折叠：先自己回忆，再展开查看。真实场景中的练习比阅读更重要，而把练习间隔开来正是关键。课程结束时仍不清楚的地方，值得先追溯到一手资料再继续往下学。
